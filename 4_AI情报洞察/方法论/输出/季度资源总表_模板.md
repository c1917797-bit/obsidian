## 三、资源仲裁规则

当总需求 > 预算时，按以下规则仲裁：

### 3.1 优先级排序

```
排序规则: 综合得分（降序）→ 优先级（P0>P1>P2）→ ROI（降序）

示例排序:
  P0-1 FP8 (8.3) > P0-1 KV量化 (7.6) > P0-2 W×K (7.0) > P0-2 Agent KV (7.2)
  → 但 Agent KV 得分 7.2 > W×K 7.0，所以:
  P0-1 FP8 (8.3) > P0-1 KV量化 (7.6) > P0-2 Agent KV (7.2) > P0-2 W×K (7.0)
  > P0-3 MoE INT4 (6.0)
```

### 3.2 裁剪规则

```
从排序末尾开始裁剪:
  1. P0-3 MoE INT4 (6.0, 6 GPU×月) → 延期到 Q4
  2. 如果还不够 → P0-2 W×K (7.0, 10 GPU×月) → 缩减规模或延期
  
裁剪后:
  P0-1 FP8 (8) + P0-1 KV量化 (15) + P0-2 Agent KV (8) = 31 GPU×月 ≤ 40 ✅
```

### 3.3 资源共享

检查课题之间是否可以共享资源：

| 共享类型 | 示例 | 节省 |
|---------|------|------|
| 共享 GPU | P0-1 FP8 和 P0-2 W×K 可在同一集群分时使用 | -20% GPU |
| 共享人力 | 同一个工程师可同时做 P0-1 和 P0-3（都是量化） | -30% 人力 |
| 共享数据 | KVCache 报告和参数压缩报告共用 calibration data | -50% 数据成本 |

## 四、季度更新流程

```
每季度首月 W1（课题规划负责人，1 小时）:
  1. 收集所有在研/计划中课题的资源需求
  2. 填入季度资源总表
  3. 对比预算
  4. 如有缺口 → 执行仲裁规则
  5. 发布"季度资源分配决议"
  6. 各课题负责人确认
```
