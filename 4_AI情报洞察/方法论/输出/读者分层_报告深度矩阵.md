> 版本: v1.0 | 更新: 2026-06-28

## 一、读者画像与阅读目标

不同读者读同一份报告，关注点差异巨大。本文档给出**6 类读者**的差异化阅读路径。

### 1.1 6 类读者画像

| 读者 | 角色 | 阅读时间 | 阅读目标 | 决策权 |
|------|------|---------|---------|--------|
| **C1 高管** | CTO / VP / 部门负责人 | 15 分钟 | 决策: 是否投资、投入多少 | ⭐⭐⭐⭐⭐ |
| **C2 业务负责人** | 产品总监 / 业务线负责人 | 30 分钟 | 决策: 业务优先级、ROI | ⭐⭐⭐⭐ |
| **C3 课题负责人** | 算法专家 / 技术经理 | 60 分钟 | 决策: 怎么做、谁来做 | ⭐⭐⭐⭐⭐ |
| **C4 工程师** | 算法/工程实施者 | 30 分钟 | 了解: 实现路径、接口 | ⭐⭐ |
| **C5 跨团队协作者** | 上下游团队负责人 | 20 分钟 | 了解: 依赖、接口、时间 | ⭐⭐ |
| **C6 外部读者** | 投资人 / 合作伙伴 | 20 分钟 | 评估: 市场、护城河 | ⭐ |

## 三、6 类读者的阅读路径

### 3.1 C1 高管（15 分钟）

**必读章节**:
1. **0. 一页纸摘要**（5 分钟）→ 核心结论
2. **1.5 反方证据汇总**（3 分钟）→ 风险总览
3. **2.4 风险评估**（3 分钟）→ 备选方案
4. **2.5 决策建议**（2 分钟）→ 拍板

**跳过**: 1.2, 1.4, 3.2, 3.5, 4

**输出产物**:
- 决策: 立项 / 暂缓 / 砍掉
- 资源承诺: GPU×月 + 人头

**配套材料**: 一页纸 PDF（可单独打印）

---

### 3.2 C2 业务负责人（30 分钟）

**必读章节**:
1. **0. 一页纸摘要**（3 分钟）
2. **1.1 五看分析**（5 分钟）→ 市场+客户
3. **1.3 5场景适用性**（3 分钟）→ 跨场景价值
4. **2.1 量化目标**（3 分钟）→ 业务指标
5. **2.3 时间窗**（3 分钟）→ 投入节奏
6. **3.4 资源与时间线**（5 分钟）→ 人头+预算
7. **3.1 课题清单**（3 分钟）→ 哪些课题

**选读**: 1.4（看摘要即可）

**跳过**: 1.2, 3.2, 3.5, 4

**输出产物**:
- 业务优先级确认
- 资源承诺
- 与产品/业务的衔接

---

### 3.3 C3 课题负责人（60 分钟）

**必读章节**（全文）:
1. **0 + 1.1-1.5 + 2.1-2.5 + 3.1-3.6**（55 分钟）
2. **4.1 原始数据**（5 分钟）→ 验证数据

**输出产物**:
- 课题执行计划
- 假设清单
- 验证方案
- 失效保险设计
- 风险评估

**配套动作**:
- 与主笔人对齐细节
- 拆分任务到周/日
- 安排组内评审

---

### 3.4 C4 工程师（30 分钟）

**必读章节**:
1. **0. 一页纸摘要**（3 分钟）
2. **1.2 技术全景图**（5 分钟）→ 在 42 格的位置
3. **1.4 论文核心洞察**（10 分钟）→ Top 5 论文+复现代码
4. **2.1 量化目标**（3 分钟）→ 要达到的指标
5. **3.1 课题清单**（3 分钟）→ 自己负责的课题
6. **3.2 假设与验证**（5 分钟）→ 验证任务

**选读**: 3.3 失效保险

**跳过**: 1.1, 1.3, 1.5, 2.2, 2.3, 2.5, 3.4, 3.5, 3.6, 4

**输出产物**:
- 理解: 自己负责的课题定位
- 任务清单: Week 1-2 任务
- 论文阅读清单: Top 5 必读

**配套材料**: 论文清单 + 代码仓库链接

---

### 3.5 C5 跨团队协作者（20 分钟）

**必读章节**:
1. **0. 一页纸摘要**（3 分钟）
2. **1.3 5场景适用性**（3 分钟）→ 与自己工作的关系
3. **3.1 课题清单**（5 分钟）→ 哪些需要协同
4. **3.4 资源与时间线**（5 分钟）→ 时间节点
5. **3.6 风险与缓解**（3 分钟）→ 可能的影响

**跳过**: 大部分其他章节

**输出产物**:
- 依赖关系确认
- 时间线对齐
- 接口约定

---

### 3.6 C6 外部读者（20 分钟）

**必读章节**:
1. **0. 一页纸摘要**（5 分钟）→ 商业机会

3. **2.1 量化目标**（3 分钟）→ 性能数字

**输出产物**:
- 市场判断

**配套材料**: 摘要 + 五看分析 PDF

## 四、衍生文档建议

基于一份完整报告，针对不同读者生成**衍生版本**：

### 4.1 衍生策略

| 衍生版本 | 字数 | 章节 | 输出格式 |
|---------|------|------|---------|
| **一页纸 PDF** | 500-1000 | 0 + 2.5 | 飞书 / 邮件 |
| **高管简报** | 3000-5000 | 0, 1.1, 1.5, 2.4, 2.5, 3.4 | PDF / PPT |
| **业务方版本** | 5000-8000 | 0, 1.1, 1.3, 2.1, 2.3, 3.1, 3.4 | PDF |
| **工程实施卡片** | 1000-3000 | 0, 1.2, 1.4, 3.1, 3.2 | Wiki / 飞书 |
| **外部 pitch 版** | 3000-5000 | 0, 1.1, 2.1, 2.5 | PPT / 视频 |

### 4.2 自动生成建议

写报告时**先写完整版**（30-60 页），然后**自动生成衍生版本**：

```python
# 伪代码
def generate_derivatives(report):
    full = report.get_full_text()
    return {
        'one_pager': extract_section(full, '0'),
        'exec_summary': extract_sections(full, ['0', '1.1', '1.5', '2.4', '2.5']),
        'business': extract_sections(full, ['0', '1.1', '1.3', '2.1', '3.4']),
        'engineering': extract_sections(full, ['0', '1.2', '1.4', '3.2']),
        'pitch': extract_sections(full, ['0', '1.1', '2.5']),
    }
```

## 六、报告评审机制

### 6.1 评审流程

```
作者写草稿（v0.1）
  → 自评（v0.5）
  → 课题负责人评审（v0.8）
  → 跨团队评审（v0.9）
  → 高管评审（v1.0）
  → 发布
```

### 6.2 评审检查清单

每章评审要点：

| 章节 | 评审要点 |
|------|---------|
| 0. 一页纸 | TL;DR 是否 3 句话、决策可执行 |
| 1. 洞察 | 五看是否全面、矩阵是否完整 |
| 2. 总结 | 指标可量化、反方证据全 |
| 3. 规划 | 假设可验证、保险可执行 |
| 4. 附录 | 数据可追溯 |

### 6.3 评审角色矩阵

| 角色 | 评审重点 |
|------|---------|
| C1 高管 | 战略对齐、资源合理性 |
| C3 课题 | 技术可行性、假设严谨性 |
| C4 工程师 | 实现路径、依赖关系 |
| 跨团队 | 接口、时间、依赖 |

## 七、常见误区

### 误区 1：一刀切
❌ 给所有读者同一份完整报告
✅ 按读者分层输出不同深度

### 误区 2：过度细节
❌ 给高管讲实现细节
✅ 高管看决策+风险，工程师看实现

### 误区 3：忽略外部
❌ 只关注内部读者
✅ 投资人和合作伙伴也要有版本

### 误区 4：一次性
❌ 报告发完就归档
✅ 配套衍生版本+定期更新

### 误区 5：单方面
❌ 单向写报告
✅ 双向：写完评审，评审改写
