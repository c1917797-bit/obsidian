# AI 通话防诈助手场景化创新材料

> 决策建议：**Conditional Go（有条件验证）**  
> 项目定位：**运营商 AI 通信安全协同平台**，不是运营商自建全栈通话监听产品。

## 1. 场景挑战

### 1.1 业务背景

我国已经建立号码标记、异常话务监测、涉诈短信预警、96110 劝阻和金融止付等多层反诈体系。2025 年，全国公安机关侦破电信网络诈骗案件 25.8 万起，会同相关部门拦截诈骗电话 36 亿次、诈骗短信 33 亿条，累计见面劝阻 674.7 万人次。治理规模已经达到十亿级，但仍有大量潜在受害者需要人工介入，说明“电话接通后、危险操作发生前”仍是重要干预窗口。[来源：2025 年全国反诈工作数据](https://www.jswx.gov.cn/anquan/zixun/202601/t20260108_1184254.shtml)

与此同时，市场并非空白：

- 华为已提供设备本地通话内容检测、风险弹窗、亲情防诈和远程挂断等能力。[来源：华为通话智能安全防护](https://consumer.huawei.com/cn/support/content/zh-cn16070231/)
- vivo 已使用离线大模型识别陌生通话中的诈骗信息和高风险行为。[来源：vivo AI 识别诈骗电话](https://www.vivo.com.cn/service/questions/all?categoryId=192&questionId=1934)
- Apple 已提供陌生来电筛选和运营商垃圾或诈骗号码处理，但目前官方证据不足以证明其在中国大陆提供等价的接通后诈骗语义识别。[来源：Apple iOS 26 通话筛选](https://www.apple.com.cn/newsroom/2025/06/apple-elevates-the-iphone-experience-with-ios-26/)
- 中国电信“星小辰”已具备通话防诈、AI 代接、摘要代办和智能字幕，构成本项目最重要的内部能力基线。[来源：中国电信星小辰](https://www.chinatelecom.com.cn/ct/news/jtxw/153035.html)
- 华为 5G 新通话已经具备 IMS 数据通道、多模态交互和通话智能体平台能力，但仍需要网络、终端和产业伙伴协同。[来源：华为新通话解决方案](https://carrier.huawei.com/cn/products/core-network/newcalling)

因此，本项目面对的不是“是否能做通话摘要或诈骗提醒”，而是：

> 在终端厂商已有能力的情况下，运营商增加网侧风险信号、统一风险策略、跨品牌家庭触达和权威处置连接，能否显著提高成功干预率。

### 1.2 核心问题

#### 1.2.1 终端能力覆盖缺口是否真实存在

不能用手机品牌销量或市场份额推导反诈功能覆盖率。实际覆盖率至少由以下因素共同决定：

```text
实际覆盖率
= 品牌存量保有量
× 支持机型比例
× 系统升级率
× 功能开启率
× 可识别诈骗场景比例
× 有效干预率
```

截至目前，没有权威资料证明：

- 90% 的存量终端支持实时通话语义反诈；
- 90% 的用户已经开启相关功能；
- 90% 的用户同时获得“语义识别—本人提醒—摘要—紧急联系人联动”完整服务；
- 90% 的真实诈骗风险已被有效阻断。

所以“终端已经解决 90% 市场”不能作为事实，但必须作为项目立项前重点验证的假设。

#### 1.2.2 运营商是否提供不可替代的增量

运营商的优势不在端侧采音、通用 ASR 或手机通话界面，而在：

- 真实主叫、国际来话、异常路由和异常话务信号；
- 号码信誉、历史投诉及涉诈关联信息；
- 跨品牌短信、闪信、5G 消息、App Push 和 AI 外呼；
- 用户订购、分项授权、计费、客服和申诉；
- 与 12381、96110、公安和金融机构的既有协同关系。

这些能力是否真正提高高风险操作中止率，必须通过“终端单独方案”与“端网融合方案”的对照实验验证。

#### 1.2.3 合规和经济性是否支持规模化

《反电信网络诈骗法》要求运营商承担号卡、真实主叫、异常通信活动监测和风险提示责任，但不能由此推导出运营商可以默认分析所有用户的通话内容。

如果无法明确：

- 通话内容处理的合法基础；
- 对通话相关方的告知方式；
- 摘要保存范围和期限；
- 向紧急联系人提供信息的授权；
- 自动化风险判断的解释、纠错和申诉机制；

则网络侧语音分析应直接 No-Go。

即使技术有效，也需要证明模型、触达、存储、客服、复核和合规成本能够被商业收入或可核验的公共治理价值覆盖。

## 2. 创新 Idea 方案介绍

### 2.1 解决方案

#### 2.1.1 方案定位

建设“运营商 AI 通信安全协同平台”，依托 5G 新通话等原生通信能力，连接终端侧反诈 AI、运营商网络风险信号、跨品牌家庭联防和权威处置渠道。

方案不是让运营商监听全部通话，而是采用：

> 端侧保护并理解通话内容，网侧增强风险判断，运营商统一风险编排和可靠触达。

#### 2.1.2 与现有方案的区别

| 现有方案 | 已解决问题 | 主要缺口 | 本方案增量 |
|---|---|---|---|
| 号码黑名单 | 已知诈骗号码 | 新号码、正常号码伪装 | 加入实时语义和危险动作 |
| 终端反诈 | 本机语义提醒 | 品牌、机型和系统碎片化 | 跨品牌策略与联系人触达 |
| 手机亲情守护 | 同生态家庭提醒 | 跨品牌能力不足 | 手机号码级家庭联防 |
| 通话摘要 | 通话内容整理 | 不一定形成风险处置 | 生成风险摘要和行动建议 |
| 96110/见面劝阻 | 权威人工干预 | 介入成本高、可能较晚 | 提前发现并连接权威渠道 |

#### 2.1.3 业务流程

**第一步：用户主动开通**

- 用户选择开启通话风险识别。
- 分别授权端侧分析、摘要生成和风险特征上传。
- 设置一名或多名紧急联系人。
- 明确联系人触发等级和可共享的信息范围。
- 联系人确认愿意接收提醒。

**第二步：端侧实时理解**

- 对陌生或高风险通话进行端侧瞬时音频处理。
- 流式 ASR 生成实时文本。
- 识别诈骗类型、关键实体、危险动作和用户执行状态。
- 原始音频默认不上传、不持久化。

**第三步：运营商网侧增强**

- 获取真实主叫、国际或网间属性、异常呼叫频次和号码信誉。
- 与终端输出的风险分、诈骗类型和危险动作进行融合。
- 仅接收最小化、脱敏的风险特征，不默认接收完整录音和逐字稿。

**第四步：分级干预**

| 等级 | 系统动作 |
|---|---|
| 低风险 | 静默处理，用户需要时生成摘要 |
| 中风险 | 提醒本人核验对方身份 |
| 高风险 | 强提醒停止转账、验证码或屏幕共享 |
| 极高风险 | 在满足授权和组合条件时通知紧急联系人 |

**第五步：家庭联防与权威连接**

- 通过短信、闪信、5G 消息、App Push 或 AI 外呼通知联系人。
- 联系人可一键回拨用户。
- 提供官方号码核验、96110 等权威渠道入口。
- 运营商只负责风险提示和渠道连接，不作诈骗司法认定，不独立执行金融止付。

#### 2.1.4 紧急联系人触发规则

不能采用“命中一个敏感词就自动通知家人”。建议满足以下组合条件：

```text
综合风险超过高阈值
AND 涉及转账、验证码、远程控制等危险动作
AND 用户进入同意或执行状态
AND 模型置信度达到要求
AND 用户和联系人均已完成有效授权
```

默认只向联系人发送：

- 风险等级；
- 疑似诈骗类型；
- 关键风险动作；
- 建议立即回拨；
- 官方核验入口。

默认不发送：

- 原始录音；
- 完整逐字稿；
- 银行账号；
- 验证码；
- 与风险无关的私人内容。

### 2.2 关键技术

关键技术采用六层金字塔结构。六层全部解决后，才能形成完整闭环。

#### 2.2.1 第一层：通信承载和新通话入口

- IMS/SVC 融合话音核心网；
- VoLTE、VoNR 音视频承载；
- IMS Data Channel；
- 新通话业务使能平台；
- 终端能力协商；
- 用户鉴权、订购和计费。

IMS Data Channel 适合把风险卡片、核验入口、用户反馈和操作按钮带入原生通话界面，但它本身不等于媒体采集通道，也不当然赋予运营商分析通话内容的权利。

#### 2.2.2 第二层：端侧通话感知和理解

- VAD 语音活动检测；
- 降噪、回声消除和音量归一化；
- 流式 ASR；
- 说话人区分；
- 诈骗意图多标签分类；
- 人物、机构、金额、App、账户等实体抽取；
- 转账、验证码、屏幕共享、远程控制等危险动作识别；
- 用户“犹豫—同意—执行”状态识别。

端侧处理可降低隐私风险、网络延迟和云端算力成本。

#### 2.2.3 第三层：端网多信号风险融合

融合以下信号：

```text
终端侧：
诈骗类型 + 语义置信度 + 危险动作 + 用户执行状态

运营商侧：
真实主叫 + 国际来话 + 异常路由 + 异常话务 + 号码信誉
```

决策不依赖单个大模型，而应采用：

- 高风险规则；
- 轻量分类模型；
- 多信号校准模型；
- 诈骗阶段状态机；
- 低置信度人工复核。

#### 2.2.4 第四层：风险分级和策略编排

- 风险等级阈值；
- 本人提醒与联系人提醒采用不同阈值；
- 频率控制和告警合并；
- 相同事件冷却；
- 联系人失败递补；
- 高敏合法通话保护；
- 人工复核和申诉。

#### 2.2.5 第五层：跨品牌触达和处置连接

- 短信；
- 闪信；
- 5G 消息；
- 运营商 App Push；
- AI 语音外呼；
- 客服人工外呼；
- 96110 和公安劝阻接口；
- 银行、支付机构风险处置接口。

运营商最明确的差异化价值就在这一层：不要求被保护人与联系人使用同一品牌终端。

#### 2.2.6 第六层：安全、合规和模型治理

- 分项授权；
- 原始音频端侧优先；
- 数据最小化和脱敏；
- 传输与存储加密；
- KMS 密钥管理；
- RBAC/ABAC 权限控制；
- 数据 TTL 和自动删除；
- 模型版本、灰度和回滚；
- 风险解释和证据回溯；
- 用户纠错、删除和申诉；
- 个人信息保护影响评估。

### 2.4 运营商能独立完成与需要协同的边界

| 能力 | 运营商主导程度 | 说明 |
|---|---|---|
| 号码信誉和异常话务 | 高 | 运营商核心优势 |
| 用户开通、授权和联系人管理 | 高 | 需要严格分项授权 |
| 风险规则和策略编排 | 高 | 运营商统一运营 |
| 跨品牌通知和失败递补 | 高 | 短信、闪信、外呼等 |
| 端侧语音识别 | 低 | 依赖 OEM、系统权限和 AI 模型 |
| 原生风险弹窗与一键挂断 | 低 | 依赖新通话及终端适配 |
| IMS/Data Channel | 中 | 运营商建设，设备商提供平台 |
| 诈骗权威认定 | 低 | 由公安机关负责 |
| 金融止付 | 低 | 由公安、银行和支付机构依法处理 |
| 跨运营商一致体验 | 低 | 需要标准、互联和运营商协同 |

| 触达 | 短信、闪信、5G 消息、Push、AI 外呼 |

| 评测 | PR 曲线、PPV、误报率、P95 时延、成功干预率 |

### 2.6 终端覆盖策略

| 终端层级 | 可提供能力 |
|---|---|
| L1：完整新通话终端 | 端侧语义识别、风险卡片、摘要、一键核验、联系人联动 |
| L2：VoLTE/VoNR但无完整数据通道 | 网侧风险提示、短信/闪信、语音提醒、联系人通知 |
| L3：老旧终端 | 号码提示、通话后风险通知、联系人外呼 |

不能把某款华为终端已经适配新通话，表述成全部用户已经覆盖。

### 2.7 分阶段落地

**阶段 0：前置审查**

- 完成法律意见和个人信息保护影响评估；
- 盘点目标用户的终端、系统版本、功能支持和开启率；
- 确认 OEM 音频与端侧模型接入路径；
- 明确现有号码提醒服务作为对照基线。

**阶段 1：离线和红队评测**

- 经核验诈骗样本；
- 银行、公安、医院、快递等合法难负样本；
- 方言、噪声、AI 变声、隐语和分阶段诱导；
- 输出 PR 曲线、PPV、高敏合法场景误报率和 P95 时延。

**阶段 2：影子模式**

- 只对明确授权用户评分；
- 不向用户或联系人发送新增提醒；
- 高风险样本双盲人工复核；
- 按有效阳性事件数而不是单纯用户数决定样本量。

**阶段 3：分层对照**

- A 组：现有号码风险提醒；
- B 组：号码风险 + 端侧语义提醒；
- C 组：号码风险 + 端侧语义 + 授权联系人联动。

主指标是经核验的高风险操作中止率和 C 相对 B 的增量干预率。

**阶段 4：规模化决策**

- 若端网融合具有显著增量，且合规、成本、投诉通过门槛，逐省扩大；
- 若终端覆盖较高但运营商触达仍有价值，转为风险 API 和触达平台；
- 若无显著增量，停止面向消费者重复建设。

## 3. 创新 Idea 商业价值

### 3.1 战略价值

#### 3.1.1 从通信连接升级为可信通信安全

运营商不再只提供号码和通话连接，而是提供：

- 网络风险可信度；
- 跨终端安全策略；
- 家庭通信安全服务；
- 权威反诈渠道连接。

#### 3.1.2 建立运营商的跨品牌安全入口

终端能力受品牌、机型和系统限制。运营商可以通过号码、网络和多通道触达，成为终端之间的安全连接层。

#### 3.1.3 形成可复用的通信安全平台

平台未来可以扩展至：

- AI 换脸或变声风险；
- 虚假客服和金融诱导；
- 企业高风险通话保护；
- 未成年人和适老通信安全；
- 智能客服身份核验。

### 3.2 商业价值

#### 3.2.1 市场价值不能直接用号码数计算

```text
TAM
= 去重自然人用户
× 合规可开通率
× 终端和网络兼容率

SAM
= TAM
× 目标高风险客群
× 用户授权率
× 产品可用率

SOM
= SAM
× 触达率
× 开通率
× 90日留存率
× 付费率
```

不得用全国移动电话账户数直接乘套餐价格，也不应在缺少真实转化数据时给出“亿元市场规模”。

#### 3.2.2 商业模式优先级

**第一优先：B2B2C 权益采购**

- 银行、保险、养老机构或企业为目标用户购买安全权益；
- 获客成本相对较低；
- 付费方的风险损失规避价值更明确；
- 不能把反诈数据用于交叉营销。

**第二优先：家庭套餐增值权益**

- 基础风险提醒免费；
- 多联系人、跨品牌联动、家庭看板和人工协助作为增值权益；
- 不建议初期单独销售高价个人月包。

**第三优先：平台/API 模式**

当终端反诈覆盖较高时，运营商向 OEM 提供：

- 号码和网侧风险 API；
- 统一授权与风险编排；
- 跨品牌通知；
- 权威核验接口。

#### 3.2.3 单位经济性

```text
单活跃用户月贡献毛利
= 月ARPPU或单人权益收入
- 模型推理成本
- 短信/外呼成本
- 安全审计和存储成本
- 客服和人工复核成本
- OEM及渠道分成
```

```text
每次有效干预成本
= 试点总增量成本
÷ 经核验成功中止的高风险事件数
```

商业价值不能只看开通量和提醒次数，应以有效干预、留存、贡献毛利和严格归因的避免损失衡量。

### 3.3 社会价值

- 将反诈从事后处置前移至危险动作发生前；
- 为不具备最新端侧 AI 能力的存量用户提供兜底；
- 为老年人和高风险家庭提供跨品牌守护；
- 降低公安见面劝阻和人工触达压力；
- 形成用户主动授权、端侧优先、最小化处理的可信 AI 应用范式。

### 3.4 Go / No-Go 决策

#### Go

只有以下条件同时满足时进入规模化建设：

- 通话处理和第三方通知合法基础明确；
- 目标高风险人群存在实质终端覆盖缺口；
- B 组显著优于 A 组；
- C 组相对 B 组具有显著联系人联动增量；
- 高敏合法通话误报处于可接受范围；
- 贡献毛利为正，或公共治理收益达到内部标准；
- 重大隐私和数据安全事件为零。

#### 转平台模式

若终端完整能力覆盖较高，但运营商网侧信号和触达仍有增量：

> 停止自建端侧语义能力，转为风险 API、统一授权、跨品牌触达和权威协同平台。

#### No-Go

- 无法取得明确通话内容处理合法基础；
- 主要依赖普通运营商 App 获取蜂窝通话音频；
- 目标用户完整终端能力覆盖超过 90%；
- 端网融合相对终端单独方案没有显著增量；
- 单位经济性长期为负，且没有可核验公共治理收益；
- 误报频繁影响银行、公安、医院等正常通话；
- 需要默认监听、长期保存录音或未经授权通知家人。

**《别转账，让家人来得及介入》**

- 端侧识别诈骗语义；
- 运营商网侧信号增强；
- IMS Data Channel 展示风险卡片；
- 高风险时跨品牌通知用户女儿；
- 通话结束后生成脱敏风险摘要。

### 4.3 Demo 需要明确的边界

- 风险判断显示“疑似诈骗”，不作司法认定；
- 紧急联系人为用户预先设置并完成授权；
- 通知中不显示完整录音、账号和验证码；
- Demo 展示完整新通话终端，不暗示所有存量终端均已支持；
- 无风险提示不能被解释为通话绝对安全。

## 5. 最终结论

该项目不是“运营商再做一个 AI 电话助手”，而是验证运营商能否以网侧风险、统一授权和跨品牌触达补齐终端反诈闭环。

建议：

> 只批准端侧优先、用户自愿、最小化处理的有限试点；在覆盖缺口、增量效果、合规基础和单位经济性得到验证前，不批准全量建设。

如果试点证明终端完整能力已覆盖绝大多数目标用户，或运营商增强不能显著提高有效干预率，应停止消费者侧重复建设，转为号码信誉、风险 API、跨品牌触达和权威协同平台。

## 6. 多 Agent 执行说明

本材料采用以下分工完成：

- **市场与竞品 Agent**：核验诈骗治理数据、终端反诈能力、星小辰及新通话市场现状；
- **技术与运营商架构 Agent**：设计端网协同架构、技术金字塔、技术栈和能力边界；
- **商业与反方 Agent**：检验运营商必要性、商业模式、单位经济性和 No-Go 条件；
- **主 Agent**：读取模板、交叉核验结论、解决冲突、统一口径并形成最终稿。

AI 参与资料检索、分析和编写；正式立项前仍需由法务、网络安全、终端合作、反诈业务和财务部门人工复核。
