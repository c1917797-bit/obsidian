## ★★★ NSA — 原生可训练稀疏注意力：DeepSeek的硬件对齐方案

**论文**：Native Sparse Attention: Hardware-Aligned and Natively Trainable Sparse Attention
**ID**：arXiv:2502.11089 | Jingyang Yuan, Huazuo Gao, Damai Dai 等
**机构**：DeepSeek
**发表**：2025年2月（预印本）

### 问题：稀疏注意力的两大困境

**困境①：推理-only vs 训练-from-scratch**

| 方法类型 | 代表 | 问题 |
|---------|------|------|
| 推理-only稀疏 | H2O/SnapKV | 无法从头训练 → 模型质量上限受限 |
| 训练-from-scratch | Linear Attention | 质量下降 → 复杂推理任务表现差 |

**困境②：算法效率 vs 硬件效率**

```
大多数稀疏注意力算法 → 不规则内存访问模式
→ GPU Tensor Core 利用率极低
→ 理论FLOPs减少但实际wall-clock时间没降
```

### NSA 方案：三分支层次化稀疏

```
                    ┌─────────────────────────┐
                    │    NSA Attention Output   │
                    └────────┬────────────────┘
                             │ 加权融合
              ┌──────────────┼──────────────────┐
              ▼              ▼                  ▼
     ┌────────────┐  ┌──────────────┐  ┌──────────────┐
     │ 粗粒度压缩  │  │ 细粒度选择    │  │ 滑动窗口     │
     │ (Compress) │  │ (Selection)  │  │ (Window)     │
     │            │  │              │  │              │
     │ 块级均值池化│  │ Top-N块选择  │  │ 最近W个token │
     │ 全局上下文  │  │ 局部精度     │  │ 近距离信息   │
     └────────────┘  └──────────────┘  └──────────────┘
```

**关键设计决策**：

1. **算术强度均衡**：所有分支使用**块级GEMM**（而非散乱访问），确保Tensor Core满载
2. **端到端可训练**：三个分支的融合权重在预训练中学习，非推理时后接
3. **门控机制**：可学习的gate决定每个位置使用哪个分支

### 关键数据

| 指标 | 结果 |
|------|------|
| 通用基准 | **匹配或超越** Full Attention |
| 64K序列 | Decode/Forward/Backward **全面加速** |
| 训练成本 | 预训练计算量**减少**，质量不降 |

### 与经典方法对比

| 维度 | H2O/SnapKV | Linear Attention | **NSA** |
|------|-----------|-----------------|---------|
| 可训练 | ❌ 推理only | ✅ | **✅ 端到端** |
| 硬件对齐 | ❌ 散乱访问 | ✅ | **✅ 块级GEMM** |
| 推理质量 | 接近Full | 下降 | **≥ Full** |
| 生产部署 | 可集成 | 受限 | **DeepSeek生产级** |

### 局限与产业意义

**局限**：
- 需要从头预训练（非drop-in替换现有权重）
- 仅报告到64K（超长上下文未验证）
- 未报告绝对延迟/吞吐数字

**产业意义**：
- DeepSeek出品，验证了**稀疏注意力可原生训练**且不损失质量
- 确立了"**硬件对齐 + 端到端训练**"的设计范式
- 可能影响下一代基础模型架构设计

## ★★★ RocketKV — 两阶段压缩：400×极端压缩比

**论文**：RocketKV: Accelerating Long-Context LLM Inference via Two-Stage KV Cache Compression
**ID**：arXiv:2502.14051 | Payman Behnam, Yaosheng Fu, Ritchie Zhao 等
**机构**：NVIDIA + Georgia Tech
**发表**：ICML 2025

### 问题：单阶段压缩的精度-效率矛盾

```
H2O/SnapKV等单阶段驱逐：
  → 要么压缩不够（内存仍然大）
  → 要么压缩太狠（精度崩溃）
  → 无法同时达到极端压缩比 + 可忽略精度损失
```

### RocketKV 方案：粗筛 + 精选两阶段

```
Stage 1 — 粗粒度永久驱逐（Prefill后执行一次）
  输入: 全部N个token的KV
  操作: 基于注意力分数 → 永久丢弃大部分token
  输出: 保留M个token（M << N）
  特点: 不可逆，一次性，大幅减少后续计算量

Stage 2 — 细粒度混合稀疏注意力（每步Decode执行）
  输入: Stage 1保留的M个token
  操作: 头维度降维 + 序列维度降维 → 近似Top-k
  输出: 实际参与attention的k个token
  特点: 近似而非全量Top-k → 每步开销极小
```

**关键创新**：
- Stage 2不用全量attention score选Top-k（太贵），而是用**降维后的近似**
- 专门设计了**多轮对话变体**，解决query漂移问题

### 关键数据

| 指标 | 结果 |
|------|------|
| **压缩比** | **最高400×** |
| 端到端加速 | **3.7×**（A100）|
| 峰值内存降低 | **32.6%** |
| 精度损失 | 可忽略（多长上下文任务）|
| 多轮对话 | 接近Oracle Top-k性能 |

### 压缩比对比

| 方法 | 最大压缩比 | 精度 | 训练需求 |
|------|-----------|------|---------|
| H2O | ~5× (20%保留) | 小幅下降 | 无 |
| SnapKV | ~6× (16%保留) | 接近Full | 无 |
| PyramidKV | ~8× (12%保留) | 匹配Full | 无 |
| **RocketKV** | **400×** | **可忽略损失** | **无** |

### 局限与产业意义

**局限**：
- Stage 1驱逐不可逆
- 增益主要在Decode阶段
- 仅在A100上验证

**产业意义**：
- 第一个实现**400×压缩比**且精度几乎无损的方法
- NVIDIA出品，硬件协同设计
- ICML 2025，多轮对话场景的SOTA

## ★★★ MoE-nD — 逐层多轴路由：把压缩当成MoE问题

**论文**：MoE-nD: Per-Layer Mixture-of-Experts Routing for Multi-Axis KV Cache Compression
**ID**：arXiv:2604.17695 | Libo Sun, Peixiong He, Po-Wei Harn, Xiao Qin
**机构**：Georgia Tech
**发表**：2026年4月（预印本）

### 问题：均匀压缩配方的根本缺陷

```
KV Cache 是四维张量: [layer × head × seq_len × hidden_dim]

现有方法各压缩一个维度：
  驱逐 → 压缩 seq_len
  量化 → 压缩 precision
  低秩 → 压缩 hidden_dim
  跨层共享 → 压缩 layer

但所有层都用同一个配方！
→ 浅层对驱逐敏感 → 不该驱逐
→ 深层对量化敏感 → 不该量化
→ 均匀配方必然在某层过度压缩
```

### 核心发现：层的异构性

**实验证据**（4任务LongBench子集 + AIME推理）：

| 配方 | 问题 |
|------|------|
| 全局统一驱逐 | 浅层精度崩溃 |
| 全局统一量化 | 深层精度下降 |
| 全局统一低秩 | 关键层信息丢失 |
| **逐层异构** | **每种操作只在适合的层执行** |

### MoE-nD 方案：压缩即路由

```
将压缩操作类比为MoE中的"专家"：
  Expert 1: 驱逐（eviction-ratio = α）
  Expert 2: K量化（K-bits = b_k）
  Expert 3: V量化（V-bits = b_v）

每层的路由 = (α_i, b_k_i, b_v_i)

离线贪心求解器：
  目标: 全局内存预算下最小化预测质量损失
  方法: 逐层校准 → 贪心分配 → 全局约束
```

### 关键数据

| 指标 | 结果 |
|------|------|
| 14×压缩 | **匹配1.9GB未压缩基线** |
| 其他方法@同内存 | <8/100（几乎不可用）|
| AIME推理 | **+6到+27分** vs 最强逐层量化 |
| 短输入(MATH-500/TREC) | 无增益（solver选keep=1.0）|

### 负面结果的分析价值

```
MATH-500和TREC无增益 → 原因：输入短 → solver选择大部分层keep=1.0
→ 干净地界定了方法的适用范围：
  ✅ 长输入 + 推理密集 → 显著增益
  ❌ 短输入 → 无损但无增益
```

### 产业意义

- 将KV压缩从"**选一种方法统一应用**"升级为"**逐层最优混合**"
- MoE思想迁移到压缩领域，开辟新范式
- 离线校准一次性，推理时零额外开销

## ★★★ RDKV — 率失真统一：驱逐和量化是同一问题的两端

**论文**：RDKV: Rate-Distortion Bit Allocation for Joint Eviction and Quantization of the KV Cache
**ID**：arXiv:2605.08317 | Junkai Zhang, Hang Guo, Luca Benini, Yawei Li
**机构**：ETH Zürich
**发表**：2026年5月（预印本）

### 问题：驱逐和量化的人为割裂

```
现有范式：
  方法A: 做驱逐 → 再做量化（串行，各自独立优化）
  方法B: 只做驱逐
  方法C: 只做量化

问题：
  Token X → 驱逐成本低但量化成本高（该驱逐）
  Token Y → 驱逐成本高但量化成本低（该量化到低bit）
  → 独立优化无法看到全局最优
```

### 核心洞察：驱逐 = 0-bit量化

```
Rate-Distortion 理论框架：

  bit-width = 0  → 驱逐（ eviction）
  bit-width = 2  → 2-bit量化
  bit-width = 4  → 4-bit量化
  bit-width = 16 → 全精度保留

  所有操作都是同一个"比特分配"问题的不同点！
```

### RDKV 方案：反向注水（Reverse Water-Filling）

```
Step 1（Prefill后一次）：
  对每个token/channel计算"注意力失真权重"
  → 该token被压缩到b-bit时，attention输出会扭曲多少？

Step 2：反向注水分配
  全局内存预算 = B bits
  
  ┌──────────────────────────────────────────┐
  │  Token重要性高 ████████████ 16-bit (Full) │
  │  Token重要性中 ██████ 4-bit              │
  │  Token重要性低 ██ 2-bit                  │
  │  Token不重要 ░ 0-bit (驱逐)              │
  └──────────────────────────────────────────┘
  
  "水面" = 预算B，注水分配使全局失真最小化
```

### 关键数据

| 指标 | 结果 |
|------|------|
| vs 最优基线 | **+9.1%平均**（LongBench/RULER/InfiniteBench）|
| 2.48%保留 | **97.81% Full-Cache精度**（LongBench）|
| vs FlashAttention-2 Full | **4.5× Decode加速**，1.9×峰值内存降低 |
| 上下文长度 | 128K |

### 与之前方法的本质区别

| 方法 | 驱逐 & 量化关系 | 全局最优？ |
|------|:---:|:---:|
| H2O + KIVI | 串行独立 | ❌ |
| MoE-nD | 逐层独立选择 | ✅ 逐层 |
| **RDKV** | **统一为比特分配** | **✅ 全局** |

### 产业意义

- 用**信息论**统一了KV压缩的两大方向（驱逐 + 量化）
- 反向注水是经典R-D理论在KV Cache上的首次应用
- ETH Zürich出品，理论严谨

## ★★★ OSCAR — INT2极限量化：注意力感知的频谱旋转

**论文**：OSCAR: Offline Spectral Covariance-Aware Rotation for 2-Bit KV Cache Quantization
**ID**：arXiv:2605.17757 | Zhongzhu Zhou, Donglin Zhuang 等
**机构**：UW-Madison + Together AI
**发表**：2026年5月（预印本）

### 问题：INT2 KV量化的最后一公里

```
2-bit KV Cache量化：
  Hadamard旋转 → 减少异常值 → 量化
  但推理模型(reasoning models)的长CoT轨迹 → INT2精度崩溃

Qwen3-4B-Thinking-2507 + INT2 + Hadamard旋转：
  → 准确率几乎归零！（vs BF16基线）
```

### 核心发现：旋转矩阵需要对齐注意力

**Hadamard旋转的问题**：
- Hadamard是**注意力无关**的通用旋转
- 减少了异常值，但没有对齐到attention实际使用的方向
- 推理模型的CoT轨迹中，attention对某些方向极其敏感

**OSCAR的思路**：
- 离线估计KV的**注意力感知协方差结构**
- 从协方差推导旋转矩阵 → 对齐到attention实际关注的方向
- 旋转后异常值分布与attention需求一致 → INT2精度保持

### OSCAR 方案

```
离线校准（每模型一次）：
  1. 用校准数据前向传播 → 收集KV Cache
  2. 估计注意力感知协方差矩阵 Σ_attention
  3. 从 Σ_attention 推导固定旋转矩阵 R
  4. 计算最优clipping阈值

推理时：
  KV → R × KV → INT2量化 → 存储
  Decode时: INT2反量化 → R^T × KV → Attention
  
  自定义INT2 Attention Kernel:
  - 兼容PagedAttention（vLLM）
  - 兼容Fused Pipeline（SGLang）
  - 零额外反量化开销（融合在attention kernel中）
```

### 关键数据

| 模型 | INT2精度(BF16 gap) | Hadamard INT2 |
|------|:---:|:---:|
| Qwen3-4B-Thinking | **3.78 pts** | ~0（崩溃）|
| Qwen3-8B | **1.42 pts** | ~0（崩溃）|
| Qwen3-32B | **≈ BF16** | - |
| GLM-4.7 (358B) | **≈ BF16** | - |

| 系统指标 | 结果 |
|---------|------|
| KV内存降低 | **~8×** |
| 大batch吞吐 | **7×** |
| 单请求Decode加速 | **3×** |
| RULER-NIAH | 128K稳定 |

### 产业意义

- 第一个在**推理模型INT2**上近无损的KV量化
- **可部署**：SGLang/vLLM集成，非论文-only
- 旋转+量化联合优化的新范式

## ★★ STAR-KV — 自适应低秩：可微分软阈值

**论文**：STAR-KV: Low-Rank KV Cache Compression via Soft Thresholding for Adaptive Rank Control
**ID**：arXiv:2606.08382 | Priyansh Bhatnagar 等
**机构**：Arizona State University + KAIST 等
**发表**：2026年6月（预印本）

### 问题：固定秩低秩压缩的僵化

```
低秩压缩（如Palu）→ 固定rank r
  所有head/block用同一个r
  → 敏感head被过度压缩
  → 不敏感head压缩不够
```

### STAR-KV 三重创新

**① 可微分软阈值（Soft Thresholding）**
```
传统: rank = 固定整数r（不可优化）
STAR-KV: rank = soft_threshold(σ) 
  σ是可学习参数 → 梯度下降自动找到每层/head的最优秩
```

**② K/V混合分解**
```
Key → 对低秩更敏感 → 用更精确的分解
Value → 对低秩较不敏感 → 可用更激进的分解
（呼应KIVI的K/V非对称洞察）
```

**③ 低秩感知混合精度量化**
```
低秩近似后 → 再叠加量化
利用低秩结构的数据统计 → 选择性混合精度
→ 近无损低比特量化
```

### 关键数据

| 指标 | 结果 |
|------|------|
| 低秩压缩 | **75%** |
| 含量化总压缩 | **20×** |
| Attention模块加速 | **6.9×** |
| 端到端吞吐 | **3.1×** |
| 自定义Kernel | Triton实现 |

### 与ThinK/Palu对比

| 方法 | 秩选择 | K/V区分 | 量化 | Kernel |
|------|--------|:---:|:---:|:---:|
| Palu | 固定 | ❌ | ❌ | ❌ |
| ThinK | Query-driven | ❌ | ❌ | 需定制 |
| **STAR-KV** | **可学习** | **✅** | **✅ 混合精度** | **✅ Triton** |

## ★★ TriAttention — 三角级数：Pre-RoPE空间的长推理压缩

**论文**：TriAttention: Efficient Long Reasoning with Trigonometric KV Compression
**ID**：arXiv:2604.04921 | Weian Mao, Xi Lin, Wei Huang 等
**机构**：MIT HAN Lab + 浙江大学
**发表**：2026年4月（预印本）

### 问题：长推理场景下KV压缩的失败

```
推理模型(如DeepSeek-R1)生成32K+ token的CoT
→ KV Cache爆炸 → 需要压缩

但传统KV压缩在长推理中失败：
  用最近几步的post-RoPE query估计重要性
  → RoPE旋转使query随位置变化
  → "代表性"query极少 → top-key选择不稳定
  → 推理链断裂 → 精度崩溃
```

### 核心发现：Pre-RoPE空间的Q/K集中现象

```
Post-RoPE空间（旋转后）：
  Q和K随位置旋转 → 方向不稳定 → 难以预测哪些K重要

Pre-RoPE空间（旋转前）：
  Q和K集中在固定的非零中心附近！
  → Q_center, K_center 不随位置变化
  → 中心决定了query偏好的key距离（三角级数关系）

  Q_center · K_center → cos(n·θ) 三角级数
  → 距离偏好 = f(中心方向)
  → 可用中心方向 + 距离 来score key重要性
```

### TriAttention 方案

```
重要性评分 = 三角级数距离偏好 + Q/K范数

  score(key_j) = Σ trig(center_q, center_k, dist(j))
               + λ · ||Q|| · ||K_j||

  → 无需post-RoPE attention score
  → 无需在线计算（可预计算距离偏好）
  → 对长推理轨迹稳定
```

### 关键数据

| 指标 | 结果 |
|------|------|
| AIME25 (32K生成) | **匹配Full Attention精度** |
| 或 | **2.5×吞吐** *或* **10.7×内存降低** |
| vs 基线@同效率 | 基线仅~50%精度 |
| OpenClaw部署 | **单消费级GPU**（Full Attention会OOM）|

### 产业意义

- 专门解决**长推理场景**的KV压缩——这是推理模型时代的核心痛点
- MIT HAN Lab出品（与StreamingLLM/DuoAttention同一团队）
- 数学优雅：Pre-RoPE集中 → 三角级数 → 距离评分

## ★★ CompressKV — 语义检索头：GQA模型的精准压缩

**论文**：CompressKV: Semantic-Retrieval-Guided KV-Cache Compression for Resource-Efficient Long-Context LLM Inference
**ID**：arXiv:2606.24467 | Xiaolin Lin, Jingcun Wang 等
**机构**：TU Darmstadt
**发表**：2026年6月（预印本）

> ⚠️ 注意：arXiv标注此文与2508.02401有大量文本重叠，原创性待验证

### 问题：GQA模型中聚合所有head的陷阱

```
GQA架构: 多个Query Head共享同一组K/V Head

现有方法: 将所有Query Head的注意力分数聚合 → 选top-k token
问题: 大部分Streaming Head的注意力是噪声
  → 聚合后噪声稀释了Retrieval Head的信号
  → 重要token被误判为不重要 → 被驱逐
```

### CompressKV 方案

```
Step 1: 离线识别Semantic Retrieval Heads (SRHs)
  SRH特征:
    ✅ 关注prompt首尾token
    ✅ 捕获中间语义关键证据
  
Step 2: 仅用SRH的注意力分数选token（而非全部head聚合）

Step 3: 逐层预算分配
  离线估计每层的驱逐误差 → 误差大的层分配更多预算
```
