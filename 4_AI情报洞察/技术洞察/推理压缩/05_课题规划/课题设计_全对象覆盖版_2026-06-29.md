# 一、量化（4个课题，覆盖权重+激活+KV+通信）

---

## 课题Q1【权重量化】LLM/VLM全模型INT4 NPU部署量化

### 场景痛点
LLM 7B需INT4才能在单卡910B（64GB）部署。VLM的ViT编码器22B参数更需压缩。当前NPU有权重量化但缺乏旋转预处理（SpinQuant在GPU上，NPU未适配）。

### 核心创新
**NPU适配的旋转量化+INT4部署全流程**：
- 旋转矩阵学习（SpinQuant方法）适配Ascend Cube INT4指令
- 不同模块差异化：LLM权重INT4 + ViT编码器INT4 + ASR INT4 + TTS INT4
- mindie框架级集成

### 参考
SpinQuant(87ref) / FlatQuant(5ref) / QuaRot / AMXFP4(ACL2025)

### 目标
Qwen3-7B INT4单卡910B部署，全任务精度损失≤2%

---

## 课题Q2【激活量化】长上下文注意力激活INT8量化

### 场景痛点
128K翻译输入时注意力计算O(n²)是计算瓶颈。注意力激活（Q×K^T的输出、softmax后attention weight）占用大量内存。SageAttention做了8-bit注意力但只在GPU上，NPU没有。

### 核心创新
**NPU注意力激活量化kernel**：
- Q×K^T结果INT8存储（而非FP16）
- Softmax在INT8上近似计算
- Attention×V在INT8上完成
- 全程免反量化，利用Cube INT8指令

### 参考
SageAttention(ICLR2025, 8-bit注意力) / TEAL(ICLR2025, 激活稀疏) / FlashAttention(kernel设计)

### 目标
128K注意力计算加速2×，精度损失≤0.5%

---

## 课题Q3【KV量化】通话历史时间衰减渐进KV量化

（同之前设计的Q1，按对话轮次2/4/8-bit渐进）

### 参考
KVTuner / KIVI / OSCAR / ThinKV / Block-GTQ

---

## 课题Q4【通信量化】多卡MoE推理INT4 All-to-All通信

### 场景痛点
如果用DeepSeek-V3级别的MoE模型做翻译/通话，多卡910B间All-to-All通信占40-60%时间。DeepEP仅FP8，FlashMoE未做量化。

### 核心创新
**动态精度All-to-All**：热专家FP8 + 冷专家INT4 + HCCL量化-通信-计算流水线

### 参考
FlashMoE(NeurIPS2025) / DeepEP / Occult(ICML2025) / FoMoE(ICLR2026)

# 二、稀疏（4个课题，覆盖权重+激活+KV+视觉）

---

## 课题S1【权重/层稀疏】通话实时性的层跳过

### 场景痛点
通话助手要求<500ms响应，但LLM 32层全计算太慢。Deeper Layers(90ref)证明深层50%冗余——通话场景中简单回复（"好的""明白了"）不需要32层。

### 核心创新
**通话难度感知的动态层跳过**：
- 轻量分类器预测当前token的"推理难度"
- 简单回复（闲聊/确认）：跳过深层，只用前16层
- 复杂回复（翻译/推理）：全32层
- 与NPU Cube分块对齐：跳过的层不加载权重

### 参考
Deeper Layers(90ref, ICLR2025) / ShortGPT(139ref) / LayerSkip(Meta)

### 目标
通话场景平均层计算减少30-40%，简单对话延迟降低40%

---

## 课题S2【激活稀疏】长上下文翻译的注意力稀疏化

### 场景痛点
128K翻译的注意力矩阵是128K×128K，但99%的attention score接近0（远距离token几乎不相关）。当前全部计算是浪费。

### 核心创新
**翻译位置感知的动态稀疏注意力**：
- 当前翻译位置±滑动窗口：全注意力
- 术语/实体位置：保留（跨距离引用）
- 其他位置：自动稀疏化（attention score<阈值→跳过）
- 句子边界检测驱动窗口大小自适应

### 参考
StreamingLLM(ICLR2024, sink+window) / SnapKV / TidalDecode(ICLR2025) / MoBA(Kimi生产)

### 目标
128K注意力计算量降低5-10×，BLEU损失≤0.5

---

## 课题S3【KV稀疏】通话行为感知的KV语义稀疏

（同之前设计的S1，按对话行为类型差异化保留）

### 参考
SnapKV / DuoAttention(34ref) / KVzip / LazyLLM

---

## 课题S4【视觉激活稀疏】VLM通话中的视觉Token动态压缩

### 场景痛点
通话中如果用户发了图片/屏幕截图，VLM产生2570个视觉token。通话进行后大部分视觉信息不再被关注，但KV仍全量缓存。

### 核心创新
**通话上下文引导的视觉Token稀疏**：
- 当前对话query与视觉patch的对齐分数动态更新
- 高对齐（用户正在讨论的图片区域）：保留
- 低对齐（无关背景）：稀疏化/合并
- 通话推进后自动压缩历史图片的KV

### 参考
VoCo-LLaMA(576×, CVPR2025) / VL-Cache(90%↓) / SparseVLM / KVCapsule

### 目标
5图通话：视觉Token压缩8×，VQA损失≤2%

# 三、蒸馏（4个课题，覆盖模型+KV+激活+管线）

---

## 课题D1【模型蒸馏】通话翻译专用小模型蒸馏

### 场景痛点
通用大模型（Qwen3-72B）翻译质量好但太慢。DeepSeek-R1-Distill证明可以蒸馏推理能力到7B。但通话翻译需要：翻译质量+实时性+多轮上下文，三者联合蒸馏无人做。

### 核心创新
**通话翻译三能力联合蒸馏**：
- 翻译能力蒸馏：大模型翻译输出 → 小模型学习
- 实时性蒸馏：蒸馏时加入延迟约束（输出长度控制）
- 多轮上下文蒸馏：蒸馏时模拟多轮场景（不只单句翻译）
- 损失函数：L = α·L翻译 + β·L延迟 + γ·L多轮一致性

### 参考
rStar-Math(78ref, 推理蒸馏) / DeepSeek-R1-Distill / Smaller Weaker Yet Better(33ref)

### 目标
72B→7B蒸馏，翻译BLEU≥大模型95%，推理延迟<300ms

---

## 课题D2【KV蒸馏】通话记忆蒸馏——历史KV压缩为记忆Token

（同之前设计的D1，将50轮历史KV蒸馏为64个记忆Token）

### 参考
KVSculpt(连续空间) / Activation Beacon(ICLR2025) / KV-Distill / SwiftKV

### 目标
50轮通话：KV压缩为64记忆Token（>100×），通话质量损失≤3%

---

## 课题D3【激活蒸馏】长上下文注意力模式蒸馏

### 场景痛点
长文本翻译时，大模型（72B）的注意力模式（哪些位置互相关注）包含丰富信息。小模型（7B）的注意力模式较粗糙。能否蒸馏注意力模式本身？

### 核心创新
**注意力模式蒸馏**：
- 教师（72B）的attention map → 学生（7B）学习对齐
- 重点蒸馏：翻译中的长距离依赖（句子间的术语一致性）
- 损失函数：L = L_KL(attention分布对齐) + L_MSE(attention weight回归)

### 参考
Differential Transformer(44ref) / Retrieval Head(51ref, 注意力头分析) / GKD(注意力蒸馏)

### 目标
7B学生模型的长距离翻译一致性提升，术语一致性≥90%

---

## 课题D4【管线蒸馏】ASR-LLM-TTS跨段联合蒸馏

### 场景痛点
通话管线三段独立：ASR→文本→LLM→文本→TTS。跨段有冗余转换（声学→文本→token→embedding→文本→声学）。全链路延迟>1秒。

### 核心创新
**跨段中间表示蒸馏**：
- ASR编码器输出 → 直接蒸馏为LLM embedding（跳过ASR解码+文本化）
- LLM输出 → 直接蒸馏为TTS声码器输入（跳过文本化+TTS tokenizer）
- 三段KV联合压缩

### 参考
VoCo-LLaMA(跨模态蒸馏) / Seamless(Meta统一语音翻译) / Distil-Whisper

### 目标
全链路延迟<500ms，MOS≥4.0
