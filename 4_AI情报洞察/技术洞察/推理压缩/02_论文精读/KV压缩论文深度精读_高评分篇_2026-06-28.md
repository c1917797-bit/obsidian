## ★★★ Retrieval Head — 注意力头的机械解释：为什么KV压缩有效

**论文**：Retrieval Head Mechanistically Explains Long-Context Factuality
**ID**：arXiv:2404.15574 | Wenhao Wu, Yizhong Wang, Yao Fu 等
**发表**：ICLR 2025 | **评分 8.0**（KV方向最高分）

### 问题

KV压缩方法（H2O/SnapKV/DuoAttention）发现"某些head更重要"，但**为什么？哪些head？能否精确定位？**

### 核心发现：Retrieval Head的五大性质

| 性质 | 说明 |
|------|------|
| **普遍性** | 所有具备长上下文能力的模型都有Retrieval Head |
| **稀疏性** | 仅 **<5%** 的head是retrieval head |
| **内禀性** | 在短上下文预训练时已存在，不随上下文扩展而新增 |
| **动态激活** | 少数head始终激活（Llama-2-7B有12个），其余随上下文激活 |
| **因果性** | 剪枝retrieval head → 检索失败+幻觉；剪枝随机非retrieval head → 无影响 |

### 对KV压缩的指导意义

```
Retrieval Head 发现 → 解释了 DuoAttention 为什么要区分head类型
                   → 指导KV压缩：retrieval head必须保留全量KV
                   → 连接CoT推理：CoT需要频繁回溯 → 依赖retrieval head
```

### 产业意义

- ICLR 2025 KV方向最高分（8.0），理论指导价值极高
- 为所有head-level KV压缩方法提供**机械解释**
- 指导未来方向：保护retrieval head → 同时实现高压缩+保持检索

## ★★ DeFT — 树结构推理的Flash Attention

**论文**：DeFT: Decoding with Flash Tree-attention for Efficient Tree-structured LLM Inference
**ID**：arXiv:2404.00242 | LINs-lab
**发表**：ICLR 2025 | 评分 7.5

### 问题

投机解码/few-shot/多步推理 → **树结构共享前缀** → 现有FlashAttention按线性序列设计 → 共享前缀被重复加载

### 方案

**KV-Guided Grouping**：按"需要哪些KV"来分组Query（而非按Query分组），避免共享前缀重复IO。

**Flattened Tree KV Splitting**：将树展平后均匀分割KV到GPU分区，实现负载均衡。

### 关键数据

| 指标 | 结果 |
|------|------|
| KV Cache IO减少 | **73-99%** |
| 部分结果IO减少 | **~100%** |
| 端到端加速 | **2.23×** |
| Attention延迟加速 | **3.59×** |

## ★★ MagicPIG — LSH采样：有理论保证的注意力近似

**论文**：MagicPIG: LSH Sampling for Efficient LLM Generation
**ID**：arXiv:2410.16179 | Infini-AI-Lab
**发表**：ICLR 2025 | 评分 7.2

### 问题

TopK注意力假设"注意力是稀疏的"——但某些任务中注意力并不稀疏，TopK选择导致质量下降。

### 方案

将注意力近似重新定义为**采样问题**（非选择问题）：
- 使用**Locality Sensitive Hashing (LSH)** 进行采样
- 提供**无偏估计**的理论保证
- LSH哈希表 + 注意力计算放CPU → GPU内存释放

### 关键数据

| 指标 | 结果 |
|------|------|
| 解码吞吐量 | **5×** 提升 |
| RTX 4090上Llama-3.1-8B 96K上下文 | **54ms** 解码延迟 |

### 与TopK方法对比

| 方法 | 理论保证 | 稠密注意力任务 | 硬件设计 |
|------|:---:|:---:|---------|
| TopK (H2O) | ❌ | 质量下降 | GPU |
| **MagicPIG (LSH)** | **✅ 无偏** | **质量保持** | **GPU+CPU异构** |

## ★★ Activation Beacon — 直接压缩激活：灵活的上下文压缩

**论文**：Long Context Compression with Activation Beacon
**ID**：arXiv:2401.03462 | 智源研究院(BAASS)
**发表**：ICLR 2025 | 评分 7.0

### 问题

之前的方法用soft prompt间接传递压缩信息 → 信息瓶颈 → 长上下文理解差。

### 方案

**直接压缩激活（K/V）** 而非soft prompt：
1. 每层渐进式细粒度压缩
2. **压缩自回归训练**：用纯文本+指令数据优化
3. **随机压缩比训练**：每步随机采样压缩比 → 单模型支持任意压缩配置

### 关键数据

| 指标 | 结果 |
|------|------|
| 推理加速 | **2×** |
| KV内存降低 | **8×** |
| 128K上下文（训练仅20K） | 与未压缩基线相当 |

### 核心创新点

随机压缩比训练使模型学会适应不同压缩率 → 推理时可按需选择 → 灵活性极高。

## ★★ MagicDec — 大Batch投机解码：打破延迟-吞吐权衡

**论文**：MagicDec: Breaking the Latency-Throughput Tradeoff for Long Context Generation
**ID**：arXiv:2408.11049 | CMU + Meta 等
**发表**：ICLR 2025 | 评分 6.8

### 核心发现

**传统认知**：投机解码(SD)只在小batch有效。
**MagicDec发现**：长上下文场景下，SD在**大batch（32-256）**仍能加速！

```
原因：随batch增大 + 序列变长：
  瓶颈从Compute-bound → Memory-bandwidth-bound（KV Cache加载）
  SD的draft model用稀疏KV → 减少KV瓶颈 → 大batch也能加速
```

### 关键数据

| 指标 | 结果 |
|------|------|
| Llama3.1-8B batch=32-256 | **2.51×** 加速 |
| 精度 | 无损 |

### 产业意义

颠覆了"SD只适合小batch"的认知，为生产级长上下文推理服务开辟新路。

## ★★ Samba — Mamba+SWA混合：线性时间的无限上下文

**论文**：Samba: Simple Hybrid State Space Models for Efficient Unlimited Context Language Modeling
**ID**：arXiv:2406.07522 | Microsoft
**发表**：ICLR 2025 | 评分 6.7

### 方案

逐层交替Mamba（SSM） + Sliding Window Attention：
- Mamba → 将序列压缩为循环隐状态（无限上下文）
- SWA → 精确回忆最近的token（局部精度）

### 关键数据

| 指标 | 结果 |
|------|------|
| 128K吞吐量 vs GQA Transformer | **3.73×** |
| 64K生成速度 | **3.64×** |
| Zero-shot PPL | 改善至 **1M token** |
| 4K训练→256K推理 | Passkey完美回忆 |

### 产业意义

证明了**混合SSM架构**可scale到3.8B/3.2T tokens，彻底绕过KV Cache问题。

## ★★ HeadKV — 头级KV压缩：1.5%保留→97%性能

**论文**：Not All Heads Matter: A Head-Level KV Cache Compression Method with Integrated Retrieval and Reasoning
**ID**：arXiv:2410.19258
**发表**：ICLR 2025 | 评分 6.5

### 方案

将KV压缩从**层级别**细化到**头级别**：
- HeadKV：逐头评估重要性
- HeadKV-R2：估计每个头对"检索+推理"的综合贡献

### 关键数据

| KV保留比例 | 性能（vs Full KV）|
|-----------|-----------------|
| **1.5%** | **97%** |
| 64-128条 | 大幅超越层级基线 |

与DuoAttention（同为头级别）的差异：HeadKV-R2同时考虑检索+推理，DuoAttention主要关注检索。

## ★★ SCBench — KV Cache全生命周期基准

**论文**：SCBench: A KV Cache-Centric Analysis of Long-Context Methods
**ID**：arXiv:2412.10319 | Microsoft
**发表**：ICLR 2025 | 评分 6.5

### 方案

第一个**KV Cache全生命周期**评测基准，覆盖4个阶段：
1. KV生成 2. KV压缩 3. KV检索 4. KV加载

使用**共享上下文+多轮**测试模式，模拟vLLM/SGLang/OpenAI API的真实场景。

### 关键发现

| 发现 | 说明 |
|------|------|
| sub-O(n)内存方法 | **多轮场景失败** |
| 动态稀疏 > 静态稀疏 | 动态模式更有表达力 |
| 混合架构层级稀疏 | 减少内存且性能强 |
| 长生成注意力漂移 | **新发现**：长生成中attention分布漂移 |

### 产业意义

为KV Cache方法提供**生产级评测标准**，被广泛引用。

## ★★ LongGen — 训练推理一体化：上下文扩展+KV优化一步到位

**论文**：A Little Goes a Long Way: Efficient Long Context Training and Inference with Partial Contexts
**ID**：arXiv:2410.01485
**发表**：ICLR 2025 | 评分 6.4

### 核心创新

将两个独立步骤合并：
```
传统流程：上下文扩展训练 → 再做KV优化改造 → 两个独立步骤
LongGen：上下文扩展 + KV优化同时进行 → 一步到位
```

**架构**：1/3 Full Attention + 2/3 高效层（Window + Sink + Block Sparse）

### 关键数据

| 指标 | 结果 |
|------|------|
| 128K训练加速 | **1.55×** |
| 墙钟时间降低 | **36%** |
| KV内存降低 | **62%** |
| Prefill加速 | **1.67×** |
| Decode加速 | **1.41×** |
| 训练数据需求 | 仅5B tokens（4K→128K）|

## ★★ Provence — RAG上下文剪枝：即插即用

**论文**：Provence: efficient and robust context pruning for retrieval-augmented generation
**ID**：arXiv:2501.16214
**发表**：ICLR 2025 | 评分 6.2

### 方案

将上下文剪枝建模为**序列标注**任务（token/passage级别决策），统一剪枝+重排序到一个模型中。

### 关键特性

- 动态检测所需剪枝量（非固定比例）
- 多领域训练 → 即插即用，无需领域适配
| 指标 | 结果 |
|------|------|
| 性能损失 | 可忽略 |
| 额外开销 | 几乎为零 |
| RAG Pipeline集成 | drop-in |
