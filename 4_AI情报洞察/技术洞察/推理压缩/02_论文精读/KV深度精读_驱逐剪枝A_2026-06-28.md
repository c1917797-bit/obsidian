## ★★ KVzip — 上下文重构：Query无关的KV驱逐

**论文**：KVzip: Query-Agnostic KV Cache Compression with Context Reconstruction
**ID**：arXiv:2505.23416
**发表**：预印本 2025

### 问题：Query感知驱逐的多查询退化

```
现有方法（H2O/SnapKV）：基于特定query的attention score驱逐KV
→ 压缩后的KV Cache与该query绑定
→ 换一个query时 → 性能严重下降
→ 多查询场景（如RAG多轮问答）→ 90%预算比仍退化！
```

### KVzip 方案：用LLM自身评估KV重要性

```
核心思路：让LLM自己判断"哪些KV对上下文理解最重要"

Step 1：用LLM从缓存的KV对重建原始上下文
Step 2：重建困难 → 该KV重要 → 保留
        重建容易 → 该KV冗余 → 驱逐
Step 3：驱逐后 → 压缩KV可跨不同query复用（Query无关）
```

**关键区别**：
| 方法 | 依赖Query？ | 多查询表现 |
|------|:---:|---------|
| H2O | ✅ | 90%预算仍退化 |
| SnapKV | ✅ | 观察窗口绑定 |
| **KVzip** | **❌** | **3-4×压缩后无损** |

### 关键数据

| 指标 | 结果 |
|------|------|
| KV压缩比 | **3-4×** |
| FlashAttention解码延迟 | **~2× 降低** |
| 最大上下文 | **170K** |
| 测试模型 | LLaMA3.1, Qwen2.5, Gemma3 |
| vs query-aware方法@90%预算 | **显著优于** |

### 产业意义

解决了多查询场景下KV Cache复用的核心痛点——一次压缩，多查询通用。

## ★★ MadaKV — 模态感知：多模态KV驱逐

**论文**：MadaKV: Adaptive Modality-Perception KV Cache Eviction for Efficient Multimodal Long-Context Inference
**ID**：arXiv:2506.15724

### 问题

传统KV驱逐为纯文本设计 → 多模态场景中不同attention head对视觉/文本模态有不同偏好 → 统一驱逐策略次优。

### 方案

```
① 模态偏好适应：动态感知每个head的模态偏好
   - 视觉偏好head → 保留视觉相关token
   - 文本偏好head → 保留文本相关token

② 层次化压缩补偿：跨层补偿模态信息损失
```

### 关键数据

| 指标 | 结果 |
|------|------|
| KV内存+延迟改善 | **1.3-1.5×** |
| 基准 | MileBench（多模态长上下文）|
| 精度 | 维持 |

## ★★ MiniKV — 2-bit分层判别：FlashAttention兼容

**论文**：MiniKV: Pushing the Limits of LLM Inference via 2-Bit Layer-Discriminative KV Cache
**ID**：arXiv:2411.18077

### 问题

2-bit KV量化的精度损失 + FlashAttention兼容性。

### 方案

**2-bit分层判别KV Cache**：不同层使用不同的2-bit配置（敏感层更精细）。开发专用CUDA Kernel兼容FlashAttention。

### 关键数据

| 指标 | 结果 |
|------|------|
| KV压缩率 | **86%** |
| 精度恢复 | **>98.5%** |
| FlashAttention兼容 | ✅ |

## ★★ Mustafar — 非结构化稀疏：70%稀疏无需微调

**论文**：Mustafar: Promoting Unstructured Sparsity for KV Cache Pruning in LLM Inference
**ID**：arXiv:2505.22913

### 问题

结构化稀疏（block/head级别）限制压缩率 → 能否用非结构化稀疏（任意位置剪枝）？

### 核心发现

```
Key Cache: 异常channel突出 → 幅度剪枝有效（呼应KIVI/ThinK）
Value Cache: 分布均匀但幅度剪枝竟也有效！（意外发现）
```

### 方案

- Per-token幅度剪枝 → 非结构化稀疏模式
- Bitmap稀疏格式 + 自定义attention kernel → 直接在压缩cache上计算

### 关键数据

| 指标 | 结果 |
|------|------|
| 稀疏率 | **70%** |
| KV Cache压缩 | **45%** of dense |
| 吞吐量 | **2.23×** |
| 微调需求 | **无** |

## ★★ SpeCache — 投机KV预取：CPU卸载+预测

**论文**：SpeCache: Speculative Key-Value Caching for Efficient Generation of LLMs
**ID**：arXiv:2503.16163

### 问题

KV Cache超出GPU显存 → 卸载到CPU → 每步需从CPU取KV → PCIe延迟。

### 方案

```
GPU: 保留低bit KV副本 → 快速评估各token重要性
CPU: 全量KV Cache

投机预取：
  当前步 → 预测下一步可能需要的KV → 提前从CPU预取
  → 预取与计算并行 → 隐藏PCIe延迟
```

### 关键数据

| 指标 | 结果 |
|------|------|
| 压缩比 | **10×** |
| 信息遗忘 | 无（全量在CPU）|
| 基准 | LongBench + NIAH |
| 重训练 | 无 |

## ★★ AttentionPredictor — 时序模式预测：13×压缩

**论文**：AttentionPredictor: Temporal Patterns Matter for KV Cache Compression
**ID**：arXiv:2502.04077 | NeurIPS 2025

### 问题

现有方法静态建模attention score → 忽略了attention score的**时序模式** → 关键token识别不准。

### 方案

```
① 轻量统一卷积模型 → 动态捕获时空模式 → 预测下一步attention score
② 跨所有transformer层共享同一模型 → 内存可忽略
③ 跨token关键cache预取框架 → 隐藏估计开销
```

### 关键数据

| 指标 | 结果 |
|------|------|
| KV压缩 | **13×** |
| 速度提升 | **5.6×**（offloading场景）|
| 发表 | **NeurIPS 2025** |

## ★★ KVMerger — 自适应合并：高斯核加权

**论文**：Model Tells You Where to Merge: Adaptive KV Cache Merging for LLMs on Long-Context Tasks
**ID**：arXiv:2407.08454

### 问题

驱逐导致信息丢失 → 能否**合并**而非丢弃？

### 核心发现

Key states在同一序列内的token级别高度相似 → 可合并相似KV对。

### 方案

```
① 合并集识别算法 → 找到可合并的KV组
② KV稀疏性是模型级别（与数据集无关）→ 持久稳定
③ 高斯核加权合并 → 选择性合并每个集合内的状态
```

### 关键数据

| 指标 | 结果 |
|------|------|
| vs H2O @50%预算 | **更优** |
| vs H2O @35%预算 | **更优** |
| 基准 | LongBench + ZeroScroll |

## ★★ ContextCache — 上下文感知语义缓存

**论文**：ContextCache: Context-Aware Semantic Cache for Multi-Turn Queries
**ID**：arXiv:2506.22791

### 问题

现有语义缓存只匹配单个query → 忽略多轮对话上下文 → 错误缓存命中。

### 方案

两阶段检索：
1. 向量检索当前query → 找候选
2. Self-attention整合历史对话 → 精确上下文匹配

### 关键数据

| 指标 | 结果 |
|------|------|
| vs 直接LLM调用延迟 | **~10× 降低** |
| 精度+召回 | 超越现有方法 |
