## 二、通信压缩：MoE 时代的新瓶颈

### 2.1 为什么通信成为瓶颈

**DeepSeek-V3 实测数据：**
- 专家激活率：~8/671（1.2%）
- All-to-All 通信占 Prefill 时间：**40%+**
- 计算与通信开销比：接近 1:1

### 2.2 2026 论文中的通信压缩方案

| 论文 | 对象 | 方法 | 性能 |
|------|------|------|------|
| **SpectrumKV** | KV+通信 | per-token 精度分配 | TTFT 降低 50-62% |
| **KVServe** | KV+通信 | Bayesian Profiling | 9.13x JCT 加速 |
| **Semantic Cache Distillation** | KV+通信 | 蒸馏 + 稀疏 | 2.65x TTFT 加速 |
| **TokenDance** | KV+通信 | KV 共享 | 1.9x prefill 加速 |
| **MoE-nD** | KV | 每层不同压缩配置 | 14x 压缩，AIME +6~27 pts |

### 2.3 通信压缩的技术路径

```
路径1: 减少通信量
  - FP8 通信 (NVIDIA Hopper)
  - 通信量化 (INT4/INT8)
  - 路由器裁剪 (MegaScale-MoE)

路径2: 隐藏通信延迟
  - Compute-Communication Overlap
  - DualPipe (DeepSeek V3)
  - Async AllReduce

路径3: 减少传输次数
  - KV 合并 (KVSharer)
  - 跨请求 KV 复用
```

## 三、量化技术：已达哪些精度？

### 3.1 Weight 量化状态

| 精度 | 方法 | 质量损失 | 适用场景 |
|------|------|----------|----------|
| FP8 | 硬件支持 | 无损失 | 通用推理 |
| INT4 | GPTQ/AWQ | <1% | 高压缩场景 |
| INT2 | 特殊设计 | 2-5% | 极致压缩 |
| NF4 | bitsandbytes | <1% | LLM 专用 |

### 3.2 KV 量化状态

| 精度 | 方法 | 压缩比 | 关键问题 |
|------|------|--------|----------|
| INT4 | per-token | 4x | Key/Value 敏感性不同 |
| INT2 | KIVI 方案 | 4x | Key per-channel, Value per-token |
| 1.5bit | 探索中 | 6x+ | 精度损失大 |
| 混合 | TriAxialKV | 4.5x | 时间/模态/语义三维感知 |

**关键发现**：Value cache 的敏感性低于 Key cache，这解释了为什么非对称量化方案（如 KIVI）有效。

## 四、稀疏/剪枝技术：能做到多稀疏？

### 4.1 注意力稀疏

| 方法 | 保留比例 | 精度影响 | 代表工作 |
|------|----------|----------|----------|
| Window Attention | 窗口大小 | 严重下降 | 基础方案 |
| Heavy-Hitter | 20-30% | <1% | H2O |
| SnapKV | 50% | <1% | ICLR 2025 |
| StreamingLLM | 4 tokens + sink | <1% | ICLR 2024 |
| Pyramid-RKV | 层间差异 | 更优 | 2025 |

### 4.2 2026 年新方向

**问题**：现有方法主要依赖 attention score，但 attention score 与实际重要性存在差异。

**新思路**：
1. **信息论度量** (InfoKV)：Forward Influence - 预测未来 token 的能力
2. **语义检索头** (CompressKV)：识别捕获初始/结束 token 的头
3. **频域分析** (EntropyInfer)：识别 Rigid Head vs Dynamic Head
4. **Momentum 跟踪** (Moment-KV)：长期生成场景

## 五、蒸馏技术：真的有效吗？

### 5.1 KV 蒸馏现状

**理论优势**：
- 蒸馏信号可能比 attention score 更准确反映重要性
- 可以捕捉 attention 无法表达的语义关系

**2026 年实际进展**：

| 论文 | 方法 | 性能 | 问题 |
|------|------|------|------|
| YouZhi | GQA→MLA + 蒸馏 | 2.69x 并发 | 需微调 |
| Semantic Cache Distillation | 蒸馏 + 稀疏 | 2.65x TTFT | 需预计算 |
| MoE-nD | 每层路由 + 蒸馏 | 14x 压缩 | 复杂 |

**关键限制**：
- 在线蒸馏开销大（需额外 forward pass）
- 离线预计算损失动态适应性
- 与 attention-based 方法相比无显著优势

### 5.2 蒸馏 vs 其他方法对比

| 维度 | 剪枝 | 量化 | 蒸馏 |
|------|------|------|------|
| 压缩比 | 10-30x | 4-6x | 取决于实现 |
| 精度损失 | <1% | <1% | 可<1% |
| 计算开销 | 低 | 低 | 高 |
| 需微调 | 否 | 否 | 通常是 |
| 动态适应性 | 中 | 高 | 低 |

**结论**：蒸馏在 KV 压缩领域**尚未证明显著优于剪枝/量化**，主要原因：
1. 在线蒸馏开销抵消压缩收益
2. 静态预计算失去动态性
3. 缺乏与 attention 信号的互补性验证

## 七、基于数据的课题建议

### 课题 N：验证蒸馏信号假设

**当前问题**：2026 年有 3 篇论文（YouZhi, Semantic Cache Distillation, MoE-nD）声称蒸馏有效，但都需微调或预计算。

**假设**：蒸馏信号比 attention score 更能识别重要 KV

**两周验证计划**：
1. 提取 SnapKV 的 attention score 排序
2. 计算 teacher model 的 KV soft label 分布
3. 验证两者相关性：<0.7 则假设成立

**通过标准**：Pearson 相关系数 < 0.7

---

### 课题 N+1：低开销的动态 KV 压缩

**当前问题**：现有动态压缩（如 EntropyInfer, Moment-KV）需额外计算。

**机会**：利用推理过程中的中间结果（如 hidden states）做轻量压缩判断。

**技术路径**：
1. 利用 value norm 的统计特性（已知的轻量方法）
2. 结合 layer-wise importance 的先验
3. 设计无需额外 forward pass 的压缩判断

---

### 课题 N+2：PD 分离架构下的 KV 传输优化

**当前问题**：KVServe, SpectrumKV 显示 50-62% TTFT 降低，但需 PD 分离架构。

**机会**：如果你的系统已经是 PD 分离，这个方向是低 hanging fruit。

**关键指标**：TTFT 降低 50%+

## 八、结论

### 8.1 有血有肉的核心数据

```
KV 压缩极限：
  - 已验证：4-5x 压缩，<1% 精度损失
  - 理论极限：10x+ (需更多验证)

通信压缩：
  - DeepSeek V3 实测：All-to-All 占 40%+
  - 优化空间：50-60% TTFT 降低（已验证）

蒸馏在 KV 领域：
  - 2026 年 3 篇论文声称有效
  - 但需微调或预计算，开销抵消收益
  - 关键假设未经验证
```

|--------|------|------|
