## 1. R-KV: Redundancy-aware KV Cache Compression for Reasoning Models

| 属性 | 值 |
|------|-----|
| **arXiv** | [2505.24133](https://arxiv.org/abs/2505.24133)（v3, 2026-05） |
| **代码** | https://github.com/Zefan-Cai/R-KV |
| **作者** | Zefan Cai(Wisconsin)、Wen Xiao(Microsoft)、Anima Anandkumar(Caltech)、Junjie Hu 等 |
| **定位** | reasoning model KV 压缩的决定性工作；本报告"压状态"控制点的对标基线 |

### 核心贡献

首个**显式针对 reasoning model 冗余**的解码阶段 KV 压缩方法。揭示一个被忽视的事实：reasoning model 生成冗长且高度重复，**超半数 token 对任务贡献极小**，但现有 attention-based 压缩（SnapKV/H2O）反而**过度保留这些重复内容**——因为重复片段彼此产生高 attention。

### 关键观察（论据）

1. **冗余是结构性的**：reasoning model 生成长度是 ground truth 的 **8-14×**，1-/2-gram 频率高出 **5-7×**
2. **现有方法反向失效**：重复的自反思片段彼此 attention 高 → SnapKV 把它们当"重要"过度保留（论文 Figure 3 可视化）
3. **统计压缩在此系统性误判**：Naively pruning "低 attention" token 会误删关键但分散的推理片段

### 方法（三组件）

**① 重要性评分 I（attention-based）**
- 用最后 α=8 个 observation token 作 query，计算对每个 key 的 attention
- 支持 MHA 与 GQA（GQA 用组内 max-pool 聚合）
- 滑窗 max-pool（窗口 2W）稳定 outlier

**② 冗余评分 R（语义相似度，本报告"关系信号"的来源）**
- 对 key 向量做 cosine 相似度矩阵 `S = K̄·K̄ᵀ`
- token i 的冗余度 = 它与所有其他 key 的平均相似度（softmax 归一化）
- **强制保留最近的 β 个相似 token**（最近的更能支撑解码）

**③ 联合选择（关键公式）**
```
Z_i = λ·I_i − (1−λ)·R_i     保留 Z 最高的 top-k
λ = 0.1   ← 重冗余惩罚（redundancy 主导）
```
> **战略读法**：λ=0.1 意味着 R-KV 把 **90% 权重给冗余（关系）信号，10% 给重要性（统计）信号**。这是"关系信号压倒统计信号"的参数级证据——与本报告命题完全一致。

### 实验结果

| KV 保留 | baseline(SnapKV 类) | R-KV | 显存 | 吞吐 |
|--------|--------------------|------|------|------|
| 10% | 60% | **≈100%** | — | — |
| 16% | <100% | **105%**（超全量）| 90% 节省 | **6.6×** |

模型：R1-Llama-8B / R1-Qwen-14B；基准：MATH-500、AIME 2024。Training-free、model-agnostic，可用于 RL rollout 与 serving。

### 对关系压缩课题的启示

- ✅ **冗余评分（cosine 相似度）是隐式的关系信号**——但它只看"token 间相似"，不看"拓扑位置/桥接价值"。这正是课题一要升级的点：用**桥接中心性**替代"相似度"作为关系信号
- ✅ λ=0.1 证明：在 reasoning 负载下，**关系信号权重应远大于统计信号**，为课题一的超参数设定提供先验
- ⚠️ **局限**（来自 ThinKV 的批评 + R-KV 附录 D）：R-KV 仍是 token 级决策，未见思维/步骤语义；其 gather-based compaction 在大 batch 下有 **37× TPOT 慢化**（见 ThinKV §5.1）——系统层有改进空间

## 2. ShotKV / KVFundaBench: Semantic Integrity Matters（ICML 2026）

| 属性 | 值 |
|------|-----|
| **arXiv** | [2502.01941](https://arxiv.org/abs/2502.01941)（v3, 2026-05） |
| **会议** | **ICML 2026** |
| **作者** | Xiang Liu, Zhenheng Tang, Hong Chen, Xiaowen Chu（HKBU）等 |
| **定位** | **同行评审直接验证本报告"关系链断裂"命题**；最关键的命题背书 |

### 核心贡献

提出 **KVFundaBench**，首次系统揭示：现有 KV 压缩评测偏重"检索"（NIAH/LongBench），**掩盖了"高密度推理"（High-Density Reasoning）下的退化**。结论一句话——**推理任务因 disrupted CoT links（关系链断裂）在激进压缩下严重退化**。

### 六大观察（论据，本报告命题的实证基础）

| # | 观察 | 数据 | 对关系压缩的含义 |
|---|------|------|----------------|
| O1 | **Task-Dependent Degradation** | 算术推理在 <20% 压缩比下精度从 0.75 跌到 <0.5 | 关系密集任务最脆弱 |
| O2 | **Model-Type Robustness** | R1 蒸馏模型在 10% 压缩比仍保 0.60；instruct 模型跌到 0.5 | reasoning 模型有特殊 attention 模式 |
| O3 | **Prompt Length Vulnerability** | 1-shot 从 0.5 跌到 0.05；8-shot 仅 0.75→0.5 | 短上下文更依赖每条关系 |
| O4 | **Chunk-Level Superiority** | ChunkKV 在 <10% 时最稳 | 关系应以"语义单元"而非单 token 保留 |
| O5 | **Prompt-Gain Sensitivity** | 算术 CoT 增益 +50.41%（vs 知识 +6.20%），增益越大越敏感 | CoT 依赖度 = 关系依赖度 |
| O6 | **Long-Context Generation Sensitivity** | 长上下文生成对压缩极度敏感 | 生成阶段关系更脆 |

### Attention 机制分析（为何关系任务脆弱）

- 含 sink token 时：top 1% token 占 60% attention（sink 主导，任务无关）
- **去掉 sink token 后**：算术任务的 non-sink attention **更弥散**（依赖更广的上下文线索）→ 压缩一旦影响这些 non-sink token，推理即崩
- 这从 attention 分布角度解释了"为何关系推理对压缩敏感"

### ShotKV 方法（命题的操作化，作者自述"非算法创新"）

- **核心 insight**：把 few-shot 示例作为**不可分割的语义单元（Semantic Unit）**保留
- **实现**：显式分离 prefill 与 decoding 两阶段——prefill 用 chunk 式语义单元保留，decoding 用动态压缩
- **结果**：长上下文生成 **+9%~18%** 精度，泛化到文档 QA，端到端延迟 **-11%**

### 对关系压缩课题的启示

- ⭐ **命题背书**：ICML 评审接受"disrupted CoT links"作为退化主因 → 本报告"关系边断裂"从推导升级为**共识**
- ✅ O4（chunk-level 优于 token-level）直接支持课题一的**桥接中心性按"关系簇"而非单 token 决策**
- ✅ O5（CoT 增益越大越敏感）量化了"关系依赖度"，可作为关系压缩的**任务筛选标准**
- ⚠️ **局限**（作者自陈 §6）：仅限 few-shot ICL 结构；scoring 是启发式；对 prompt 结构有依赖。**未引入显式关系图**——仍是课题一的空白机会

## 3. ThinKV: Thought-Adaptive KV Cache Compression（ICLR 2026 Oral）

| 属性 | 值 |
|------|-----|
| **arXiv** | [2510.01290](https://arxiv.org/abs/2510.01290)（v2, 2026-05） |
| **会议** | **ICLR 2026 Oral** |
| **作者** | Akshat Ramachandran, Tushar Krishna(Georgia Tech) + **NVIDIA Research** |
| **定位** | "思维类型关系"维度；课题二（推理链阶段压缩）的直接对标 |

### 核心贡献

提出 **thought-adaptive** 混合量化-驱逐框架。核心洞察：CoT 可按 attention 稀疏度分解为不同**思维类型（thought type）**，其重要性差异显著。这是首个把"推理链语义结构"作为压缩粒度的工作。

### 思维分解（关系结构建模）

- **三模态**：attention 稀疏呈现三峰分布 → 三类思维 **𝒯 = {R, E, T}**
  - **R（reasoning）**：系统思考，中等稀疏
  - **E（execution）**：计算/代码生成，最低稀疏（强依赖上下文）
  - **T（transition）**：不确定性/回溯，**最高稀疏**
- **重要性层级**（反事实 KL 散度，50 次 rollout）：**R >> E >> T**
- **关键发现**：异常的 T 思维（回溯）极其关键——移除会导致**模型无限循环**（呼应 VaSE 的"重复推理循环"灾难性失效）
- **思维关联**：每次 T 思维出现，此前所有思维段影响力递减（T 改变推理轨迹）

### 方法（算法-系统协同设计）

**① Think Before you Quantize (TBQ)——思维自适应量化**
```
ρ(R)=2 → 8-bit(FP8)    ρ(E)=1 → 4-bit(NVFP4)    ρ(T)=0 → 2-bit(ternary)
（实测 R 在 4-bit 仍无损 → 实践用 R/E=4-bit, T=2-bit）
```

**② Think Before you Evict (TBE)——思维自适应驱逐**
- T 思维 = 轨迹改变点，触发对前置思维段的**渐进式驱逐**
- 保留调度 ℛ = {64,32,16,8,4}（每次 T 出现，前置段降一级，最少留 4 token）
- 用 **K-means 聚类 post-RoPE key** 选保留代表（K=保留数）

**③ Continuous Thinking (CT) kernel——系统创新**
- 扩展 PagedAttention，**原地复用被驱逐的内存槽**，避免 gather compaction
- 论文实测：R-KV 的 gather-based compaction 在大 batch 下 **TPOT 慢化达 37×**；CT 消除该开销

### 关键公式与结果

```
显存：Mem(KV) ∝ (I + b·L_gen) × a·β
  a∈[0,1] 量化缩减，b∈[0,1] 驱逐缩减
关键发现：纯量化会膨胀 L_gen（生成长度）→ 抵消显存节省
         量化+驱逐混合（ThinKV）= Pareto 最优前沿
```

| 指标 | ThinKV | 对比 |
|------|--------|------|
| KV 占用 | **<5%** 全量 | 近无损 |
| 吞吐 | **5.8×** | vs SoTA |
| TPOT | **1.68× 更低** | vs R-KV |
| 显存占用 | **2.51%**（vs R-KV 5.48%） | CT 原地复用 |

模型：DeepSeek-R1-Distill(8B/70B/Qwen14B)、GPT-OSS(20B/120B)、QwQ-32B、AceReason-Nemotron-14B；基准：MATH-500、AIME、GSM8K、LiveCodeBench。

### 对关系压缩课题的启示

- ✅ **思维类型 R/E/T 是推理链的关系结构**，直接验证课题二"按推理阶段差异化压缩"的可行性（课题二原设计 Planning/Tool/Verify/Reflection 四阶段，ThinKV 的 R/E/T 是其工业级简化版）
- ✅ **T 思维 = 关系轨迹改变点**，是课题一"桥接中心性"在时序上的对应物——未来重要性预测应锚定 T 点
- ✅ CT kernel 的 37× 慢化教训：**关系压缩的工程实现必须避免 gather compaction**，应走 PagedAttention 原地复用路线（课题一的 Runtime 设计约束）
- ⚠️ **局限**：思维分类靠 attention 稀疏近似 ϕ（非精确）；固定 |𝒯|=3；仍是"思维粒度"而非"实体-关系图粒度"——未统一多个关系维度

## 三篇对比：关系维度正交，无人统一

| 维度 | R-KV | ShotKV | ThinKV |
|------|------|--------|--------|
| 利用的关系 | token-token 冗余（相似） | CoT 链路（语义单元） | 思维类型（R/E/T） |
| 信号 | cosine 相似度 | few-shot 结构 | attention 稀疏三模态 |
| 决策粒度 | token | chunk/语义单元 | thought 段 |
| 压缩手段 | 驱逐（λ=0.1 重冗余） | prefill+decoding 分离 | 量化+驱逐混合 |
| 关系图 | ✗ 隐式 | ✗ 隐式 | ✗ 隐式 |
| 工程创新 | GQA importance | — | CT kernel（避免 gather） |

> **战略结论**：三篇各自抓住一个关系面（冗余/链路/思维），**但都没有用统一的实体-关系图**。这印证了洞察报告的核心课题定位——**课题一"关系图 KV 压缩"的价值，在于把这三个正交维度收进一张图，用桥接中心性等图论指标统一决策**。单点创新窗口（做第 4 个维度）已关闭，统一整合是下一个价值高地。
