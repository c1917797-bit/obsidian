# 报告分级标准

> 版本: v1.0 | 更新: 2026-06-28
> 用途: 根据决策重要性选择不同"重量"的报告，避免过度工程化
> 配套: AI课题技术规划报告_主模板.md + 洞察写作指南.md v1.4

---

## 一、为什么需要分级

完整版方法论（7 要素 + 19 维度 + 五看三定 + 反方证据）适合**年度/季度战略报告**，但不适合日常快速决策。如果所有报告都走全流程，一个 3 人团队一个季度只能写 1 份。

**原则：报告重量匹配决策重量。**

---

## 二、三级标准

### 完整版（战略级）

| 项目 | 内容 |
|------|------|
| **适用场景** | 年度规划 / 季度课题立项 / 新方向启动 / 高管决策 |
| **决策金额** | >¥100,000 或 >10 GPU×月 |
| **读者** | CTO / VP / 课题负责人 |
| **产出** | 30-60 页完整报告 |
| **章节** | §0-§4 全部 + 红蓝对抗 12+ 个 |
| **洞察要素** | 7 要素全满足 |
| **五看** | 全部 5 看 |
| **红蓝对抗** | 10 核心 + ≥2 扩展 = ≥12 个 |
| **撰写周期** | 1-2 周 |
| **模板** | AI课题技术规划报告_主模板.md v1.3（完整版） |

### 精简版（战术级）

| 项目 | 内容 |
|------|------|
| **适用场景** | 月度方向调整 / 单课题可行性评估 / 中层决策 |
| **决策金额** | ¥10,000-100,000 或 2-10 GPU×月 |
| **读者** | 技术经理 / 课题负责人 |
| **产出** | 5-10 页精简报告 |
| **章节** | §0 一页纸 + §1 洞察（精简）+ §2.2 得分 + §3.1-3.3 课题 + §3.7 红蓝 |
| **洞察要素** | 3 要素（反直觉 + 业界案例≥1 + 行动） |
| **五看** | 选 2 看（看竞争 + 看机会） |
| **红蓝对抗** | 5 核心（技术替代性 + 安全风险 + ROI + 竞争壁垒 + 框架vs自研） |
| **撰写周期** | 1-2 天 |
| **模板** | 主模板精简版（去掉 §1.2-1.3, §3.4-3.6） |

### 闪电版（日常级）

| 项目 | 内容 |
|------|------|
| **适用场景** | 日常技术选型 / 论文评估 / 快速 Go/No-Go |
| **决策金额** | <¥10,000 或 <2 GPU×月 |
| **读者** | 工程师 / 自用决策 |
| **产出** | 1 页（≤500 字） |
| **格式** | 见下方模板 |
| **撰写周期** | 30 分钟 |

---

## 三、闪电版模板

```markdown
# [方向名] 快速评估

**结论**: [一句话 Go/No-Go + 理由]

**业界**: [1 个具体业界案例 — 谁在做+效果]
  例: DeepSeek-V3 用 FP8 把 API 成本降到 $0.27/1M

**最大风险**: [1 个风险 + 失效保险]
  例: INT4 对齐崩溃 → 降级 FP8

**下一步**: [1 个具体动作]
  例: Q3 W2 复现 AWQ 在 Qwen-72B 上的 MMLU
```

## 四、选择决策树

```
决策金额 > ¥100K？
  ├── 是 → 完整版（1-2 周）
  └── 否 → 决策金额 > ¥10K？
            ├── 是 → 精简版（1-2 天）
            └── 否 → 闪电版（30 分钟）
```

**简化规则**：宁可降级不要升级。先用闪电版快速判断，如果发现"需要深入"再升级到精简版或完整版。
