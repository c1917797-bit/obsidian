# 工作区协作约定

## 分工

- Obsidian 保存经确认的长期笔记、双链、标签与项目上下文。
- Agent 工作区负责抓取、解析、研究、生成与质量检查。
- 工作过程中的图片、下载代码、解析文件、日志与导出物默认保留在工作区 `.tmp/`，避免把大体积临时文件写入知识库。

## 交付流程

1. 在 Codex 中提出任务，注明要沉淀的知识层。
2. Agent 把过程产物保存在工作区 `.tmp/`。
3. 未分类的 Markdown 结论先交付到 [[0_Codex工作台/Inbox/收件箱说明|Codex Inbox]]。
4. 人工确认后，按 [[📋_目录导航]] 归档到溯源、织网、日历、洞察或学术研究层。

## 可直接使用的任务模板

### 网页 / 报告整理

> 抓取并整理这份材料。过程产物放工作区 `.tmp/`；最终创建一篇带来源链接、Codex 分析和待验证问题的 Obsidian 笔记，先放入 `0_Codex工作台/Inbox/`。

### 论文分析

> 解析这篇论文。结构化 XML、图表和中间文件放工作区 `.tmp/`；最终把论文摘要、方法、证据、局限与相关双链整理为笔记，先放入 `0_Codex工作台/Inbox/`。

### 技术洞察与 PPT

> 基于指定 Obsidian 笔记形成技术洞察。研究与 PPT 过程产物放工作区 `.tmp/`；将可复用的核心观点、证据链接和开放问题回写为一篇 Inbox 笔记，待确认后归档到 `4_AI情报洞察/`。

## 归档原则

- 来源事实、Codex 分析和开放问题分区书写。
- 新增笔记保留 UTF-8、frontmatter、标签和 `[[wikilinks]]`。
- 未经明确确认，不批量移动、重命名或改写已有笔记。

## 从 Agent 工作区复用的工程化做法

- **临时与正式分离**：下载、解析、截图、日志和草稿只放在 AgentWorkspace 的 `.tmp/runs/<run-id>/`；Obsidian 只接收确认后的 Markdown、索引和必要证据。
- **证据链优先**：每条结论至少记录来源、访问日期、证据位置和待验证问题；不要把截图或模型猜测当作事实。
- **先 Inbox 后归档**：新内容先进入 Inbox，完成标题、frontmatter、来源和双链检查后，再由人确认归档。
- **质量门禁**：提交前运行 `obsidian-loop-quality.ps1 quality`，检查 frontmatter、标题、重复笔记和疑似敏感信息；失败时先修复，不推送。
- **可恢复运行**：长任务按 run-id 保存状态与报告，允许中断后从 checkpoint 继续，避免重复抓取和重复改写。
- **安全边界**：令牌、密码、私钥、内部地址和运行时凭据不进入 Obsidian 或 Git；需要连接外部系统时使用环境变量或安全凭据管理。
