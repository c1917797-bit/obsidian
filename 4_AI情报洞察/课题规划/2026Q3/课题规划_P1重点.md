# 课题九：KIVI 工业级部署与 vLLM 集成

**业务约束（业务驱动方法）**：
- Q1：✅ 多卡 MoE（128K+ KV 是核心瓶颈）
- Q2：✅ 128K-1M 长上下文
- Q3：✅ TTFT 降低（KV 减少降低首字延迟）
- Q4：✅ 高并发
- Q5：≤1% 精度损失
- Q6：✅ 任意 RoPE 模型
- **约束过滤**：K 必要 + 长上下文强需求

**关键挑战**：KIVI (ICLR 2024) 提出了**非对称粒度量化**（Key per-channel + Value per-token），2-bit 量化是 LLM KV 压缩的基准方案。但工业落地面临三大挑战：
1. 与 vLLM PagedAttention 内存布局不兼容
2. 反量化 kernel 在长上下文下访存开销大
3. 缺乏跨 batch 的统一量化策略

**技术目标**（引用目标.md 公式）：

- vLLM 主线 PR 合并（KIVI 算子）
- KV 显存减少 **2-4x**（FP16 → INT2）
- TTFT 降低 **15-25%**（公式四：TTFT = (S_input × T_calc + T_comm) × (1 - η) + T_queue × (1 - λ)）
- C_max 提升 **30-50%**（公式二：C_max = min(C_V, C_gpu, C_comm)）
- 模型精度损失 ≤ **1%**（PPL 增长）

**关键技术**：

1. **vLLM PagedAttention 兼容的 KIVI 算子（框架级落地）**
   KIVI 原实现基于连续内存；vLLM 的 PagedAttention 是分页管理；需要设计**分页感知的非对称量化算子**，将量化粒度与 KV block 对齐。

2. **反量化访存优化（性能提升）**
   长上下文下反量化开销不容忽视；设计**L2 cache 友好的反量化 kernel**，将反量化结果缓存在 L2 cache，避免重复计算。

3. **跨 batch 统一量化策略（精度保持）**
   同一 prompt 多个 batch 请求共享 KV，需要统一量化尺度（scale）；设计**batch-aware 量化校准**，降低 batch 间的精度方差。

**对象×方法**：K × Q（KV × 量化）

**综合得分**（技术驱动方法评分卡）：
- 技术深度：2/3（KIVI 已成熟，工程创新为主）
- 工程影响：3/3（vLLM 集成是工业级落地）
- 趋势强度：2/2（KV 量化是 2026 主流）
- 行业影响：2/2（所有 LLM 受益）
- **综合得分：2×3×2×2 = 24 → 8分**（进入战略分析）

**代码状态**：⚠️ 部分（KIVI 原代码已开源，vLLM 集成需自研）

**与产品的交集**：
- 直接集成到 vLLM/SGLang
- 减少 50-75% KV 显存
- 适合所有 RoPE 模型

# 课题十：HyperQuant 1.7bps 极限量化

**业务约束**：
- Q1：✅ 多卡
- Q2：✅ 128K+ 长上下文
- Q5：≤1% 精度损失
- Q6：✅ 任意模型
- **约束过滤**：K 必要 + 极限压缩是热点

**关键挑战**：HyperQuant (2026) 实现了 **KV 1.7bps 极限量化**（每 token 1.7 比特），是当前 KV 压缩的极限水平。核心技术是 **Hadamard 变换 + 最优格量化 + Rice 编码**的统一流水线。但工业落地面临：
1. 1.7bps 的精度损失边界需要严格评估
2. Hadamard 矩阵的硬件友好性需要优化
3. Rice 编码的解码延迟在长序列下累积

**技术目标**：

- KV 比特降至 **1.7-2.5bps**（极限压缩）
- 在 7B 模型上 PPL 损失 ≤ **1%**
- H100 上 4bps 实现 **3.79x 压缩**
- 与 vLLM 集成

**关键技术**：

1. **任务感知极限压缩（数学/代码不适用）**
   1.7bps 不适合数学/代码任务（需要更多精度）；设计**任务感知的比特预算分配**，数学任务用 4bps，对话用 1.7bps。

2. **Hadamard 矩阵硬件友好化（性能）**
   Hadamard 变换的快速算法（FWHT）在 GPU 上延迟高；设计**硬件感知 Hadamard kernel**，减少 SM 间通信。

3. **Rice 编码流水线优化（解码延迟）**
   长序列下 Rice 解码累积延迟显著；设计**SIMD 加速的 Rice 解码 kernel**，与 GPU 解码流水线融合。

**对象×方法**：K × Q（KV × 量化）

**综合得分**：
- 技术深度：3/3（Hadamard + 格量化 + 编码的组合创新）
- 工程影响：2/3（极限压缩，工业落地少）
- 趋势强度：2/2（极限压缩是热点）
- 行业影响：2/2（对话/摘要场景受益）
- **综合得分：3×2×2×2 = 24 → 9分**

**代码状态**：❌ 无（全新实现）

**与产品的交集**：
- 适合对话/摘要场景
- KV 显存减少 8-16x
- 极限压缩场景

# 课题十四：视频帧 KV 全程压缩

**业务约束**：
- C1（模态类型）：✅ 视频
- C2（输入模态）：✅ 1-3 模态
- C3（实时 vs 离线）：✅ 70% 实时
- C4（分辨率）：✅ 720p 起步
- C5（融合时机）：✅ 早期融合
- **约束过滤**：M 必要 + 视频场景核心

**关键挑战**：1 分钟视频 = **150K token**（每秒 25 帧 × 6000 tokens/帧），KV 累积远超图像。视频帧间存在 **90%+ 冗余**。但现有方案只关注编码或解码单阶段，**全程联合压缩是空白**。

**技术目标**：

- 视频 KV 压缩比 **10-50x**
- VideoMME 准确率损失 ≤ **3%**
- 视频 TTFT 降低 **50%**
- 支持 1 小时长视频

**关键技术**：

1. **视频帧间 KV 共享（前后帧复用）**
