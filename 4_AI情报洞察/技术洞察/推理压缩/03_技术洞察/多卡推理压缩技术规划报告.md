# 第一篇：洞察——五个被忽视的关键发现

## 洞察一：B与TPOT的对偶关系是所有压缩技术的核心约束

**问题**：大多数KV压缩技术规划只关注"压缩能带来什么收益"，但没有计算"压缩本身要付出什么代价"。

```
M_KV压缩的直接收益：
  M_KV↓ → B↑ → TPS↑

M_KV压缩的间接代价：
  压缩/解压操作引入额外计算
  → TPOT↑
  → 部分抵消B↑的收益
```

**对偶关系的数学表达**：

```
TPS = C / TPOT
    = C / (T_calc + S × T_mem + T_comm)

M_KV压缩后：
  M_KV_new = M_KV × α（α < 1，压缩比）
  B_new = B / α

  但TPOT可能增加：
  TPOT_new = TPOT × β（β > 1，压缩开销因子）

  净吞吐变化：
  TPS_new / TPS = (B/α) / (TPOT × β) = (B/TPOT) / (α × β)
```

**关键结论**：只有当α × β < 1时，压缩才是合算的。

```
三种压缩手段的对偶关系分析：

量化（Bit↓）：
  α = 0.5（INT4 vs FP16）
  β ≈ 1.0（解压开销可忽略）
  → α × β ≈ 0.5 < 1 ✅ 最干净

剪枝（S↓）：
  α = 0.125（8倍压缩）
  β > 1.0（重计算开销）
  → α × β ? 需要验证 ⚠️

跨请求缓存：
  α ≈ 0（命中时跳过计算）
  β < 1.0（无压缩开销）
  → α × β ≈ 0 ✅ 免费午餐
```

**实践意义**：不是所有压缩技术都是"免费的午餐"。Bit量化是最干净的手段，剪枝需要验证对偶关系，跨请求缓存是唯一真正的免费午餐。

## 洞察二：三个目标不是独立的，而是乘积关系

**目标体系**：

```
① 推理时延：1.5×加速
  → TTFT + (N_out - 1) × TPOT 整体降低33%

② 系统吞吐：2×提升
  → TPS = C / TPOT

③ 模型精度：损失 ≤ 1%
  → 约束所有优化方向的上限
```

**乘积关系的推导**：

```
2×吞吐提升不能靠单一优化实现，必须多路径叠加：

Bit量化（课题一）→ B↑ 2×
MoE通信压缩（课题三）→ TPOT↓ 1.33×
跨请求缓存（课题五）→ 命中时B↑ 1.3×

多课题叠加：
  课题一 × 课题三 × 课题五 ≈ 2× × 1.33× × 1.3× ≈ 3.5× > 2× ✅

课题六（A-FFN联合）间接贡献：
  TTFT↓ → 整体时延1.5×（目标①的一部分）
  与B和TPOT完全正交，可并行推进
```

**关键结论**：不同维度的优化乘积叠加，而非单一维度的线性累加。选择课题时，应优先选择彼此正交（不产生对偶冲突）的方向。

## 洞察三：S在TTFT和TPOT中含义不同

**被忽视的细节**：S在端到端推理的两个公式中代表不同的物理量。

```
TTFT公式中的S：
  S = S_input（输入序列长度）
  → 用于计算Prefill阶段的计算量
  → TTFT = S_input × T_calc_ffn + T_comm

TPOT公式中的S：
  S = S_kv（当前KV缓存长度）
  → S_kv = S_input + 已生成的token数
  → 在生成过程中不断增长

Decode第t步时：
  S_kv(t) = S_input + t - 1

因此TPOT不是恒定值，而是随生成过程增长：
  TPOT(1) < TPOT(10) < TPOT(100)
```

**对规划的影响**：

```
① TPS = C / TPOT是近似值（用均值或P99代表）
② B = (M_total - M_weights) / M_KV中的S是当前长度
③ 压缩技术对TTFT和TPOT的影响需要分开评估
```

**关键结论**：评估KV压缩技术时，不能只看B↑，还要看TPOT的变化。纯缓存（命中时跳过计算）对TTFT和TPOT都友好，是最优方向。

## 洞察四：MoE通信压缩是唯一直接降低TPOT且不影响B的方向

**T_comm优化的独特价值**：

```
T_comm优化的三个独特属性：
  ① 直接降低TPOT → TPS↑（直接）
  ② 不影响M_KV → B不变（无副作用）
  ③ 与Bit/S压缩正交，可叠加

三个独立因子：
  T_comm = 交换次数 × 字节数/次 × Expert参与量

核心问题（未被显式解决）：
  量化噪声导致top-k Expert排名翻转
  → Expert_7（量化前top-1）变成Expert_3（量化后top-1）
  → 路由错误 → 模型输出质量下降
```

**与Bit量化的对比**：

```
Bit量化：
  直接：B↑
  间接：TPOT可能↑（解压开销）
  对偶关系：存在但可控

T_comm压缩：
  直接：TPOT↓
  间接：B不变
  对偶关系：不存在 ✅
```

**关键结论**：MoE通信压缩是唯一"纯粹"的TPOT↓手段，不引入对偶关系，是所有课题中最干净的方向之一。

### 证据实例：MoE 通信机理与 Rank-Aware 失效案例

**① MoE All-to-All 通信机理走查（为何"传不快"）**

MoE 每个 token 只激活少数专家(如 DeepSeek-V3 的 top-8/256)，但专家分布在多卡上，每层都要做两次 All-to-All：
```
每层每步:
  ① Gate 计算路由: token → top-k 专家
  ② All-to-All dispatch: token 发到专家所在卡   ← 跨卡通信
  ③ 专家计算: 各卡并行算激活专家                ← 计算
  ④ All-to-All combine: 结果发回原卡            ← 跨卡通信
  ⑤ 拼接输出
通信量 ∝ token数 × hidden_dim × 跨卡次数
```

**② 1:1 计算通信比的算术强度推导**
```
算力 vs 互联带宽(NVLink ~900GB/s, H100 ~990TFLOPS):
  算术强度门槛 = 990e12 / 900e9 ≈ 1100 FLOP/byte
  MoE 单 token 计算强度 < 门槛 → 通信时间 ≈ 计算时间 → 1:1
→ 卡越多，跨卡通信占比越高，加卡红利被 All-to-All 吃掉
→ 这就是"压流量(减字节/次数)"比"加带宽"更本质的原因
```

**③ Rank-Aware top-k 翻转的具体失效案例**
```
量化前(FP16) Gate 分数排序:
  Expert_7(0.91) > Expert_3(0.88) > ... > Expert_8(0.71) > Expert_2(0.70)
  top-8 = {..., 8}        ← Expert_8 入选，Expert_2 落选

FP8/INT4 量化后(通信字节↓)，噪声扰动:
  ... > Expert_2(0.72) > Expert_8(0.69)
  top-8 = {..., 2}        ← Expert_2 翻转入选，Expert_8 被挤出

机理: Gate 分数在 top-k 边界附近密集(0.71 vs 0.70，差 0.01)
      量化噪声(~0.02)足以翻转排名 → 路由到错误专家
后果: 激活错误知识 → 输出质量下降；每层翻转概率累积 → 困惑度显著上升
空白: 现有方法(ExpertQuant/ASAP)只压字节，从不显式约束排名稳定
      → Jaccard(量化前后 top-k) < 0.9 时已显著翻转，但无工作把此约束写进损失
```
> **证据含义**：①②证明 MoE 通信是结构性瓶颈（非加带宽可解）；③证明"压字节"会引入"路由错误"这个新代价——这正是 Rank-Aware Jaccard Loss（显式约束排名稳定）的机会，也论证了"压流量必须保路由正确"。

## 洞察五：VLM视觉压缩是独立战场，与文本KV压缩正交

**VLM的特殊性**：

```
VLM视觉token的冗余来源与文本完全不同：

文本KV：
  冗余来源：attention模式稀疏
  压缩依据：attention score

视觉token：
  冗余来源：空间相邻patch像素重复
  压缩依据：CLIP特征相似度

典型数据：
  一张224×224图片 → 576个visual token
  4张图 → 2304个visual token
  总S = 1K文本 + 2.3K视觉 = 3.3K
  视觉占S的70%

这是LLM不存在的独特问题，必须独立研究。
```

**VLM的第二个独特性：跨请求复用模式**

```
vLLM RadixAttention的局限：
  → 只能识别精确的文本前缀匹配
  → 无法识别"同一图片+不同问题"

新缓存维度：
  图片语义指纹 = CLIP embedding → LSH hash
  作为独立于文本前缀的缓存键

命中时：
  → 跳过图像ViT编码（TTFT↓）
  → 跳过图像self-attention KV计算
  → 只重新计算cross-attention
```

**关键结论**：VLM视觉压缩和文本KV压缩是"两场不同的战争"，方法论和技术方案都不能直接迁移。

## 课题一：Head-wise敏感度自适应的KV混合精度量化

### 背景与问题

```
M_KV = 2 × L × H × D × (Bit/8) × S

Bit量化的独特价值：
  Bit只影响M_KV（→B↑）
  不影响TPOT_wo_M_KV（量化在显存层，解压后计算方式不变）

这是与S剪枝的本质区别：
  S剪枝：减少计算量 → 可能增加TPOT↑（重计算开销）
  Bit量化：减少存储量 → 对TPOT计算几乎无影响

因此：Bit量化是最"干净"的B↑手段
```

### 技术方案

```
① Head-wise敏感度分析（离线标定）
   梯度敏感度：loss对各head KV量化误差的梯度
   Attention方差：高方差=聚集型=h敏感，低方差=分散型=l敏感
   联合评分 → head敏感度排序表

② RoPE频域感知量化（在线执行）
   低频分量（前d/2维度）→ INT4
   高频分量（后d/2维度）→ INT2

③ 多轮感知精度补偿
   前序轮次 → INT4（精度优先）
   当前轮次 → INT2（容量优先）
```

### 关键假设

| 假设 | 验证方法 | 通过标准 |
|------|---------|---------|
| H1：Head-wise敏感度差异显著 | 梯度敏感度+attention方差分析 | top/bottom差异>5% |
| H2：INT2 perplexity损失<1% | LongBench测试 | <1% |
| H3：RoPE频域分块有效 | 低频INT4 vs 全INT4 | 差异>0.3 |

### 目标指标

```
M_KV↓：Bit从16→4（INT4），局部INT2面积30%
B↑：2×（理论），验证>1.5×
精度：LongBench perplexity损失<1%
```

## 课题二：蒸馏信号感知的KV动态剪枝与B↑-TPOT↑对偶关系验证

### 背景与问题

```
现有KV剪枝方法的问题：
  H2O/SnapKV/LazyLLM：依赖离散的importance score
  无法捕捉token之间的语义关联强度

蒸馏的核心价值（Hinton 2015）：
  Soft label包含类别之间的相对距离
  比hard label更丰富

迁移到KV压缩：
  Teacher = 完整KV的attention分布
  Student = 压缩后KV的attention分布
  Loss = KL(Student || Teacher)

→ 每个token的"蒸馏重要性分数"比attention score多包含"语义关联"信息
```

### 技术方案

```
① 蒸馏信号提取（Prefill，一次性）
   Teacher = 完整KV attention分布
   计算每个token的KL贡献度
   → 蒸馏重要性分数

② 语义等效token识别
   相邻token embedding cosine相似度>0.9
   → 识别为可合并的语义等效组
   → 组内仅保留attention score最高的token的KV

③ B↑-TPOT↑对偶关系验证（核心）
   每N步评估：
     B提升比例 = 1/压缩比
     TPOT开销比例 = 测量值
   净收益 = B↑ / TPOT↑

   决策：
     净收益>2 → 继续压缩
     净收益<1 → 触发失效保险
```

### 关键假设

| 假设 | 验证方法 | 通过标准 |
|------|---------|---------|
| H1：蒸馏信号与attention score互补 | Pearson相关系数 | <0.7 |
| H2：在线蒸馏开销<Prefill 5% | 实测额外延迟 | <5% |
| H3：B↑收益>TPOT↑开销 | 计算净收益 | >2 |

### 目标指标

```
S↓：128K→16K（8×压缩，验证3×保底）
B↑：验证>1.5×
TPOT↑：<20%（失效保险：>50%则终止）
精度：LongBench损失<1%
净收益：>2×
```

### 失效保险

```
触发：净收益<1
动作：终止S剪枝方向
备选：以课题一（Bit量化）为主要B↑手段
```

## 课题三：Rank-Aware MoE通信量化

### 背景与问题

```
T_comm优化的独特价值：
  ① 直接降低TPOT → TPS↑（直接）
  ② 不影响M_KV → B不变（无副作用）
  ③ 与Bit/S压缩正交，可叠加

核心问题（未被显式解决）：
  量化噪声导致top-k Expert排名翻转
  → Expert_7（量化前top-1）变成Expert_3（量化后top-1）
  → 路由错误 → 模型输出质量下降

Rank-Aware Jaccard Loss：
  L = L_routing + λ × L_jaccard
  L_jaccard = max(0, 0.9 - Jaccard(top-k_pre, top-k_post))
```

### 技术方案

```
① Top-k排名稳定性分析（离线）
   在测试集上统计：
     量化前top-k Expert集合
     量化后top-k Expert集合
     Jaccard相似度

② Rank-Aware量化（训练/微调时引入）
   Top-k Expert → FP8（高保真）
   组内非top-k → INT4
   组外 → 跳过

③ 三步流水线（工程集成）
   Step 1：低频Expert跳过（减少参与量）
   Step 2：协作约束路由（减少交换次数）
   Step 3：Rank-Aware量化（减少字节数）
```

### 关键假设

| 假设 | 验证方法 | 通过标准 |
|------|---------|---------|
| H1：Jaccard(top-k)<0.9 | 实测量化前后相似度 | <0.9 |
| H2：Rank-Aware perplexity损失<0.5% | 对比有无约束 | <0.5% |
| H3：三步流水线TPOT↑<10% | 实测总延迟 | <10% |

### 目标指标

```
T_comm↓：30-50%（三步叠加）
TPOT↓：15-25%
B：不变（无副作用）
精度：perplexity损失<1%
```

### 失效保险

```
触发：Rank-Aware perplexity损失>1%
动作：去掉Rank-Aware，保留协作路由和跳过
```

## 课题四：空间语义双维度协同的视觉KV压缩

### 背景与问题

```
VLM视觉token的冗余来源与文本完全不同：

文本KV：
  冗余来源：attention模式稀疏
  压缩依据：attention score

视觉token：
  冗余来源：空间相邻patch像素重复
  压缩依据：CLIP特征相似度

典型数据：
  一张224×224图片 → 576个visual token
  4张图 → 2304个visual token（占S的70%+）
```

### 技术方案

```
① 空间聚类（Prefill，一次性）
   ViT编码后576 token
   CLIP embedding → K-means空间聚类
   相邻patch被自动合并到同一语义簇

② Attention筛选（Prefill）
   各簇与query的cross-attention
   高关联 → 保留完整KV
   低关联 → INT4压缩

③ 空间-语义双维度协同
   空间维度：相邻patch像素相似度
   语义维度：簇与query的cross-attention
   两者正交 → 高空间冗余×高语义相关 = 优先压缩计算
```

### 关键假设

| 假设 | 验证方法 | 通过标准 |
|------|---------|---------|
| H1：相邻patch CLIP相似度>0.9 | 计算均值 | >0.9 |
| H2：空间聚类+attention互补性强 | Jaccard overlap | <0.85 |
| H3：VLM场景B↑净收益>1.5 | 计算B↑/TPOT↑ | >1.5 |

### 目标指标

```
视觉token压缩：50%+
S_visual↓：576→288
VLM场景吞吐：提升>1.5×
精度：多模态benchmark损失<2%
```

## 课题五：视觉语义指纹缓存

### 背景与问题

```
vLLM RadixAttention的局限：
  → 只能识别精确的文本前缀匹配
  → 无法识别"同一图片+不同问题"

新缓存维度：
  图片语义指纹 = CLIP embedding → LSH hash
  作为独立于文本前缀的缓存键

命中时：
  → 跳过图像ViT编码（TTFT↓）
  → 跳过图像self-attention KV计算
  → 只重新计算cross-attention

命中条件：
  文本前缀相同 + 图像指纹相同
```

### 技术方案

```
① 视觉语义指纹编码
   CLIP图像编码器 → 全图embedding
   局部敏感哈希（LSH）→ 128-bit指纹
   碰撞率<1%

② 双维度缓存索引
   缓存键 = 文本前缀hash + 图像指纹hash
   两套独立维护

③ 跨模态复用策略
   命中：图像self-attention KV复用，只算cross-attention
   未命中：正常计算完整图像KV
```

### 关键假设

| 假设 | 验证方法 | 通过标准 |
|------|---------|---------|
| H1：指纹碰撞率<1% | 在图片集上测 | <1% |
| H2：同图不同问比例>30% | 统计数据集 | >30% |
| H3：命中时TTFT↓可覆盖未命中TPOT↑ | 计算期望值 | >0 |

### 目标指标

```
缓存命中率：>60%
TTFT↓：命中时35%+
吞吐提升：>1.3×
```

## 课题六：Attention-FFN联合重要性评估与选择性计算

### 背景与问题

```
FTP（ICLR 2025）的贡献：
  → 验证了FFN激活存在动态稀疏
  → 跳过FFN输出接近零的token

FTP的局限：
  → 只跳过FFN，不跳过KV
  → 单独优化FFN和单独优化attention都是局部最优

联合重要性评估的发现：
  Attention重要的token和FFN激活强的token往往不是同一批

  高attn + 高FFN → 全量计算
  高attn + 低FFN → 跳过FFN（保留attn）
  低attn + 高FFN → 保留FFN（跳过attn，罕见）
  低attn + 低FFN → 跳过两者
```

### 技术方案

```
① FFN激活模式分析（Prefill）
   实测FFN输出激活值分布
   识别激活值接近零的token

② Attention-FFN联合评估
   对每个token计算：
     attention_score
     ffn_activation
   建立2×2象限矩阵

③ 源头KV联动（可选扩展）
   FFN不重要 → KV大概率也不重要
   → 源头减少KV生成
   → 需要独立验证B和TPOT变化
```

### 关键假设

| 假设 | 验证方法 | 通过标准 |
|------|---------|---------|
| H1：attention和FFN重要性Jaccard<0.8 | 计算overlap | <0.8 |
| H2：A-FFN联合比单独FFN跳过TTFT↓更多 | 对比 | >10% |
| H3：源头KV联动不引入TPOT↑ | 测B和TPOT | TPOT↑<5% |

### 目标指标

```
TTFT↓：20-30%
Prefill计算量↓：35-40%
精度：≤1%
```
