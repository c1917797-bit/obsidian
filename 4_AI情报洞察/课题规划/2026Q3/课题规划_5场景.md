## 课题一：面向 Agent 语义驱动的 LLM 动态 KV 稀疏技术

**关键挑战**：Token 级 KV 存在大量语义冗余，相邻或相近 Token 产生重复表示。现有方法多依赖静态注意力分数或查询感知选择，前者缺乏对语义冗余的主动识别，后者受位置编码影响稳定性不足；普遍缺乏跨层语义一致性约束，Agent 长链路推理中关键上下文易被误删或发生语义漂移。

**技术目标**：在不显著损失模型效果的前提下（精度损失 ≤1%）：

- 端到端推理吞吐提升约 **40%–60%**
- 长上下文场景下推理时延降低约 **20%–30%**

**关键技术**：

1. **基于观测窗口的语义聚类压缩（Prefill 全局静态瘦身）**
   利用模型末尾观测窗口的注意力分布，识别每个注意力头高关注的语义簇，仅保留这些聚类对应的 KV，将存储粒度从 token 级压缩为语义单元级，从源头减少冗余。

2. **动态渐进式 Token 选择与恢复（Decode 动态自适应）**
   在每个生成步根据当前语义动态评估历史 Token 的重要性，对低贡献 Token 临时稀疏化；当后续步骤语义变化时，允许被稀疏 Token 重新参与计算，实现信息恢复，避免永久丢失。

3. **观测窗口锚定的跨层一致性约束（全链路精度兜底）**
   引入轻量一致性正则项，确保压缩后的语义单元在各 Attention 层传播中保持表征稳定，避免语义漂移，保障长上下文精度。

**可信性 & 创新点**：

- **参考论文**：
  - SnapKV (ICML 2024) — 观察窗口投票选 token
  - H2O (NeurIPS 2023) — Heavy-Hitter Oracle 累计 score
  - LazyLLM (ICML 2024) — 驱逐后按需恢复
  - TRIM-KV (2025) — 可学习保留分数
  - CacheBlend (2024) — 跨查询缓存混合
  - **Scholar Alert #3**：`KV cache compression offloading LLM long context`
- **可观测信号源**：

- **创新点**：

## 课题二：MoE 分布式推理通信量化压缩技术

**关键挑战**：MoE 模型（DeepSeek-V3/Qwen3-Max）每个 Token 仅激活少数专家（Top-2/Top-4），但需要 All-to-All 路由通信。在 128K 上下文 + 64 并发生产环境下，KV 已是权重的 4 倍（参见技术洞察 P2 定量证据），通信占比达 **40–60%**。现有方案"全复制所有专家"（用空间换通信）实际是低效的；专家参数量化是工业落地为零的全新方向（44 篇中 ExpertQuant 2025 是首个）。

**技术目标**：对 MoE 多卡推理场景：

- 跨卡 All-to-All 通信量降低 **50%–80%**
- 单 Token 推理时延降低 **25%–40%**
- 模型精度损失 ≤ **1%**

**关键技术**：

1. **专家参数 INT4 量化 + 动态精度切换（通信减量）**
   对 All-to-All 传输中的专家参数做 INT4 量化，结合 All-to-All 通信原语实现硬件级压缩；同时保留本地"影子副本"为关键专家提供 FP8/FP16 fallback。

2. **路由感知的稀疏通信（流量减负）**
   基于路由表预测哪些节点间通信最频繁（hot pair），仅对这些路径做 FP8 高频传输，其他路径保持 INT4 极低频传输。

3. **通信-计算重叠 + 量化协同调度（延迟隐藏）**
   将量化-通信-反量化流水化，与专家计算并行；同时通过算子融合减少 kernel launch 开销。

**可信性 & 创新点**：

- **参考论文**：
  - FoMoE (ICLR 2026) — 打破全复制范式，通信↓1.42-45x
  - ASAP (2026) — 异步解耦 Attention 和 MoE，prefill 吞吐↑90%
  - CloudMoE (OSDI 2026) — CPU-GPU 混合 + AVX-512 FP8
  - DeepEP (2024) — DeepSeek 通信库，INT4/FP8 生产级
  - MegaScale-MoE — 路由裁剪
  - **Scholar Alert #4**：`MoE communication optimization expert parallel LLM`

## 课题三：RoPE 频域感知的低比特 KV Cache 量化

**关键挑战**：所有主流 LLM（Llama/Qwen/DeepSeek）都使用 RoPE 旋转位置编码，但现有 KV 量化方法把 Key 当"普通向量"处理，**忽略了 RoPE 频域能量分布的极端不均**（不同频域块能量差异可达 10³ 倍）。均匀比特分配在数学推理任务上直接崩溃（AIME 2024 = 0 分）。Block-GTQ (2026) 首次揭示这一现象，K2V2 配置 AIME24 达 **51.7**（接近 FP16 的 54.2），但**框架集成（vLLM/SGLang）仍为空白**。

**技术目标**：

- KV 比特降至 **2-bit**（K2V2），AIME24 准确率 ≥ **50**
- vLLM / SGLang 主线 PR 合并
- 通用数学/代码任务精度损失 ≤ **2%**

**关键技术**：

1. **RoPE 频域分块 + 能量感知比特分配（基础方案）**
   将 KV 按 RoPE 频域块分组，每个块独立评估能量分布；高能量块分配 4-bit，低能量块可降至 1-bit；总平均 2.5-bit。

2. **任务感知比特预算分配（数学/代码/对话差异化）**
   推理类任务（数学/代码）对 RoPE 高频分量敏感，分配更多比特；对话类任务对全局上下文敏感，采用 RoPE-全频率均衡策略。

3. **框架级集成：vLLM/SGLang 算子融合（工程落地）**
   将频域分块 + 比特分配实现在 CUDA kernel 中，与 PagedAttention / RadixAttention 兼容；提供 Python API 供业务层调用。

**可信性 & 创新点**：

- **参考论文**：
  - Block-GTQ (2026) — RoPE 频域块自适应，AIME24 51.7
  - KIVI (ICLR 2024) — 非对称粒度

  - RotaryQuant (2025) — 旋转不变性
  - **Scholar Alert #3**：`KV cache compression offloading LLM long context`

## 课题四：Dustin 长上下文投机解码稀疏验证加速

**关键挑战**：长上下文（128K+）+ 投机解码场景下，**87.5% 的验证时间花在 KV 加载而非实际计算**（Dustin, ICML 2026）。验证阶段需加载完整 KV Cache，导致投机解码的加速比被严重削弱（理论上 10x，实际只有 2-3x）。现有方案仅在投机阶段优化，**验证阶段几乎无专用方案**。

**技术目标**：

- 验证阶段 self-attention 加速 **>20x**（Dustin 论文 27.85x）
- 投机接受率保持 ≥ **0.85**
- 端到端 TTFT 降低 **40%**

**关键技术**：

1. **验证阶段 KV 预取与缓存（I/O 减负）**
   验证阶段需要全部 KV，但其中 80% 与上一次投机阶段相同；将这些"热 KV"缓存在 L2 cache，验证时只加载"冷 KV"。

2. **稀疏验证策略（计算减负）**
   投机解码的"草稿 token"已通过小模型验证，**大模型验证时可只对预测最不确定的 token 加载完整 KV**，其他 token 用稀疏验证。

3. **分布式投机解码协同（多节点扩展）**
   在多节点部署下，验证阶段涉及跨节点 KV 通信；通过 gossip 协议同步热 KV，**减少跨节点通信量 50%**。

**可信性 & 创新点**：

## 课题五：VLM 视觉 Token 动态稀疏化与跨模态 KV 复用

**关键挑战**：VIT-22B 产生 **2570 个视觉 token**，远多于文本 token（典型对话 50-500）；视觉 token 间存在大量 2D 空间冗余；多模态融合时，视觉 KV 与文本 KV 的交叉注意力开销巨大。完全研究空白：现有 VLM 优化工作多关注视觉编码器，对 KV Cache 压缩几乎没有专门方案。

**技术目标**：

- 视觉 token 压缩比 **4-8x**（2570 → 320-640）
- VQA / 多模态 benchmark 准确率损失 ≤ **2%**
- VLM 推理 TPOT 降低 **40%**

**关键技术**：

1. **视觉 Token 重要性评分（基于文本 query 引导）**
   文本 query 与视觉 token 计算相关性，仅保留 Top-K 相关视觉 token；K=320 时保留 80% 信息。

2. **视觉 KV 与文本 KV 跨模态共享（融合机制）**
   视觉 token 的 KV 可被相邻视觉 token 共享（视觉 patch 相似性），文本与视觉共享注意力池（跨模态对齐）。

3. **VLM 专用 PagedAttention（框架级优化）**
   视觉 KV 的访存模式与文本 KV 完全不同（2D 局部性），需要 VLM 专用的 PagedAttention 算子，支持视觉 token 的动态插入/删除。

**可信性 & 创新点**：

- **参考论文**：
  - MemoTok (2026) — 视觉记忆 token 管理
  - SparseVLM (2025) — 视觉 token 动态稀疏

  - CrossFit (2025) — 跨模态注意力效率
  - LLaVA-1.5 / Qwen2-VL / InternVL3 — VLM 架构
- **可观测信号源**：

## 课题六：长时记忆向量量化压缩（Agent State Compression）

**关键挑战**：Agent 长时任务（小时/天级）需要持久化记忆。当前方案（MemGPT/Letta/Zep）使用原始 LLM 隐藏状态作为记忆，**每条记忆 1024-4096 维 FP16**（2-8KB/条），百万条记忆占用 2-8GB 内存。**检索时延随记忆规模线性增长**，10万条记忆 P99 检索时延 > 500ms。完全研究空白：现有记忆压缩工作多关注 KV Cache，没有 Agent 长期记忆专用方案。

**技术目标**：

- 记忆存储降低 **8-16x**（FP16 → INT2/INT4）
- 检索精度保持（Recall@10 ≥ 0.95）
- 检索时延降低 **40%**

**关键技术**：

1. **记忆向量 INT4/INT2 量化（存储减量）**
   将记忆向量量化为 INT4 编码，结合 Product Quantization (PQ) 进一步压缩；反量化仅在最终排序时执行。

2. **层次化记忆索引（检索加速）**
   将记忆按时间/主题分层，每层维护倒排索引；Top-K 检索时先在粗粒度层找候选，再在细粒度层精排。

3. **重要性感知压缩（精度保持）**
   高频访问记忆保持 FP16 全精度，低频记忆降至 INT2；通过访问模式动态迁移。

**可信性 & 创新点**：

## 课题七：Function Call Schema 语义压缩（Tool Call Overhead）

**关键挑战**：随着工具生态扩展（OpenAI 已支持 100+ 工具），Function Call 的 JSON schema 序列化是 LLM 推理的隐藏瓶颈。当工具数 > 50 时，**schema 序列化占 TTFT 30%+**（每次请求需传入完整 schema 列表）。完全研究空白：现有工作关注工具调用成功率，不关注 schema 本身的压缩。

**技术目标**：

- Schema 加载时间降低 **80%**
- TTFT 降低 **30%**（schema 加载是 TTFT 组成之一）
- 工具调用准确率保持不变

**关键技术**：

1. **Schema 选择性注入（按 query 注入相关工具）**
   使用轻量级意图分类器，按 query 预测需要的 Top-K 工具（K=5-10），仅注入这些工具的 schema。

2. **Schema 语义合并（功能相似工具合并）**
   对工具做语义聚类，将功能相似工具（如多个搜索引擎）合并为"工具族"，只暴露族级 schema，使用时再展开。

3. **Schema 模板缓存（增量复用）**
   将工具 schema 编译为模板（protobuf/二进制），增量更新而非全量加载；通过版本号管理兼容性。

**可信性 & 创新点**：

- **参考论文/项目**：
  - OpenAI Function Calling
  - Anthropic Skills

## 课题八：流式 ASR 音频编码器 INT4 感知压缩

**关键挑战**：实时 ASR（80% 业务场景）要求 0.5-1.5s 流式窗口，**音频编码器占推理时间 50%+**（Whisper-large 编码器 600M 参数）。现有 INT8 量化方案精度损失明显（WER↑2-3%），INT4 几乎无生产可用方案。Mel 频谱（80×3000）有大量频段冗余，但未有人专门研究。

**技术目标**：

- 音频编码器推理加速 **3-5x**
- WER 保持 < 5%（LibriSpeech test-clean）
- 流式延迟 < **500ms**（首字延迟）

**关键技术**：

1. **音频编码器 INT4 量化 + QAT 训练（精度保持）**
   对 Whisper Encoder 做 INT4 量化感知训练（QAT），恢复精度损失；同时设计针对音频特征的量化粒度（频段感知）。

2. **Mel 频谱稀疏化（输入减量）**
   音频 Mel 频谱存在大量低能量频段（人耳不敏感），可稀疏化；保留 64 个高能量 Mel 通道，去除 16 个低能量通道。

3. **流式 Chunk 注意力优化（延迟隐藏）**
   流式 ASR 使用 chunk 处理（0.5-1.5s），chunk 间注意力可稀疏化（远距离 chunk 不影响当前识别）；通过 attention mask 实现。

**可信性 & 创新点**：

- **参考论文/项目**：
  - Whisper (OpenAI) — 主流 ASR 模型
  - Zipformer (2024) — 音频编码器效率

## 课题九：TTS 声码器低秩分解与流式合成

**关键挑战**：TTS 实时合成要求 First Audio Latency < 300ms，**声码器（HiFi-GAN/Vocos）占推理时间 40%+**（HiFi-GAN-large 24M 参数）。多说话人场景（70% 业务需求）需要保持说话人特征，量化方案容易损失 MOS 分。流式 TTS 是 2026 爆发方向，但现有声码器不支持流式。

**技术目标**：

- 声码器推理时间降低 **60%**
- MOS 保持 ≥ **4.0**（VCTK/LibriTTS）
- First Audio Latency < **300ms**

**关键技术**：

1. **HiFi-GAN 低秩分解（参数量化）**
   对 HiFi-GAN 的卷积核做低秩分解，参数降低 5x；用 LoRA 思想训练低秩补偿。

2. **Vocos 替代 HiFi-GAN（架构升级）**
   Vocos 是 2023 年提出的轻量声码器（基于 STFT），参数量减少 80%，MOS 保持 4.0+；直接采用 Vocos 替换 HiFi-GAN。

3. **流式声码器（Chunk 级别合成）**
   将声码器改造为流式：输入 chunk 级别 Mel 频谱，输出 chunk 级别音频；通过因果卷积实现。

**可信性 & 创新点**：

## 课题十：跨轮 Agent KV 共享与状态序列化压缩

**关键挑战**：Agent 多轮对话中，前 N 轮的 KV 在后续轮次仍需使用。**当前系统每轮都从头计算 KV**，重复算力浪费严重（10 轮对话 = 10x 算力）。跨轮 KV 复用是 Agent 推理的"圣杯"，但**完全没有现成方案**——所有 KV 压缩工作都假设单轮场景。

**技术目标**：

- 跨轮 KV 命中率 ≥ **60%**
- 多轮对话 TPOT 降低 **40%**
- 任务完成率保持不变

**关键技术**：

1. **跨轮 KV 重要性评分（轮次感知）**
   每轮结束时评估所有 KV 的"未来价值"，给每个 KV 打分；分数低的轮次 KV 优先淘汰。

2. **跨轮 KV 共享池（多轮复用）**
   建立跨轮 KV 共享池（与 vLLM Prefix Cache 概念类似但粒度更细），按 query 相似度匹配复用。

3. **状态序列化压缩（替代方案）**
   如果 KV 不可复用，**将轮次状态序列化为压缩向量**，下轮作为额外 context 输入；通过 QLoRA 等技术恢复精度。

**可信性 & 创新点**：

- **参考论文**：
  - IntentKV (2026) — 跨轮 Query Memory
  - KV Pareto (2025) — KV 量化 + 权重量化 + chunked prefill 联合
  - CacheBlend (2024) — 跨查询缓存混合
  - Models Take Notes (2026) — KV Cache 可编辑
  - **Scholar Alert #5**：`agent workflow scheduling`
- **可观测信号源**：
  - 每日 LangChain Blog / Anthropic Computer Use
  - 每周 arXiv cs.MA / cs.CL
  - 关注 AgentBench / BFCL 评测
- **创新点**：
  - 现有 KV 压缩无跨轮方案，**本课题首次提出"轮次感知的重要性评分"**
  - 现有 Prefix Cache 粒度粗，**本课题首次实现"query 相似度的跨轮 KV 共享"**
  - 现有方案 KV 不可序列化，**本课题首次提出"状态向量序列化"替代方案**
