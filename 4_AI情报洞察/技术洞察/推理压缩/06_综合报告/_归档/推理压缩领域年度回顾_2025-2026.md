# 推理压缩领域年度回顾：2025.06 → 2026.06

> 精读支撑：11篇必读论文（8篇 KV 压缩 + 5篇通信压缩，2篇跨分类）

---

## 一、领域背景：为什么 2025-2026 是推理压缩的爆发年

2023-2024 年，LLM 推理优化的主战场是**权重量化**（GPTQ、AWQ、GGUF），模型从 FP16 压缩到 INT8/INT4，部署成本大幅下降。

但 2024 年下半年起，业界意识到一个新瓶颈正在形成：

> **KV Cache 内存爆炸**：长上下文场景下，KV Cache 的内存占用可以轻易超过权重本身。128K 上下文下 KV Cache 可能是权重的 10-20 倍。单纯压缩权重已经不够用了。

同时，**MoE（Mixture-of-Experts）架构**成为主流（DeepSeek-V3、Mixtral、Qwen3-MoE），分布式推理中的**专家路由通信**成为新的带宽瓶颈。

两条技术演进线在此交汇：

```
LLM 推理优化
    ├── 权重量化 ──────────────────→ 成熟落地（2023-2024）
    │                                    2025-2026 仍有进步（AWQ → QuIP# → HIGGS）
    │
    ├── KV Cache 压缩 ←── 新爆发点（2024-2025 至今）
    │   ├── 量化（最热，约93篇/年）
    │   ├── 低秩近似（新兴，约36篇/年）
    │   └── 管理/淘汰（成熟生产落地）
    │
    └── 通信压缩（MoE 分布式推理）←── 新兴（2025-2026）
        ├── MoE 专家并行通信
        └── 梯度同步压缩（训练侧）
```

**本报告重点：KV Cache 压缩 + 通信压缩**，权重量化作为背景不展开。

## 三、技术演进时间线（季度视角）

### 2025 年 Q3（2025.07-09）：方向确立

这一阶段是 KV Cache 压缩方向的**学术研究全面启动**。

**核心事件：**

- **KIVI** 在这一时期被工业界大规模引用。Per-channel Key / per-token Value 的非对称 INT2 量化成为 KV 量化的事实基准。
- **KVQuant**（NeurIPS 2024 → 2025 活跃）系统化地将 INT2/3/4 量化落地，分析了 per-head 量化敏感性，成为后续工作的对比基准。
- **H2O**（Heavy-Hitter Oracle，NeurIPS 2023）继续被引用和改进，但其"累计 attention score"规则在长上下文场景的效果受到质疑。

**技术主流：** 均值/最大值标准化 + per-channel 量化，几乎没有任务感知能力。

**产业状态：** vLLM 0.4 发布，引入 Paged Attention 和 Prefix Caching，生产环境开始依赖 KV Cache 管理而非压缩。工业界意识到管理技术解决的是"保留什么"，但解决不了"占用太大"的问题。

---

### 2025 年 Q4（2025.10-12）：混合精度 + 任务感知萌芽

**核心事件：**

这一阶段出现了三个重要方向分歧：

**方向 A：Query-aware 混合精度**

- **MixKVQ**（2025-12，arXiv:2512.19206）：提出对当前 query 重要的 key 通道应保留高精度，不重要的可以压缩更狠。这是第一次有人把"任务相关性"引入 KV 量化比特分配。精度损失在复杂推理任务上显著优于固定精度。
- 局限：需要额外计算 query-key 相似度，有一定 overhead。

**方向 B：联合优化 Pareto 前沿**

- **KV Pareto**（2025-12，arXiv:2512.01953）：将 KV 量化 + 权重量化 + chunked prefill 三者联合搜索 Pareto 前沿。在 Qwen/Llama/Mistral 上实现 68-78% 内存降低，精度损失仅 1-3%。
- 代表了"单点优化已触瓶颈"的认识：必须联合系统调度才能进一步突破。

**方向 C：可学习淘汰策略**

- **TRIM-KV**（同期，arXiv:2512.03324，正式发表 2026-03）：每个 token 创建时学习一个"保留分数"，分数低的 token 被主动淘汰。按层/头差异化处理，数学推理和长上下文 benchmarks 超越静态 eviction baseline。
- 代表了从"规则驱动"到"数据驱动"的管理技术转变。

**学术论文密度：** 这一季度 KV Cache 相关论文约占全年的 35%，是学术产出最密集的时期（ICLR 2025 录稿 + NeurIPS 2025 投稿双重驱动）。

---

### 2026 年 Q1（2026.01-03）：生产落地深化

**核心事件：**

- **DeepSeek-V3**（2025-12 发布）：生产级模型，首次将 KV cache 压缩与权重量化联合设计内置到模型发布中。DeepSeek 团队实际上在做 KV Pareto 主张的事情，但以内置模型 weight 的方式实现。
- **Qwen3**（2026-03 发布）：同样内置混合精度 KV cache 支持。
- **SGLang**（2026-01 活跃）：RadixAttention（自动 KV cache 重用 + Prefix Caching 调度）成为除 vLLM 之外最重要的开源推理框架。

**技术主流：** 生产框架（vLLM/SGLang）全面支持 Paged Attention + Prefix Caching，学术界开始区分：
- **压缩技术**（让数据变小）：量化、低秩近似
- **管理技术**（决定保留什么）：可学习的 eviction policies

**重要论文：** TRIM-KV（正式发表）、Heterogeneous Parallelism for Multimodal（多模态训练的异构并行，给通信压缩提供新视角）

---

### 2026 年 Q2（2026.04-06）：架构感知 + 联合优化突破

这是历史上 KV Cache 压缩研究最密集的季度。

**核心突破：**

#### 突破 1：RoPE-aware 量化 — Block-GTQ（2026-06）

**为什么重要：** KV Cache 量化在此之前一直把 key 当"普通向量"处理，但所有主流模型（Llama、Qwen、DeepSeek）都使用 RoPE 位置编码。Block-GTQ 首次揭示：

> Key cache 在 RoPE 频域的不同块，能量差异可达几个数量级。高能量 RoPE block 的量化误差会主导最终 logit 偏差。均匀比特分配在 AIME 2024 数学任务上直接崩溃到 0 分。

**关键数据：** K2V2（Key 2bit / Value 2bit）配置下：
- NIAH 检索：70.6 → **97.4**（+26.8）
- AIME 2024：0.0 → **51.7**（从崩溃到接近 fp16 的 54.2）

**意义：** 把 KV 量化从"存储优化"重新定义为"logit 保真度优化"，是 2026 年上半年最具工程价值的论文。

#### 突破 2：权重 + KV 联合量化 — HyperQuant（2026-06）

**为什么重要：** 第一个完整的"权重 + KV 统一量化流水线"，包含 Hadamard 变换 + 最优格量化 + Rice 编码。KV 量化低至 **1.7 bps**（每 token 1.7 比特），H100 上 4 bps 实现 3.79x 压缩。

**意义：** 将 KV Pareto 的"联合优化"Pareto 前沿搜索，从实验性框架推进到可生产的流水线。

#### 突破 3：自适应低秩 — STAR-KV（2026-06）

**为什么重要：** 软阈值机制 + 头级/块级 rank 自适应控制。75% KV cache 压缩，结合量化后实现 **20x KV reduction**，6.9x attention 加速。

**意义：** 低秩近似终于有了"自适应 rank 控制"能力，不再依赖手工设定 rank。

#### 突破 4：投机解码验证加速 — Dustin（ICML 2026，2026-06）

**为什么重要：** 首次系统分析长上下文场景下"验证阶段的 KV cache loading 主导延迟"（87.5% 的验证时间花在 KV 加载上）。提出稀疏验证策略，在 32K context + batch=16 下实现 **27.85x self-attention 加速**。

**意义：** 将 KV cache 管理技术（eviction）应用到投机解码的验证阶段，是一个新的应用场景。

## 四、细分类别深度解析

### 4.1 KV Cache 量化（~93篇/年）

#### 技术路线分化

```
KV Cache 量化
├── 均匀量化（基准）— per-channel 均匀 INT2/3/4
│   └── 代表：KIVI、KVQuant（已被超越）
│
├── 混合精度量化（主流）
│   ├── per-block 自适应 — TQ-MSE、Block-GTQ（RoPE-aware）
│   ├── per-head 敏感性 — KVQuant
│   └── query-aware — MixKVQ
│
└── 联合优化（新兴）
    ├── KV + 权重 — KV Pareto、HyperQuant
    └── KV + 调度 — Dustin、TRIM-KV
```

#### 关键论文演进脉络

| 阶段 | 论文 | 核心创新 |
|------|------|---------|
| 基准 | KIVI (2024) | 非对称 per-channel 量化 |
| 系统化 | KVQuant (2024) | INT2/3/4 + per-head 敏感性分析 |
| MSE最优 | TurboQuant-MSE (2026-05) | MSE最优变体 |
| **RoPE-aware** | **Block-GTQ (2026-06)** | **按频域块自适应比特分配** |
| 联合流水线 | HyperQuant (2026-06) | 权重+KV 统一量化 |

**当前 SOTA：** Block-GTQ 在 perplexity 和下游任务上均超越所有前序工作，且有配套 H800 实现（256K context 可行）。

### 4.2 KV Cache 管理技术

**核心区别：** 管理技术决定**保留哪些数据**，压缩技术把**数据变小**。两者是正交且互补的。

#### 技术路线

```
KV Cache 管理
├── 规则驱动
│   ├── Heavy-hitter — H2O（累计 score 保留）
│   ├── 窗口投票 — SnapKV（观察窗口投票）
│   └── Streaming — StreamingLLM（静态保留 sink + 局部窗口）
│
├── 可学习驱动
│   ├── 保留分数 — TRIM-KV（per-token 可学习保留分数）
│   └── 稀疏验证 — Dustin（投机解码专用）
│
└── 生产系统
    ├── Paged Attention — vLLM（分页管理，非淘汰）
    └── RadixAttention — SGLang（自动重用 + 前缀共享）
```

#### 技术分歧：Eviction vs. Compression

**Eviction**（淘汰）：直接丢弃不重要的 token，是有损的。代表工作 H2O、SnapKV。
**Compression**（压缩）：保留但缩小，是潜在无损的。代表工作 KIVI、Block-GTQ。

**2026 年趋势：** 两者正在融合——TRIM-KV 用可学习淘汰 + 动态分数，是 Eviction 的进化；Block-GTQ 在压缩码上直接做 attention，是 Compression 的进化。**最终会走向联合**：Eviction 决定保留哪些，Compression 把保留的变小。

### 4.3 通信压缩（MoE + 分布式）

#### 背景

MoE 模型（如 DeepSeek-V3、Qwen3-MoE）的特点是：**每个 token 只激活少数专家**，但需要 All-to-All 路由通信。在分布式场景下，跨节点专家路由产生大量网络带宽开销。

```
传统 MoE 分布式（全复制范式）：
每个节点复制所有专家 → 专家路由本地执行 → 无跨节点通信
问题：专家总数增加时，内存爆炸（1个专家→N个副本）

新型 MoE 分布式（专家并行 EP）：
专家分布到不同节点 → 路由到其他节点 → 跨节点通信瓶颈
问题：带宽成为主要限制

→ 通信压缩成为必须
```

#### 代表工作

| 论文 | 时间 | 核心问题 | 解决方案 |
|------|------|---------|---------|
| **SCD**（arXiv:2606.07684）| 2026-06 | KV 在分布式推理节点间传输时带宽大 | 异步流水线重叠 + 低比特 KV 传输 |
| **NetKV**（arXiv:2606.03910）| 2026-06 | 推理实例选择忽视拓扑aware | 跨节点拓扑感知 + KV 复用 |
| **FoMoE**（arXiv:2606.19025）| 2026-06 | 全复制范式内存爆炸 | 专家跨节点分区 + skip-token |
| **ASAP**（arXiv:2606.22541）| 2026-06 | Attention 和 MoE 同步barrier | 解耦 + 异步执行 |
| **CloudMoE**（arXiv:2606.10493）| 2026-06 | 端侧 MoE I/O 瓶颈 | CPU-GPU 混合调度 + 本地 FP8 |
| **ZipMoE**（arXiv:2601.21198）| 2026-01 | 端侧无损压缩 | 无损压缩 + Cache-affinity 协同 |

#### 最重要突破

**FoMoE（2026-06）：** 打破"每个节点全复制所有专家"的范式，提出跨节点专家分区 + skip-token 机制，通信成本降低 **1.42x~45.44x**，吞吐提升 1.4x。这释放了 MoE 的真实稀疏性潜力——之前全复制相当于用空间换通信，本质上还是低效的。

**ASAP（2026-06）：** 在 disaggregated（解耦）架构下，将 Prefill 的 Attention 阶段和 MoE 阶段异步执行，消除同步 barrier，在 SLO-compliant 约束下 prefill 吞吐提升 **90%**。

## 六、核心规律：三个转折点

### 转折 1：均匀量化 → 结构感知量化

**时间：** 2025 Q4 → 2026 Q2

**变化：** KV Cache 量化从"通用压缩"走向"结构感知"。

早期（KIVI、KVQuant）把 key 和 value 当作独立向量做均匀/非对称量化。2025 Q4 开始，MixKVQ 引入 query-aware，2026 Q2 Block-GTQ 引入 RoPE-aware——认识到 KV cache 的结构（RoPE 频域、query 关联性）与量化策略高度相关。

**驱动力：** 下游任务精度（特别是 AIME 数学）成为了量化方案的试金石，暴露了均匀量化的系统性偏差。

---

### 转折 2：单目标优化 → 联合 Pareto 搜索

**时间：** 2025 Q4 → 2026 Q1

**变化：** KV 压缩 + 权重量化 + 系统调度三者必须联合优化。

KV Pareto 和 HyperQuant 证明了"分别优化 KV 和权重"不如"联合搜索 Pareto 前沿"。类似地，Chunked Prefill 与 KV 量化必须协同设计。

**根本原因：** 三者的压缩-精度 trade-off 相互耦合，单独优化会在系统瓶颈处触天花板。

---

### 转折 3：全复制 → 拓扑感知分布式

**时间：** 2026 Q2

**变化：** MoE 分布式从"全复制换通信"走向"专家分区换内存"。

FoMoE 和 NetKV 代表了两个关键认识：
- "全复制"本质上是拿内存换通信，当专家数增加时内存爆炸
- "拓扑感知"让通信和内存 trade-off 可以在更细粒度上控制

**驱动力：** DeepSeek-V3（671B MoE）这样的超大模型，逼迫业界必须打破全复制范式。

|------|------|------|
| **>1M token 超长上下文 KV 压缩** | ★★★★ | 当前主流工作在 128K 以内，超长上下文 KV 量化误差难以控制 |

| **端侧 KV 量化（手机/嵌入式）** | ★★★ | 极端功耗约束下的 KV 量化方案（<4 bit 且精度保持）|

## 九、给研究者的建议

**如果做 KV 量化：**
- RoPE-aware（Block-GTQ 路线）→ 还有大量空间（如引入蒸馏 loss 联合优化）
- 联合优化（KV + 权重 + 调度）→ 有工程门槛但是正确方向
- 多模态 VLM 的 KV cache → 几乎没人做，蓝海

**如果做系统：**
- 端侧 MoE 部署（CloudMoE/ZipMoE 路线）→ 有明确工程价值
- 硬件专核 KV 卸载 → 高风险但高回报

**如果跟产业：**
- 关注 vLLM/SGLang 的 KV cache 策略变化（两者的前端调度竞争是 2026 下半年主战场）
- 关注 DeepSeek 的 KV 压缩实践（他们实际落地了 KV Pareto 思路）

---

## 十、给实践者的建议

**如果部署模型：**
- vLLM + AWQ 权重 + Paged Attention 是当前最稳的生产路径
- 长上下文（>32K）优先用 SGLang 的 RadixAttention
- 混合精度 KV 量化（Block-GTQ 类）适合对精度敏感的场景

**如果选型：**
- 精度优先 → fp16 + Paged Attention（当下最稳）
- 成本优先 → INT8/INT4 权重 + INT4 KV（参考 vLLM 官方配置）
- 超长上下文 → SGLang + Chunked Prefill + StreamingLLM
