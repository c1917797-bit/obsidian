四、工程落地工具链地图

4.1 推理框架选型

TensorRT-LLM ★★★★★

追求: 最高性能 (NVIDIA生产)

优点: NVIDIA官方、INT8/FP8、极致吞吐

缺点: 调优复杂、定制困难

SGLang ★★★★☆

追求: 最灵活调度/长文本

优点: RadixAttention、长上下文、多模型、Agent场景

缺点: 性能略低于TensorRT

vLLM ★★★★★

追求: 平衡性能与易用

优点: PagedAttention、活跃社区

缺点: 高级优化受限

llama.cpp ★★★★★

追求: CPU/端侧推理

优点: GGUF格式、CPU推理、移动端适配

缺点: 速度最慢

Ollama ★★★☆☆

追求: 小白友好

优点: 简易部署

缺点: 性能有限

五、场景路径 - Agent / MoE / 长文本

5.1 Agent推理 - KV累积是核心

Agent特有的KV挑战:
• 多轮对话: KV累积无上限，随对话轮数线性增长
• 工具调用: 动态schema导致KV模式不可预测
• 长记忆: 记忆压缩必须保持关键信息
对话轮数推荐方案
>20轮 ★★★KV量化 (KIVI/Block-GTQ) + 选择性淘汰 (SnapKV)
10-20轮 ★★选择性淘汰优先 (CONF-KV / PolyKV)
<10轮 ★vLLM PagedAttention足够

Agent专用参考工作

工作适用场景核心贡献集成难度
UltraQuant多轮AgentFP4 KV + AMD优化中等
AnchorKV安全Agent对齐锚点保持中等
CONF-KV长对话置信度感知淘汰中等
TRIM-KV多场景Agent可学习门控较高
LazyLLMPrefill加速按需KV恢复较高

5.2 MoE分布式 - 通信压缩是核心

MoE特有的通信挑战:
• Expert路由: 每个token只激活少数Expert，但All-to-All通信密集
• 负载不均: Expert使用不均衡导致GPU空闲
• 分布式训练: 梯度同步通信量巨大
场景推荐方案
训练场景 ★★★DeepEP (生产级MoE通信库) + INT4/FP8梯度压缩 + 流水线+Expert并行联合优化
推理场景 ★★ExpertQuant (通信量化, 2025新工作) + Top-K路由压缩 + 与KV压缩联合 (未来方向)

MoE专用参考工作

工作优化类型核心贡献状态
DeepEP通信库DeepSeek生产级已开源
ExpertQuant通信量化首个MoE通信量化2025新
MosaicPrune专家剪枝MoE层级化剪枝学术
MiniMoE量化+剪枝边缘MoE协同优化学术
MLPMoE密集→MoE零样本架构转换学术
💡 关键洞察: ExpertQuant是2025年新工作，MoE通信量化这个方向几乎无竞争 — 是现在介入的黄金窗口。

5.3 长上下文 - KV爆炸是核心

长上下文特有的KV挑战:
• KV累积: 128K上下文 → 约40GB KV Cache (FP16)
• 注意力稀疏: 实际有效注意力分散在全上下文
• 检索任务: NIAH (Needle in Haystack) 类任务
上下文长度推荐方案
>1M (超长) ★★★架构级压缩优先 (MLA/GQLA) + 低秩近似 (STAR-KV) + 选择性淘汰 (SnapKV/H2O)
128K-1M ★★选择性淘汰 ★★★ (SnapKV, R-KV) + 量化 (KIVI/Block-GTQ) ★★ + CONF-KV (NIAH检索场景)
32K-128K ★vLLM PagedAttention基本够用 + 追求极致上Sparse
