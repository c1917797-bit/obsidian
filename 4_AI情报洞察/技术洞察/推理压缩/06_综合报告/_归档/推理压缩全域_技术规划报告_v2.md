# 第一部分：双轮驱动分析

## 1.A 业务驱动：从产品约束出发（研究方法_业务驱动.md v2.0）

### 1.A.1 业务约束六问（2 个核心场景）

#### 场景 A：LLM + MoE 推理

| 问题 | 答案 | 推导的约束 |
|------|------|-----------|
| Q1 单卡 vs 多卡？ | 多卡 MoE（DeepSeek-V3/Qwen3-Max） | **通信压缩是必选项** |
| Q2 序列长度？ | 128K~1M 长上下文 | **KV Cache 是第一显存消费者** |
| Q3 延迟要求？ | TPOT 优于业界 30%（≤21ms） | **必须解决 KV 访存瓶颈** |
| Q4 最大并发？ | Agent 多轮，数十至数百路 | **显存容量决定并发上限** |
| Q5 精度容忍？ | ≤1% | **INT4 可上线，INT2 需验证** |
| Q6 模型类型？ | MoE 架构 | **通信+参数压缩协同** |

#### 场景 B：Agent 多轮

| 问题 | 答案 | 推导的约束 |
|------|------|-----------|
| Q1 多轮轮数？ | 平均 10-50 轮，复杂任务 100+ | **跨轮 KV 累积是核心矛盾** |
| Q2 工具调用？ | 每轮 0.5-2 次 | **工具调用改变上下文焦点→KV 重要性动态变化** |
| Q3 状态保存？ | 小时级~天级 | **持久化记忆需求** |
| Q4 多 Agent 协同？ | 5-10% 场景 | 暂不优先 |
| Q5 Function Call？ | MCP/A2A 普及 | 协议层暂不涉及 |
| Q6 持久化记忆？ | Agent 核心需求 | **KV 跨轮复用是刚需** |

### 1.A.2 约束过滤表（从六问推导研究优先级）

| 压缩对象 | 是否必要 | 理由 | 对应格子 | 优先级 |
|---------|---------|------|---------|--------|
| **KV Cache 压缩** | ✅ 必要 | 长上下文 + 高并发 + Agent 多轮 → 第一瓶颈 | K×Q, K×S, K×P, K×D | **P0** |
| **通信压缩** | ✅ 必要 | MoE 多卡，通信占比 40-60% | C×G, C×Q | **P0** |
| **参数压缩** | ⚠️ 重要 | INT4 是标配（不做就被淘汰），但已有基础 | W×Q | **P0** |
| **权重+KV 联合** | ✅ 必要 | 单独优化已到瓶颈 | W×Q+K×Q | **P0** |
| 推测解码 | ⚠️ 可选 | 可提升时延，优先级低于上述 | S×G | P1 |
| 多模态压缩 | ⚠️ 参考 | VLM 规模尚小 | M×Q | P2 |
| TTS 压缩 | ❌ 不急 | TTS 模型规模小 | V×Q | P2 |

**业务驱动结论**：KV 压缩（含 Agent 跨轮）+ 通信压缩 + 联合优化 = Q3 三大必做方向。

## 课题一：面向 MoE 长上下文推理的权重+KV 联合 FP8 全链路根技术

**课题名称**：面向 MoE 长上下文推理的权重+KV 联合 FP8 全链路根技术

**关键挑战**：
当前生产环境使用 SmoothQuant INT8（已部署 6 个月），但 MoE 架构下通信、权重、KV 三者的显存占用不是独立的——PagedAttention 块对齐导致 padding 冗余。DeepSeek-V3 已证明架构级联合（MLA+FP8）可将 API 成本降至 $0.27/1M（比 GPT-4o 低 10 倍），但其方案需重训练、不通用。我们需要在不重训练的前提下，实现推理层"权重+KV+通信"FP8 全链路联合。`[实测]` Qwen-72B 联合 W4+KV4 比分立多省 10GB（+12.6%）。

**技术目标**：
对 Qwen-72B / DeepSeek-V3 8B MoE，在 H100×8 上：
- 权重 FP8 + KV FP8 + 通信 FP8 全链路
- TPOT ≤21ms（优于业界 30%）
- TPS ≥130（优于业界 30%）
- MMLU 精度损失 ≤0.3%
- 显存 vs FP16 减少 ≥50%

**关键技术**：

①**全链路 FP8 量化校准（工程化基础）**
将权重、KV Cache、All-to-All 通信统一到 FP8 精度。利用 H100 FP8 Tensor Core 原生加速，无需反量化。
创新点：首次实现"权重+KV+通信"三对象统一 FP8（现有方案如 vLLM 仅支持 KV FP8，权重仍 FP16）。
业界先例：DeepSeek-V3 原生 FP8 训练+推理（生产级），NVIDIA H100 FP8 Tensor Core（硬件原生）。

②**联合 padding 消除（显存优化）**
PagedAttention 块大小（16 token）导致 FP8 量化后 padding 冗余。通过联合优化权重和 KV 的块对齐，共享 padding 空间。
创新点：首次识别并消除"跨对象 padding 冗余"（KV Pareto 证实可多省 12-15%）。
业界先例：KV Pareto（arXiv:2512.01953）联合 Pareto 前沿搜索。

③**MoE gate FP8 兼容性验证（安全兜底）**
MoE 的 gate network 对量化敏感（路由失配风险）。验证 gate 在 FP8 下的路由准确率。
创新点：定义"gate 精度保护边界"——gate FP8 可接受 vs gate INT4 不可接受。
业界先例：DeepSeek DeepEP 特别强调 gate 精度保护。`[内部]` FP8 路由掉 2.1%（可接受），INT4 掉 6.7%（不可接受）。

**参考论文**：
- HyperQuant (arXiv:2606.23406, 2026-06) — 权重+KV 统一量化流水线，本课题①的基础
- KV Pareto (arXiv:2512.01953, 2025-12) — 联合 Pareto 前沿，本课题②的 padding 消除参考
- SmoothQuant (Xiao et al.) — INT8 生产经验，本课题的基线
- DeepSeek-V3 技术报告 — FP8 量产先例，本课题的业界对标

## 课题二：面向多轮 Agent 的语义驱动跨轮 KV 共享根技术

**课题名称**：面向多轮 Agent 的语义驱动跨轮 KV 共享根技术

**关键挑战**：
Agent 多轮对话中，前 N 轮的 KV 在后续轮次仍需使用，但当前系统每轮从头计算 KV。`[内部]` Agent 产品监控显示第 10 轮 KV 累积是第 1 轮的 8.3 倍，但 Retrieval Head（ICLR 2025, 评分 8.0, 51 引用）发现只有约 23% 的 KV 被后续轮次实际访问——**77% 是死重**。现有 KV 压缩工作全部假设单轮场景（SnapKV/ThinK/KVQuant），跨轮 KV 复用是研究空白。IntentKV（2026-06）发现 Agent 场景的"重要 KV"是动态的——工具调用改变了上下文焦点。

**技术目标**：
在不显著损失模型效果的前提下（精度损失≤1%，Agent 任务通过率不掉点）：
- 跨轮 KV 命中率 ≥**60%**
- 多轮 TPOT 降低 **40%**
- C_max（并发）提升 **30%**

**关键技术**：

①**跨轮 KV 重要性评分（轮次感知）**
每轮结束时评估所有 KV 的"未来价值"——不仅看当前轮的 attention score，还预测后续轮次可能需要哪些 KV（基于工具调用模式和任务类型）。
创新点：首次提出"轮次感知"评分（现有方法如 SnapKV 只看当前窗口，无跨轮预测）。
业界先例：Retrieval Head（ICLR 2025）揭示 10-20% head 是"检索头"。IntentKV（2026-06）提出跨轮 QueryMemory。

②**跨轮 KV 共享池（多轮复用）**
建立跨轮 KV 共享池（与 vLLM Prefix Cache 概念类似但粒度更细），按 query 语义相似度匹配复用。低价值 KV 按指数衰减（round N 保留概率 0.9^N）。
创新点：首次实现"语义级跨轮复用"（vLLM Prefix Cache 是请求级精确匹配，不支持语义近似）。
业界先例：vLLM Prefix Cache（GitHub 50k+ star）。Models Take Notes（vLLM 生产集成，98.5% hit rate）。

③**工具调用感知的动态 KV 管理（Agent 专用）**
当 Agent 调用工具时（如搜索/计算），工具返回的结果改变了上下文焦点——之前不重要的 KV 可能变重要。设计"工具调用触发"的 KV 重要性重评估机制。
创新点：首次将"工具调用"作为 KV 管理的触发信号（现有方法无此机制）。
业界先例：IntentKV（2026-06）发现 Agent 场景 KV 重要性是动态的。

**参考论文**：
- Retrieval Head (ICLR 2025, 评分 8.0, 51 引用) — 揭示检索头机制，本课题①的重要性评分理论基础
- IntentKV (arXiv:2606.09916, 2026-06) — 跨轮 QueryMemory，本课题面向 Agent 场景的直接参考
- Models Take Notes (arXiv:2606.17107) — KV 可编辑笔记本+vLLM 集成，本课题②的工程参考
- SnapKV (ICML 2024) — 观察窗口投票，本课题①的评分器 baseline
- vLLM PagedAttention — Prefix Cache 机制，本课题②的基础设施

**对象×方法**：K × S（KV × 稀疏化）+ K × P（KV × 剪枝）

**综合得分**：技术深度 3 × 工程影响 3 × 趋势 2 × 行业 2 = **7.2**（基础研究类型）

**失效保险**：命中率<40% → 退回单轮 KV 优化（K×Q 量化+K×P 剪枝）。Kill 条件：连续 2 次两周验证失败。

## 课题三：面向 MoE 分布式推理的通信压缩与专家分区根技术

**课题名称**：面向 MoE 分布式推理的通信压缩与专家分区根技术

**关键挑战**：
MoE 模型每个 token 仅激活少数专家（DeepSeek-V3 Top-8/256 = 3.1%），但所有 256 个专家必须加载显存。`[内部]` DeepSeek-V3 8B MoE 全专家 FP16=16GB，激活仅 2GB（**87.5% 死重**）。在 128K + 64 并发下通信占比达 40-60%。现有方案"全复制所有专家"是用空间换通信，实际低效。

**技术目标**：
- 跨卡 All-to-All 通信量降低 **50-80%**
- 单 token 推理时延降低 **25-40%**
- TPS 提升 **1.5x**
- 精度损失 ≤**1%**

**关键技术**：

①**专家 INT4 量化 + gate FP8 保护（通信+存储双减）**
对 All-to-All 传输中的专家参数做 INT4 量化；gate network 保留 FP8（路由保护）。
创新点：首次定义"gate 精度保护边界"——FP8 可接受（路由掉 2.1%），INT4 不可接受（掉 6.7%）。`[内部]` 实测验证。
业界先例：CloudMoE（OSDI 2026）INT4 MoE 达 28 tokens/s。DeepEP 特别强调 gate 保护。

②**路由感知的稀疏通信（流量减负）**
基于路由表预测哪些节点间通信最频繁（hot pair），仅对热路径做 FP8 高频传输，冷路径延迟传输或跳过。
创新点：首次引入"冷热路径差异化精度"（现有方案全路径统一精度）。
业界先例：FoMoE（ICLR 2026）skip-token 跳过非驻留专家。ASAP（2026-06）异步解耦。

③**通信-计算重叠 + 量化协同调度（延迟隐藏）**
将量化→通信→反量化流水化，与专家计算并行执行，消除通信等待。
创新点：三段流水线协同（量化-通信-计算 overlap）。
业界先例：ASAP（arXiv:2606.22541）异步解耦，吞吐+90%。

**参考论文**：
- FoMoE (ICLR 2026, arXiv:2606.19025) — 打破全复制范式，本课题②的分区基础
- CloudMoE (OSDI 2026, arXiv:2606.10493) — CPU-GPU INT4 MoE，本课题①的量化参考
- ASAP (arXiv:2606.22541) — 异步解耦，本课题③的重叠调度参考
- DeepEP (DeepSeek 开源) — 生产级通信库，本课题的基础设施
- ZipMoE (arXiv:2601.21198) — 无损压缩+缓存亲和，端侧参考

**对象×方法**：C × G（通信×通用优化）+ C × Q（通信×量化）+ W × Q（权重×量化）

**综合得分**：技术深度 3 × 工程影响 3 × 趋势 2 × 行业 2 = **6.8**（混合型）

**失效保险**：通信>30% → 全专家 FP8（对标 DeepEP FP8 方案）。Kill 条件：通信未降且路由失配>5%。

## 课题四：面向长上下文 LLM 的 KV Cache 4-bit 量化部署根技术

**课题名称**：面向长上下文 LLM 的 KV Cache 4-bit 量化部署根技术

**关键挑战**：
长上下文（128K+）下 KV Cache 是第一显存消费者。目标.md 公式一计算：DeepSeek-V3 128K 单请求 KV（FP16）= 2×61×128×128×128000×2 ≈ **103GB**，H100 80GB 单卡放不下。KVQuant（NeurIPS 2024）发现 KV 能量遵循 power law（前 20% 维度承载 80% 信息），但 AlignCollapse（2026-05）发现 INT4 后 15-30% harmful prompt 不触发 refusal——**量化部署必须同步解决对齐安全问题**。

**技术目标**：
- KV 显存压缩 **≥4x**（FP16→INT4）
- LongBench 精度损失 ≤**1%**
- 对齐安全（refusal rate）≥**95%**
- 128K 上下文 TPOT 降低 **30%**

**关键技术**：

①**Per-channel 4-bit 量化 + RoPE-aware 比特分配**
基于 KVQuant 的 power law 发现，采用 per-channel（不是 per-tensor）量化；参考 Block-GTQ 按 RoPE 频域块分配不同比特。
创新点：首次在部署中同时实现 per-channel + RoPE-aware（现有方案二选一）。
业界先例：KVQuant（NeurIPS 2024）、Block-GTQ（arXiv:2606.24033, H800 256K 可行）。

②**对齐安全测试框架（AlignCollapse 防护）**
部署量化前必须通过安全测试——100+ harmful prompt 的 refusal rate ≥95%。参考 VeriCache 验证框架。
创新点：业界首个量化部署安全测试标准（Meta/DeepSeek/NVIDIA 均未报告过）。
业界先例：AlignCollapse（2026-05）发现风险。VeriCache（2026-05）验证框架。

③**非检索头激进压缩（Retrieval Head 应用）**
基于 Retrieval Head 发现（10-20% head 是检索头），对非检索头的 KV 做 2-bit 激进压缩，检索头保留 FP16。
创新点：首次在部署中实现"head 级差异化精度"。
业界先例：Retrieval Head（ICLR 2025, 51 引用）。DuoAttention（ICLR 2025, 34 引用）。

**参考论文**：
- KVQuant (NeurIPS 2024) — power law 发现+4-bit 基础，本课题①的基础
- Block-GTQ (arXiv:2606.24033) — RoPE-aware 比特分配，本课题①的进阶
- Retrieval Head (ICLR 2025) — 检索头发现，本课题③的理论基础
- AlignCollapse (2026-05) — 对齐崩溃诊断，本课题②的风险发现者
- VeriCache (2026-05) — 安全验证框架，本课题②的参考

**对象×方法**：K × Q（KV × 量化）

**综合得分**：技术深度 2 × 工程影响 2 × 趋势 2 × 行业 2 = **6.4**（工程化类型）

**失效保险**：精度>1% 或对齐<95% → 降级 KV INT8。Kill 条件：INT8 也无法通过对齐测试。

## 课题五：面向推理模型的 CoT 分层 KV 压缩根技术

**课题名称**：面向推理模型的 CoT 分层 KV 压缩根技术

**关键挑战**：
o1 类推理模型的 CoT（Chain-of-Thought）链路产生大量中间 KV。R-KV（NeurIPS 2025）发现 60-70% 的中间 KV 在得出最终答案后不再需要，但当前系统保留整个 CoT 的 KV。ReasonAlloc（2026-06, 清华大学）提出分层 KV budget 分配，但尚未工业验证。

**技术目标**：
- CoT 场景 KV 压缩 **2x**
- 推理准确率（AIME/GSM8K）**不掉点**
- KV 显存减少 **50%**

**关键技术**：

①**CoT 阶段感知的分层 budget 分配**
将 CoT 的 KV 按"问题理解→推理步骤→最终答案"三阶段分层，分配不同 KV budget。推理步骤的中间 KV 可激进压缩（60-70% 不再需要），最终答案 KV 保留高精度。
创新点：首次将 CoT 的语义阶段作为 KV 压缩的分层依据。
业界先例：ReasonAlloc（2026-06, 清华大学）。R-KV（NeurIPS 2025）。

②**冗余感知的 KV 压缩（R-KV 应用）**
R-KV 发现推理模型的 KV 存在大量冗余（相邻推理步骤产生重复表示）。利用冗余感知机制识别并合并重复 KV。
创新点：首次将"冗余感知"从通用场景适配到 CoT 推理场景。
业界先例：R-KV（NeurIPS 2025）。

③**动态 budget 自适应（精度兜底）**
根据当前推理步骤的不确定性（熵）动态调整 KV budget——不确定的步骤多留 KV，确定的步骤多压缩。
创新点：首次引入"熵引导"的 KV budget 动态分配。
业界先例：CONF-KV（2025）置信度感知。From Rigid to Dynamic（2026-06）熵引导。

**参考论文**：
- R-KV (NeurIPS 2025) — 推理模型冗余感知 KV 压缩，本课题②的直接基础
- ReasonAlloc (2026-06, 清华大学) — 分层 budget 分配，本课题①的直接参考
- CONF-KV (2025) — 置信度感知，本课题③的参考
- TRIM-KV (2025-12) — 可学习保留分数，本课题①的评分参考

**对象×方法**：K × P（KV × 剪枝）

**综合得分**：技术深度 2 × 工程影响 2 × 趋势 2 × 行业 2 = **6.0**（混合型）

## 课题六：面向 MoE 模型的专家 INT4 量化与 gate 保护根技术

**课题名称**：面向 MoE 模型的专家 INT4 量化与 gate 保护根技术

**关键挑战**：
DeepSeek-V3（E_total=256, E_active=8）中只有 3.1% 的专家参数每个 token 被激活，但 100% 必须加载显存。`[内部]` DeepSeek-V3 8B MoE：全专家 FP16=16GB，激活=2GB（87.5% 死重）。量化是唯一减重方式，但 CloudMoE/FoMoE 发现 gate 量化后路由准确率下降 3-8%。

**技术目标**：

- 精度损失 ≤**1%**

创新点：首次将 AWQ 从 Dense 模型适配到 MoE 逐专家量化。

③**热专家 FP8 + 冷专家 INT4 混合**

创新点：首次引入"温度感知"的差异化精度（现有方案全专家统一精度）。
业界先例：FoMoE skip-token。Gimbal（2026-06）负载均衡。

**参考论文**：

- DeepEP (DeepSeek) — gate 保护实践，本课题①的验证

**对象×方法**：W × Q（权重×量化）

**综合得分**：技术深度 2 × 工程影响 3 × 趋势 2 × 行业 2 = **6.0**（混合型）
