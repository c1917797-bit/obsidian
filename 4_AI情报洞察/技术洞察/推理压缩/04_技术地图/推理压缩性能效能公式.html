🚀 推理压缩性能效能公式

目标：时延↓ + 吞吐↑（不是压缩比↑）· 5个效能因子 · 以推理性能为锚 · v1.0
📐 推理性能提升 = 各效能因子收益之和 − 压缩开销
性能提升 ≈ [Latency↓·带宽占比 + Throughput↑·计算占比 + Cost↓·并发增益 + Comm↓·通信占比] × Quality − Overhead
Latency↓(带宽节省因子) · Throughput↑(计算节省因子) · Cost↓(并发扩展因子) · Comm↓(通信节省因子) · Quality(精度保持因子) · Overhead(压缩计算开销)

核心原则：压缩不是为了"数据量更少"，而是为了"推理更快/并发更多"。每个因子的收益取决于推理场景的瓶颈在哪——decode瓶颈看Latency↓，prefill瓶颈看Throughput↑，多卡瓶颈看Comm↓，并发瓶颈看Cost↓。

⚠️ 压缩反例：32K以下上下文做KV压缩，Overhead(选择开销) > Latency↓收益(带宽节省)，性能反而下降5-10%。(MagicDec, ICLR'25)

⚠️ 压缩开销CO（不能忽略）

核心矛盾：压缩节省了带宽/计算，但引入了新的开销。净性能=节省−开销。当节省<开销时，压缩有害。

🔗 效能因子 → 压缩技术 → 根技术的完整映射

效能因子目标根技术贡献关键公式
Latency↓ 时延优化Decode TPOT↓精度压缩(PF) + 维度压缩(SF)BE = PF × SF · 收益 = BE × KV带宽占比
Throughput↑ 吞吐优化Prefill TTFT↓ + 吞吐↑维度压缩(SF, 跳过计算)CE ≈ SF · 收益 = CE × 注意力计算占比
Cost↓ 成本优化吞吐↑(更多batch)全部3个根技术(减内存→增batch)VE ≈ PF × SF × RF · 收益 = VE × 并发增益系数
Comm↓ 通信优化多卡TPOT↓精度压缩(PF) + 维度压缩(SF)XE = PF × SF · 收益 = XE × 通信时间占比
Quality 质量保持有效吞吐(避免重算)知识压缩(DF, 蒸馏恢复)AE = 压缩后精度/原始 · 影响=AE × (1-重算率)
根技术到效能因子的映射：
• 精度压缩(量化) → 主要贡献Latency↓(时延)和Comm↓(通信)，因为减少比特=减少带宽
• 维度压缩(稀疏/剪枝) → 同时贡献BE(少访问)、CE(少计算)、VE(少内存)
• 知识压缩(蒸馏) → 主要贡献AE(精度恢复)，间接提升有效吞吐

所以维度压缩(稀疏)是"性价比最高"的根技术——它同时改善3个效能因子(BE+CE+VE)，而量化主要改善1个(BE)。

📐 效能因子 → 推理性能的精确数学关系

吸收来源：竞争力指标体系v2.3 · 效能因子不是抽象概念，每个因子都有精确的数学定义。

TPOT公式 × 效能因子代入

原始：TPOT = (T_calc_decode + S×T_mem) + T_comm×(1-θ)
压缩后：TPOT' = (T_calc/SF + S/SF×T_mem/PF) + T_comm/XE×(1-θ)

TPOT改善 = [T_calc×(1-1/SF) + S×T_mem×(1-1/(PF×SF)) + T_comm×(1-1/XE)×(1-θ)] / TPOT

→ Latency↓贡献 = S×T_mem×(1-1/(PF×SF)) / TPOT × 100%（decode带宽项）
→ Throughput↑贡献 = T_calc×(1-1/SF) / TPOT × 100%（decode计算项）
→ Comm↓贡献 = T_comm×(1-1/XE)×(1-θ) / TPOT × 100%（通信项）

并发公式 × 效能因子代入

原始：C_max = min(C_V, C_gpu, C_comm)
  C_V = (V_total - V_backbone) / (2×L×H×D×S×P)

压缩后：C_V' = (V_total - V_backbone/PF) / (2×L×H×D×S/PF/PF_kv×SF)
VE收益 = C_V'/C_V = 并发提升比 → 直接转化为吞吐提升

TPS = B/TPOT，其中 B = (M_total - M_weights) / M_KV
→ M_KV↓（通过PF×SF×RF）→ B↑ → TPS↑

精度约束 × 有效吞吐

C_accuracy = C_max × AE（精度保持率）
→ Quality=0.95时，5%的请求因精度不足需重算 → 有效吞吐↓5%
→ Quality<0.9（如INT2数学任务）→ 有效吞吐↓>10% → 压缩得不偿失

🔍 瓶颈诊断公式（吸收目标.md §3.3.2）

做压缩之前必须先诊断瓶颈在哪——用C_max三约束公式判断。
C_max = min(C_V, C_gpu, C_comm)

if C_comm < min(C_V, C_gpu) → 通信受限 → 用XE(通信量化/稀疏)
if C_V < min(C_gpu, C_comm) → 显存受限 → 用VE(KV量化/稀疏)
if C_gpu < min(C_V, C_comm) → GPU数受限 → 压缩无用，扩硬件
