## P1 执行摘要：结论先行

### 核心观点

权重压缩是推理压缩的**最大也是最早熟的子领域**（占 79% 论文）。INT4 的"普惠红利"已被瓜分（AWQ/GPTQ 成标配），但**"INT4 红海"是被夸大的断言**——新场景（MoE）、新精度（INT2/1-bit）、新机理（异常值/码本）仍在 INT4 量级及以下活跃。竞争焦点转向三个前沿：

- **MoE 权重量化（新场景）**：MoE 模型（DeepSeek-V3/Mixtral）的专家级、路由感知量化是 INT4 量级的活水域（ExpertQuant 等），却被"权重压缩已成熟"的叙事忽视
- **异常值感知的 PTQ（新机理）**：AWQ 显著通道→AAAC 码本→SVD 结构保留，"保护谁"的机理仍在演进
- **极限低比特 / QAT（新精度）**：1.58-bit（BitNet）打破 PTQ 天花板，但**需重训 + 硬件协同**，对多数团队是高门槛

> **修正后的关键洞察**：权重压缩不是"红海已死"，而是"**INT4 通用红利已尽，增量在 MoE 场景 + 异常值机理 + （条件性）1-bit 极限**"。1-bit 路线的价值**取决于团队是否具备重训 + 硬件能力**——不具备则应跟踪观察而非立项。

### 三大战略控制点（按可执行性排序）

- **控制点一：MoE 权重量化（最可执行）** —— 专家级/路由感知量化，新场景，团队量化能力直接迁移，无需重训
- **控制点二：异常值感知的智能保护（PTQ 精度）** —— INT2/INT4 边界的精度护城河，AAAC/SpQR 思路
- **控制点三（条件性）：极限低比特 + 硬件协同（1-bit）** —— **仅当团队有重训 + 硬件能力**才立项；否则跟踪观察。端侧能效护城河深但门槛高

### 三项核心课题

- **N：MoE 专家感知的权重量化**（新场景，最可执行）
- **N+1：异常值感知的 INT2 权重量化**（PTQ 精度突破）
- **N+2（条件）：三值原生训练与硬件协同**（仅当具备重训+硬件能力）

### 一句话结论

> **参数压缩竞争的本质：不是谁量化得更狠，而是谁能在"新场景（MoE）+ 新机理（异常值）"上找到增量；1-bit 极限是高门槛的可选项，不是普适必选项。**

## P2 看趋势：INT4 已成熟，焦点转向极限低比特与异常值

### 核心观点

权重压缩经历了清晰的演进：FP16 → INT8 → **INT4（成熟，AWQ/GPTQ 标配）** → INT2/1-bit（前沿）。INT4 之后的瓶颈不是"算法不够好"，而是两个**物理性障碍**：① 异常值（outlier）使低比特精度崩塌；② PTQ 的精度天花板需要靠训练时量化才能突破。

---

### 前置定义：权重为何要压缩？（修正：不止"部署"）

权重压缩有**两个**作用，而非仅"部署省显存"：

- **① 部署/显存**：70B 模型 FP16=140GB，INT4=35GB（4×↓）—— 解决"装得下"
- **② Prefill/TTFT 提速（被原框架低估）**：**Prefill 阶段是计算/带宽受限的**，权重计算与权重带宽主导该阶段。W8A8/W4A8 联合量化（SmoothQuant 的卖点）直接加速 Prefill、降低 TTFT——这是**运行时收益**，不是"压一次终身受益"能概括的

> **与 KV 的对照（修正版）**：对照轴应是 **Prefill vs Decode**，而非简单的"固定 vs 可变"：
> - **权重压缩** → 主导 **Prefill（TTFT）+ 部署显存**
> - **KV 压缩** → 主导 **Decode（TPOT）+ 并发/长上下文**
> - 两者在不同阶段发力，互补而非"固定 vs 可变"的二分。

> **推论**：把权重压缩框死在"部署"，会错过它在 **TTFT 优化**中的价值——这是原报告（及许多综述）的盲点。

---

### 论据链：公式 → 实测 → 共识（三层硬证据）

#### 第一层：理论——量化误差与异常值（公式推导）

**权重量化误差公式**：
```
量化: ŵ = clamp(round(w/scale), -2^(b-1), 2^(b-1)-1)
误差: ε = w - dequant(ŵ)
MSE = E[ε²] ≈ scale²/12   (均匀量化，bit 数 b 越少 scale 越大)
```
> **机理**：bit 数 b 每减 1，量化步长 scale 翻倍，MSE ×4。所以从 INT4 到 INT2，误差增 4×；到 1-bit，误差暴增。**这是低比特精度崩塌的数学根因**。

**异常值（outlier）放大机理**：
```
正常权重分布: 集中在 [-1, 1]，少量 outlier 在 [-10, 10]
均匀量化: scale 由 outlier 决定 → scale = 20 / 2^b
  → 正常权重的量化粒度被 outlier 撑大 → 正常权重精度崩
```
> **机理结论**：**少数异常值决定了全部权重的量化精度**。这是为何 AWQ/SmoothQuant 的核心都是"处理异常值"——它们不是在压权重，而是在"隔离/迁移异常值"。异常值是低比特的命门。

#### 第二层：工业实测——两条路线的天花板与突破

| 路线 | 代表 | 压缩效果 | 性质 |
|------|------|---------|------|
| **PTQ INT4** | AWQ / GPTQ / SmoothQuant | 4× 内存↓，3× 提速 | 已成熟，精度损失 <1% |
| **PTQ INT2** | QuIP# / AAAC / SpQR | 8× 内存↓ | 精度损失明显，需异常值处理 |
| **QAT 1.58-bit** | BitNet b1.58 | ~10× 内存↓ | 训练时确定，精度好但需重训 |
| **硬件协同** | TOM / BitROM / TeLLMe | 三值→ROM 计算，20+ TOPS/W | 1-bit 与硬件强绑定 |

**AWQ 的精度护城河（为何 1% 显著权重这么关键）**：
```
观察(AWQ): LLM 中"显著权重"(salient)只占 ~1%
误区: 按"权重大小"找显著权重 → 错
正解: 按"激活幅度"找显著通道 → 对
  (大权重不一定重要；被大激活访问的通道才重要)
等价变换: 对显著通道做缩放 s，等价地把误差转移到激活侧
  → 避免 mix-precision(硬件不友好)，用纯 INT4 实现"保护"
结果: INT4 精度损失 <1%，3× 提速，70B 可上移动 GPU
```

#### 第三层：学术界与产业界共识

- **AWQ / GPTQ 已成工业标配**：vLLM、TensorRT-LLM、llama.cpp、SGLang 全部集成 INT4 PTQ
- **GGUF 格式**：llama.cpp 把 INT4/INT2 量化做成消费级（CPU/端侧推理）
- **1-bit 正在工业化**：BitNet b1.58 2B4T 开源；微软推动"原生 1-bit LLM"赛道
- **硬件学界入场**：2025-2026 多篇 ASP-DAC/FPGA 论文（TOM/BitROM/TeLLMe）专做三值硬件，说明 1-bit 已被认为有产业价值

---

### 本页最终推导

```
FP16→INT8→INT4(成熟): 算法红利已尽，AWQ/GPTQ 标配
        ↓
INT4 之后两大物理障碍:
  ① 异常值撑大量化步长 → 低比特崩   (PTQ 路线命门)
  ② PTQ 精度天花板需训练时量化突破   (QAT 路线必要性)
        ↓
焦点分化:
  PTQ 路线 → 异常值感知的 INT2/码本突破(控制点二)
  QAT 路线 → 1-bit 三值化 + 硬件协同(控制点一)
        ↓
中间地带(INT4 微调)已红海，价值在两头
```

### 前提限定

> ⚠️ 本结论适用于**部署/能效导向**的权重压缩。若目标是推理并发/长上下文，权重压缩收益有限（那是 KV 压缩的战场，见 KV 报告）。

### So What

权重压缩的"普惠红利"已尽。下一个价值高低在两头：1-bit+硬件（端侧能效）与异常值感知（PTQ 精度护城河）。中间地带是红海。

## P3 看业界：PTQ 工具链已普及，1-bit 硬件协同兴起

### 核心观点

PTQ（INT4）已是"水电煤"——所有主流框架默认集成；而 1-bit 正在硬件学界催生专门的加速器设计。产业重心从"上量（集成 INT4）"转向"上极限（1-bit 硬件）"。

### PTQ 工具链（已普及）

| 工具/框架 | 集成的权重压缩 | 定位 |
|----------|--------------|------|
| **AWQ** | INT4 weight-only + 显著通道保护 | 精度最优，MLSys 2024 Best Paper |
| **GPTQ** | INT4，二阶/Hessian 误差补偿 | 速度最快，基于 OBQ |
| **SmoothQuant** | 异常值迁移（权重↔激活） | W8A8 联合量化 |
| **GGUF/llama.cpp** | INT4/INT2/Q4_K_M | CPU/端侧消费级 |
| **TensorRT-LLM** | INT4/FP8 weight-only | NVIDIA 生产级 |
| **QuIP#** | INT2/INT4 + 随机性 | 极限低比特 PTQ |

### 1-bit 硬件协同（兴起中）

三值权重 {-1,0,1} 改变了硬件游戏：权重可固化为 ROM 逻辑，做 compute-in-memory：
- **BitROM（ASP-DAC 2026）**：CiROM + BitNet 1.58-bit，20.8 TOPS/W、面积效率 10×、KV-cache 用 eDRAM
- **TOM**：ROM-SRAM 混合，BitNet-2B 达 3306 TPS
- **TeLLMe**：FPGA 三值加速器，1.58-bit 权重 + 8-bit 激活，5W 下 25 tok/s

> **产业信号**：硬件学界为 1-bit 单独设计芯片，说明 1-bit 已被认为**有产业落地价值**（不再是纯学术）。软硬件协同是 1-bit 的真正护城河——三值计算在通用 GPU 上无优势，但在定制硬件上能效碾压。

### 本页推论

```
PTQ INT4: 工具链成熟，是部署默认 → 红海，差异化难
1-bit + 硬件: 硬件学界入场，软硬协同 → 蓝海，护城河深
        ↓
产业重心: 从"集成 INT4"转向"上 1-bit 极限 + 硬件协同"
```

### So What

INT4 工具链已无差异化空间。若要做权重压缩的增量，必须上 1-bit（与硬件绑定）或异常值感知的 INT2。

## P4 看竞争：两条不可调和的路线 + 失效案例

### 核心观点

权重压缩已分化为 **PTQ（后训练） vs QAT（训练时）** 两条路线，各有天花板，中间是红海。

### 路线分化

| 维度 | PTQ 路线 | QAT/1-bit 路线 |
|------|---------|---------------|
| 代表 | AWQ / GPTQ / SmoothQuant / QuIP# | BitNet b1.58 / AAAC(QAT 思路) |
| 改训练？ | 否（事后量化） | 是（原生训练） |
| 成熟度 | INT4 生产可用 | 1.58-bit 研究→硬件协同 |
| 精度天花板 | INT2 明显崩 | 1.58-bit 仍保 85-98% |
| 硬件依赖 | 通用 GPU 友好 | 需定制硬件发挥 |
| 易用性 | 高（无需重训） | 低（需重训） |
| 护城河 | 异常值感知算法 | 软硬件协同 |

### 失效案例集（"为何两条路线各有命门"）

**案例 1：naive INT2 PTQ 精度崩塌（异常值之祸）**
```
设定: 直接均匀量化到 INT2
现象: 精度从 FP16 的 X 暴跌到 <0.5X
机理: 少量异常值(-10,+10)撑大 scale → 正常权重(±1)全压到 0
      → 信息丢失
对照: AWQ/SmoothQuant 先隔离异常值 → INT2 精度可接受
结论: 异常值是 INT2 的命门；不处理异常值的 INT2 不可用
```

**案例 2：PTQ 在极限低比特（<2bit）的天花板**
```
现象: PTQ 压到 <2bit 时，无论怎么调，精度都明显掉
机理: PTQ 不能改权重分布 → 低比特信息密度不够
对照: BitNet 训练时就把权重收敛到三值 → 分布天然适配 1.58-bit
结论: 极限低比特(1-2bit)的精度，PTQ 触不到，必须 QAT
```

**案例 3：1-bit 在通用 GPU 上无优势**
```
现象: BitNet 三值权重在 A100/H100 上跑，并不比 INT4 快多少
机理: 通用 GPU 的 tensor core 为 INT4/INT8 优化，三值无专用单元
对照: 定制 ROM 硬件(BitROM)上，三值能效碾压(TOPS/W 10×+)
结论: 1-bit 的红利必须靠硬件协同兑现，通用 GPU 上是"空有精度"
```

> **失效案例的战略含义**：案例 1 证明 PTQ 必须处理异常值（控制点二）；案例 2 证明极限低比特必须 QAT（控制点一）；案例 3 证明 QAT 红利必须硬件协同。三者共同定义了两条路线的能力边界。

### 竞争本质

```
PTQ: 易用 + INT4 成熟，但 INT2 受异常值所限 → 异常值感知是护城河
QAT: 1-bit 精度好，但需重训 + 硬件协同 → 软硬协同是护城河
中间(INT4 微调): 红海，无差异化空间
```

### So What

权重压缩已无"中间地带"机会。要么深耕 PTQ 异常值（精度护城河），要么押注 1-bit+硬件（端侧能效护城河）。

## P5 看技术：四根技术 × 异常值机理 × MoE 新场景

### 核心观点

权重压缩的**四根技术（量化/剪枝/低秩/蒸馏）已全部成熟甚至饱和**，但**驱动量化的"异常值处理"机理仍在演进**，且 **MoE 架构带来了权重压缩的新场景**。根技术稳定，机理与新场景是注入新价值的两个维度。

### MoE 权重量化：被"红海叙事"忽视的活水域（控制点一）

**为何 MoE 权重是独立战场**：MoE 模型（DeepSeek-V3 671B/激活 37B、Mixtral、Kimi K2）的权重压缩有 Dense 模型没有的特殊性：

| MoE 权重压缩特殊性 | Dense 模型不存在的问题 |
|------------------|---------------------|
| **专家级量化** | 每个专家独立，激活频率不同 → 低频专家可更激进量化 |
| **路由感知** | 量化噪声影响 Gate 路由决策（见多卡报告 Rank-Aware）→ 权重量化与路由稳定性耦合 |
| **专家剪枝** | 整个专家可被合并/删除（expert dropping），Dense 无此粒度 |
| **激活稀疏** | 每 token 仅激活少数专家 → 等效"权重稀疏"天然存在 |

- **ExpertQuant（库内多卡报告引用）**：W4A4 专家量化，精度损失 <1%——证明 MoE 权重量化在 INT4 量级可行且有效
- **空白**：MoE 专家级**混合精度**（高频专家高精度、低频专家低精度）、专家剪枝与量化的联合，仍是前沿
- **战略含义**：MoE 是权重压缩在 INT4 量级的**新场景增量**，直接反驳"INT4 已死"——它不是新精度，而是新对象（专家）

> **修正**：原报告说"INT4 中间地带红海"是过强断言。MoE 权重量化证明 INT4 量级在新架构上仍是活水域。控制点一（MoE）因此是最可执行的增量。

### 四根技术成熟度

| 根技术 | 论文数（知识库） | 代表 | 状态 |
|--------|---------------|------|------|
| **低秩** | 575 | LoRA 系（适配，非压缩）、SVD 压缩 | 高度饱和 |
| **剪枝** | 509 | SparseGPT、结构化/非结构化 | 成熟 |
| **量化** | 376 | AWQ、GPTQ、SmoothQuant、QuIP# | INT4 成熟，INT2/1-bit 前沿 |
| **蒸馏** | 231 | Logits 蒸馏、横向压缩 | 成熟 |

### 压缩信号演进（主线：如何识别"重要权重"）

| 年份 | 信号 | 代表 | 本质 |
|------|------|------|------|
| 2022 | 权重幅度 | 早期剪枝、magnitude pruning | 按 |w| 找重要 |
| 2023 | **激活感知** | **AWQ**（按激活找显著通道） | 被大激活访问的才重要 |
| 2023 | 二阶敏感性 | GPTQ（Hessian）、SpQR | 按误差贡献找重要 |
| 2023 | 异常值迁移 | SmoothQuant | 把异常值从激活迁到权重 |
| 2024 | 结构/码本 | AAAC（自适应码本）、SVD 保留 | 用内在结构做显著性代理 |
| 2024+ | 训练时收敛 | BitNet（三值原生训练） | 让分布天然适配低比特 |

> **演化主线**：从"按权重自身幅度"→"按激活/误差贡献"→"按内在结构"→"训练时重塑分布"。信号越来越接近"权重的真实功能重要性"。

### 机理工作示例

**示例 1：AWQ 如何用激活识别显著通道（精度护城河的机理）**
```
权重 W ∈ R^(out, in)，激活 x ∈ R^in
naive: 按权重大小找重要 → |W[:,j]| 大的保留
AWQ:  按激活找 → ||x_j|| 大的通道 j 重要(被高频访问)
机理: 大权重若不被激活访问，量化它无妨；
      小权重若被大激活访问，量化它误差被放大到输出
等价保护: 对通道 j 乘缩放 s_j,
          W'[:,j] = W[:,j]·s_j,  x'_j = x_j/s_j  (输出不变)
          → 等效地把该通道权重"放大"，量化粒度变细 → 受保护
结果: 仅 1% 通道受保护，INT4 精度损失 <1%
```
> **机理要点**：AWQ 的精髓不是"找重要权重"，而是"用等价缩放把保护伪装成均匀量化"——避免 mix-precision 的硬件不友好。

**示例 2：SmoothQuant 的异常值迁移（W8A8 联合量化的机理）**
```
问题: 激活有异常值(某些通道激活极大) → INT8 激活量化崩
SmoothQuant: 把激活的异常值"迁"到权重侧
  W' = W·diag(s),  x' = x/diag(s)
  → 激活变平滑(异常值被 s 压), 权重变尖(吸收异常值)
  → 权重本就分布平稳, 吸收异常值后仍可 INT8
结果: W8A8 联合 INT8, 精度无损, 计算加速
```

**示例 3：BitNet 三值原生训练（为何 QAT 能触达 1.58-bit）**
```
BitNet b1.58: 训练时权重约束为 {-1, 0, +1}
  前向: 用三值权重 + 直通估计(STE)反向
  训练过程: 权重分布被"拉"向三值聚点
机理: 训练把权重分布重塑为天然适配 1.58-bit
      → 不存在"PTQ 硬压"的信息丢失问题
代价: 必须从头训练(或重训), 不能事后套用
红利: 内存 ~10×, 且定制硬件上能效碾压
```

## P6 看机会：极限低比特 + 异常值感知 = 两个增量方向

### 核心观点

权重压缩的中间地带（INT4）已红海。两个增量方向：① 极限低比特+硬件协同（端侧能效）；② 异常值感知（PTQ 精度护城河）。

### 机会一：极限低比特 + 硬件协同（控制点一）

- **传统思路**：PTQ 压到 INT4 → 已无差异化
- **下一阶段**：**1.58-bit 原生训练 + 定制硬件** → 端侧能效护城河

**关键机会点**：
```
BitNet 已证明 1.58-bit 精度可行(85-98%)
硬件学界已入场(TOM/BitROM/TeLLMe, 20+ TOPS/W)
但: 通用 GPU 上无优势 → 必须软硬件协同
   三值权重 + ROM compute-in-memory 是端侧的唯一路线
```

### 机会二：异常值感知的 INT2（控制点二）

- **传统思路**：均匀量化到 INT2 → 异常值撑崩
- **下一阶段**：**异常值感知的码本/结构保护** → PTQ 触达 INT2

**关键机会点**：
```
AWQ 的"显著通道保护"是异常值处理的 v1(保护 1%)
AAAC 的"自适应码本"是 v2(每层学两个码本)
SVD 保留是 v3(用内在结构做显著性, 无需校准数据)
但: INT2 的精度护城河仍未稳固 → 谁定义了"异常值保护标准"谁占位
```

### 压缩对象 × 方法 × 路线 机会矩阵

| 路线＼方法 | 量化 | 剪枝 | 低秩 | 蒸馏 |
|----------|------|------|------|------|
| **PTQ（事后）** | AWQ/GPTQ(饱和) | SparseGPT(成熟) | SVD 压缩(饱和) | 横向蒸馏(成熟) |
| **异常值感知 PTQ** | AAAC/QuIP#(新兴) | — | SVD 保留(新兴) | — |
| **QAT（训练时）** | BitNet 1.58(新兴) | 训练时剪枝 | — | 蒸馏+量化 |

> **空白点**：异常值感知 INT2、1-bit 软硬件协同——两个高机会方向。

### Why Us（团队优势）

| 已有能力 | 迁移方向（权重压缩） | 复用程度 |
|---------|-------------------|---------|
| 模型量化 | 异常值感知 INT2、W8A8 | 高 |
| 稀疏优化 | 训练时剪枝、结构化稀疏 | 中高 |
| 推理 Runtime | INT4 kernel、三值算子 | 中 |
| 硬件协同（若有） | 1-bit 定制算子 | 视团队硬件能力 |

### 本页推论

权重压缩增量在两头：1-bit+硬件、异常值感知 INT2。中间红海。

### So What

越早把"异常值保护标准"或"1-bit 软硬件栈"做出来，越难复制——饱和领域的护城河来自"标准"和"栈"。

## P7 战略总结：收敛为三大战略控制点（按可执行性）

### 控制点一：MoE 权重量化（最可执行，新场景）

- **解决问题**：INT4 通用红利已尽，但 MoE 架构带来权重压缩新场景（P5）
- **核心指标**：MoE 模型显存、专家级量化精度损失
- **技术抓手**：专家级混合精度、路由感知量化（与多卡报告 Rank-Aware 联动）、专家剪枝
- **为何最可执行**：无需重训，团队量化能力直接迁移，ExpertQuant 已证 W4A4 可行

### 控制点二：异常值感知的智能保护（PTQ 精度）

- **解决问题**：INT2 精度崩塌（异常值撑大 scale，P2 公式推导）
- **核心指标**：INT2 精度损失、量化时间、无需重训
- **技术抓手**：显著通道保护（AWQ）、异常值迁移（SmoothQuant）、自适应码本（AAAC）、结构保留（SVD）

### 控制点三（条件性）：极限低比特 + 硬件协同（1-bit）

- **解决问题**：PTQ 精度天花板；端侧能效
- **⚠️ 立项条件**：**仅当团队具备①从头重训能力 + ②硬件协同能力**。两者缺一则降级为"跟踪观察"
- **核心指标**：端侧能效（TOPS/W）、1.58-bit 标准基准精度（待核，见 P9 挑战 5）
- **技术抓手**：三值原生训练（BitNet）、ROM compute-in-memory、三值 kernel

### 三大控制点的关系与优先级

```
控制点一(MoE 权重):     新场景，最可执行，P0 优先      ← 团队直接能做
控制点二(异常值感知):   PTQ 精度护城河，P0 优先        ← 团队直接能做
控制点三(1-bit,条件):   高门槛，仅当有重训+硬件能力     ← 否则跟踪观察
          ↓
权重压缩增量 = MoE 新场景 + 异常值精度 + (条件)1-bit 极限
```

### Why Now（修正：移除"硬件学界入场=产业信号"的过强推断）

| 机会窗口 | 原因 | 诚实标注 |
|---------|------|---------|

### 三类增量 = 三个护城河（强度递减）

```
增量一: MoE 权重量化(新场景，最可执行)
```

## P8 课题规划

### 课题一：MoE 专家感知的权重量化技术（P0，最可执行）

#### 关键挑战

MoE 模型权重压缩的特殊性未被通用 PTQ 方法覆盖：每个专家激活频率不同（低频专家可更激进量化）、量化噪声影响 Gate 路由（与多卡报告 Rank-Aware 问题耦合）、专家可整体剪枝。**通用 AWQ/GPTQ 把所有专家等同处理，浪费了 MoE 的结构信息**。ExpertQuant 已证 W4A4 专家量化可行（精度损失<1%），但专家级混合精度、专家剪枝-量化联合仍是空白。

#### 技术目标

对 DeepSeek-V3/Mixtral 类 MoE 模型：
- MoE 权重显存降低 **50%+**（等效 INT4 及以下）
- 精度损失 **<1%**（vs FP16）
- 路由稳定性不受损（Jaccard >0.9）

#### 关键技术

**1 专家激活频率标定**：统计各专家激活频次，低频专家→更激进量化（INT2/3），高频专家→INT4。
**2 路由感知量化**：量化约束保护 Gate top-k 排名稳定（联动多卡报告 Rank-Aware Jaccard Loss）。
**3 专家剪枝-量化联合**：极低频专家整体剪枝 + 其余量化。

#### 关键假设与验证

| # | 假设 | 验证 | 风险 |
|---|------|------|------|
| H1 | 专家激活频率呈长尾（少数高频）| 实测激活分布 | 低 |
| H2 | 低频专家激进量化不影响精度 | 频率×精度消融 | 中 |
| H3 | 路由感知量化与 Rank-Aware 正交叠加 | 联合消融 | 中 |

#### 风险与缓解

| 风险 | 缓解 |
|------|------|
| 专家激活跨任务变化 | 多任务标定 + 软分配 |
| 路由翻转 | 接入 Rank-Aware 约束（见多卡报告）|

---

### 课题二：异常值感知的 INT2 权重量化技术（P0）

#### 关键挑战

INT2 PTQ 的命门是异常值（P2 公式推导）：少量异常值撑大 scale，使正常权重精度崩塌。AWQ 的"显著通道保护"是 v1（保护 1%），AAAC 的"自适应码本"是 v2（每层学码本），但**INT2 的精度护城河仍未稳固**——"保护谁、保护多少、怎么保护"没有统一标准。naive INT2 精度崩到 <0.5X，异常值处理是唯一出路。
**⚠️ 需求前提（挑战 4）**：INT2 的立项前提是存在"INT4 不够、必须 INT2"的真实场景（如 70B 进手机/极小显存）。**立项前需先验证 INT2 的市场需求**，否则可能是寻找问题的解。

#### 技术目标

对 7B-70B 模型、云端推理场景：
- INT2 量化精度损失 **<2%**（vs FP16）
- 量化时间 **<1 小时/70B**（vs QuIP# 数小时）
- 无需重训（PTQ 路线）

#### 关键技术

**1 异常值检测与隔离**：按激活幅度 + Hessian 敏感性双重检测异常通道，高精度保留（FP16/INT8）。
**2 自适应码本**：每层学少量码本（AAAC 思路），权重选最优码本量化，降低 MSE。
**3 稀疏异常值保留**：少量异常权重用稀疏格式单独存（SpQR 思路），其余 INT2。

#### 关键假设与验证

| # | 假设 | 验证 | 风险 |
|---|------|------|------|
| H1 | 异常通道占 <5% | 实测激活分布 | 低（AWQ 已证 ~1%）|
| H2 | 自适应码本优于固定 INT2 | 同比特对照 | 中 |
| H3 | 稀疏异常值 + INT2 正交可叠加 | 联合消融 | 中 |

#### 风险与缓解

| 风险 | 缓解 |
|------|------|
| 稀疏格式硬件不友好 | 限制稀疏比例 <5%，用查表 |
| 码本学习需校准数据 | 备 SVD 无数据方案 |
| INT2 在某些任务崩 | 任务门控，关键层保 INT4 |

### 课题三：三值（1.58-bit）原生训练与硬件协同（⚠️ 条件性，仅当有重训+硬件能力）

#### 关键挑战

1-bit 的红利必须靠硬件协同兑现（P4 案例3：通用 GPU 上无优势）。BitNet 已证 1.58-bit 精度可行，但**从训练到硬件的全栈尚未打通**——三值 kernel 在通用 GPU 上无加速，需定制 ROM 算子；训练时收敛技巧（STE、随机舍入）仍需优化。

#### 技术目标

对端侧/能效导向场景：
- 三值模型精度保持 **≥90%**（vs FP16 同规模）
- 定制硬件能效 **>10 TOPS/W**
- 内存 **~10×↓**

#### 关键技术

**1 三值原生训练**：BitNet b1.58 思路 + 随机舍入（Direct Quantized Training, 2412.04787）降训练显存。
**2 三值 kernel / ROM 算子**：与硬件团队协同，三值→ROM compute-in-memory（BitROM 思路）。
**3 蒸馏辅助收敛**：FP teacher 引导三值 student（BitVLA 的 Quantize-then-Distill 思路）。

#### 关键假设与验证

| # | 假设 | 验证 | 风险 |
|---|------|------|------|
| H1 | 三值训练可收敛到 ≥90% | 训练小模型验证 | 中（BitNet 已证可行）|
| H2 | 定制算子能效 >10 TOPS/W | 硬件仿真 | 高（依赖硬件团队）|
| H3 | 蒸馏提升收敛 | 蒸馏 vs 直接三值 | 中 |

#### 风险与缓解

| 风险 | 缓解 |
|------|------|
| 依赖硬件团队 | 分阶段：先软件三值+kernel，硬件协同后续 |
| 训练成本高 | 随机舍入降训练显存；小规模先验证 |
| 通用 GPU 无加速 | 明确定位端侧/定制硬件场景 |

## P9 风险与前提限定

### 权重压缩 vs KV 压缩：定位对照（修正：Prefill vs Decode 轴）

| 维度 | 权重压缩 | KV 压缩 |
|------|---------|--------|
| 主导阶段 | **Prefill（TTFT）+ 部署显存** | **Decode（TPOT）+ 并发/长上下文** |
| 主要收益 | 装得下 + Prefill 提速（W8A8/W4A8）| 跑得动 + 并发得起 |
| 成熟度 | INT4 已生产 | 量化成熟，自适应/复用新兴 |
| 增量方向 | MoE 权重 / 异常值 INT2 / (条件)1-bit | 全生命周期 / 结构化自适应 |

### 核心前提限定

> ⚠️ 本报告结论受以下前提约束：

1. **场景前提（修正）**：权重压缩收益在**部署显存 + Prefill/TTFT 提速**。若目标是 Decode/并发/长上下文，权重压缩收益有限（KV 是瓶颈，见 KV 报告）。
2. **路线前提**：1-bit 路线**必须硬件协同 + 重训能力**才能兑现红利（通用 GPU 上无优势）。
3. **数据前提**：所有数字来自公开论文，**BitNet 85-98% 来自 BitRL 边缘论文，非标准基准**（见自我挑战 5）。
4. **课题未验证前提**：MoE 量化、异常值 INT2、三值+硬件为前瞻课题，效果待验证。

| 5 | BitNet 85-98% 有挑选嫌疑（BitRL 边缘，非标准基准） | 数据表加**诚实标注**；控制点三指标注明"标准基准待核" |
| 6 | "硬件学界入场=产业信号"逻辑弱（学术芯片多不量产） | Why Now 表加**诚实标注**：学术硬件≠量产，产业化待验证 |

> **方法论启示**：洞察报告应内置红队——任何"控制点/课题"都需问"团队是否执行得了""需求是否真实""数据是否挑选"。本报告的 1-bit 路线正是经此检验后被降级的。
3. **数据前提**：所有数字（AWQ 3×、BitNet 10-16×、BitROM 20.8 TOPS/W）来自公开论文，未外推。
4. **课题未验证前提**：异常值 INT2、三值+硬件协同为前瞻课题，效果待验证。

### 主要风险与对策

| 风险 | 对策 |
|------|------|
| INT4 红海，差异化难 | 明确押两头（1-bit / INT2 异常值），不碰中间 |
| 1-bit 依赖硬件 | 课题二定位预研，与硬件团队分阶段协同 |
| 异常值标准竞争 | 尽早开源 + 基准，抢占"异常值保护标准" |

### 反向论点（Devil's Advocate，已与自我挑战对齐）

| 反向论点 | 回应（修订后）|
|---------|------|
| "INT4 已够用，权重压缩没增量" | **部分成立**：通用 INT4 红利已尽，但 MoE 权重（控制点一）是新场景增量；端侧 INT4 仍太重（70B 仍 35GB）|
| "BitNet 1-bit 是学术玩具" | **无法简单反驳**：学术硬件论文多不量产（挑战6），1-bit 产业化待验证；通用 GPU 上无优势。**故降级为条件性控制点** |
| "异常值 INT2 精度永远不够" | AAAC/SVD 显示 INT2 可逼近 INT4，但**INT2 需求本身待证**（挑战4）|
| "权重压缩不如 KV 压缩重要" | 两者在不同阶段发力：权重→Prefill/部署，KV→Decode/并发，**不可替代**（修正：非简单"固定 vs 可变"）|

### 附录 E：关键术语表

| 术语 | 定义 |
|------|------|
| PTQ（Post-Training Quantization）| 后训练量化，不改训练，事后压权重 |
| QAT（Quantization-Aware Training）| 训练时量化，把量化纳入训练 |
| 异常值（outlier）| 少数幅度极大的权重/激活，撑大量化步长致精度崩 |
| 显著权重（salient weight）| 被大激活访问的通道（AWQ 定义），占 ~1% |
| 三值化（ternary）| 权重约束为 {-1,0,1}，1.58 bit |
| compute-in-memory | 权重固化进 ROM/存内计算，三值专用 |
| 码本（codebook）| 量化级的映射表，自适应码本每层学习 |
