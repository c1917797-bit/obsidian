## 报告使用说明

### 报告定位
本报告是**季度级别**的技术规划文档，用于：
- 课题立项决策（是否做、怎么做、谁来做）
- 跨团队共识（算法/工程/产品/业务）
- 资源申请（GPU×月、人头、预算）
- 复盘依据（季度回测、历史对比）

### 报告结构（三段式 + 附录）


## 1. 洞察 (Insights)

> ⚠️ **强制要求**：洞察部分必须**严格按照 `方法论/输入/技术洞察模版.md` 的五看三定框架生成**。
>
> **不要自创结构，不要简化五看，不要遗漏三定。直接使用该模版。**
>
> 模版路径：`方法论/输入/技术洞察模版.md`
> 模版定义的五看三定框架：
> - 五看（每看≥800字）：看行业/趋势 → 看市场/客户 → 看竞争/对手 → 看自己/能力 → 看机会/综合
> - 三定（战略输出）：定战略控制点 → 定目标 → 定策略
>
> 同时遵循 `方法论/输出/洞察写作指南.md` v1.5 的质量要求：
> - 7 要素：反直觉 + 论文数字 + 因果链 + 边界 + 行动 + 实例 + 业界案例≥2-3
> - 每看≥800字
> - ❌ "KV Cache 占用大量显存"（常识，无实例）
> - ✅ "[实测] Qwen-72B 128K KV=82GB，per-channel 4-bit 后 LongBench 掉 0.7%"
>
> **生成报告时必须先读取技术洞察模版.md，然后按其五看三定框架展开。**

#### 维度 19 详解：框架能力 vs 自研

> 这是工程化课题**最常被挑战**的维度——"成熟框架已经有了，为什么重复造轮子？"

**红军典型挑战**：
- "vLLM 已经内置 FP8 量化（v0.5+），为什么你自己做？"
- "NVIDIA TensorRT-LLM 已经有 INT8/FP8/INT4 支持，为什么不用？"
- "HuggingFace bitsandbytes 一行代码 `load_in_4bit=True` 就能量化，为什么要自研？"
- "DeepEP 已经开源了 MoE 通信库，为什么你自己做？"
- "SGLang 已经有 RadixAttention 做 KV 复用，为什么要自己做 Agent 跨轮 KV？"

**蓝军防守的 4 个层次**：

| 层次 | 防守逻辑 | 示例 |
|------|---------|------|
| **① 框架做不到** | 框架确实没有这个能力 | "vLLM 没有 Agent 跨轮 KV 共享——所有现有 KV 压缩都假设单轮场景" |
| **② 框架做得不好** | 框架有但不满足我们的场景 | "vLLM 支持 FP8 但不支持 W×K 联合 padding 优化——我们的场景需要联合优化多省 12.6%" |
| **③ 框架不可控** | 用框架=被框架绑架 | "TensorRT-LLM 闭源，NVIDIA 更新节奏不可控；我们需要自主可控的量化 pipeline" |
| **④ 自研有增量价值** | 在框架基础上做增强 | "基于 vLLM PagedAttention 扩展，不是从零做——增量是联合优化+MoE gate 保护" |

**判断标准**（是否应该自研）：

```
如果框架完全能做到 → 用框架，不自研 ❌
如果框架做不到但有替代方案 → 用替代方案
如果框架做不到且无替代 → 自研 ✅
如果框架做得到但不可控/不满足 → 基于框架扩展 ✅
```

## 写作指南

### 章节字数建议
- 一页纸摘要: 300-500 字
- 1. 洞察: 2000-4000 字
- 2. 总结: 1500-2500 字
- 3. 课题规划: 2000-4000 字
- 4. 附录: 不计入正文

### 必含元素
- [ ] 综合得分 ≥ 8 的 P0 课题必须写假设+验证+保险
- [ ] 反方证据 ≥ 11 的课题必须写备选方案
- [ ] 时间窗超过中期的课题必须写阶段性验收
- [ ] 资源规划必须给到 GPU×月级别

### 常见错误
- ❌ 写"我们想做什么"（应写"业务约束是什么"）
