### 2.4 默认跳过

- 纯营销稿、无 primary source 的二手转述
- 48 小时内无 primary source 的新闻
- Memory 近 **7 天**已推送过的同一事件
- 标题党（「颠覆 XXX」「取代 XXX」）未核实时间线和适用范围

### 2.5 来源要求

每条至少 1 个 primary source URL:
- 官方博客 / 官方文档 / Changelog
- GitHub Release / Security Advisory
- 论文（arXiv、ACL、NeurIPS、ICML、ICLR 等）
- 权威媒体深度稿（须能追溯到 primary source，否则降级或跳过）

### 2.6 硬性规则

1. **每条必须 web 核实**，附 1 个 primary source URL
2. **48 小时内**新闻优先；更早的须标注「背景补全」
3. **去重判断**（满足任一则视为同一事件）:
   - 标题关键词重叠 ≥ 3 个（如 "GPT-5" + "OpenAI" + "发布"）
   - 核心事实相同（同一公司/产品的同一事件）
   - 同一 primary source 的同一内容的不同报道
4. **质量底线**:
   - 至少 **2 条**能让人学到**新概念或新判断**
   - 至少 **1 条**明确写「可跳过」
   - 不允许只有标题没有来源

## 三、体量与节奏

### 每日（5-8 条）

- 涵盖: 热点事件(1-3) / 热点技术(2-4) / 热点方向(1-2)
- 其中至少 **1-2 条**来自顶会论文（NeurIPS / ICML / ICLR / ACL / CVPR）
- 论文优先级: arXiv 新论文 > 会议官方公告 > 权威解读
- **深度 + 热点 > 广度**，宁缺毋滥
- 若当日确实无新概念，降级为 3 条，文末说明「今日深度条目不足，仅作快讯」

### 每周（周六/周日）

- **1 条「深读」**: 论文 / Release Note / 架构文
- 格式: 热点技术专用格式 或 热点事件专用格式
- 「知识」可写 3-4 句，「行动」默认写「深读」

### 每月（最后一周）

- **1 条「趋势综述」**: 在 Agent 栈 / 推理成本 / 推理框架中选横切主题
- 格式: 热点方向专用格式，300-500 字

## 四、格式定义

### 4.1 格式选择指引

| 场景 | 推荐格式 |
|------|----------|
| 简单新闻快讯 | 标准格式 |
| 新模型/工具/框架发布 | 热点技术专用格式 |
| 重大公司事件/人事变动 | 热点事件专用格式 |
| 行业趋势/技术路线分析 | 热点方向专用格式 |

---

### 4.2 标准格式

```
【分类】标题(一句话)

- **前沿点**: 新在哪里(1 句)
- **趋势**: 说明什么方向(1 句)
- **知识**: 核心概念(1-2 句)
- **与我**: 和 AI/推理优化的关系(1 句;无关写「可跳过」)
- **行动**: [无/观察/升级/试玩/深读] + 具体建议
- **来源**: <primary source URL>
- **置信度**: 高 / 中(传闻、未签约、仅泄露标「中」)
- **信号等级**: 🔴核心 / 🟡关注 / 🟢观察
```

适用: AI-Agent / LLM推理 / 多模态推理 / 模型压缩 / 推理框架

---

### 4.3 热点技术专用格式

```

[一句话总结]: 2026年X月，【发布者】发布了【技术名】，用于【目的】，实现了【核心效果】。

[关键词]: 关键词1、关键词2、关键词3、关键词4、关键词5（5-8个）

[业务启示]:
- 【维度1】: 2-3句话
- 【维度2】: 2-3句话
（2-4个维度）

[背景介绍]:
【技术名】是【发布者】推出的【类型】，用于【目的】。此前【历史背景】，现在【新进展】。（100-150字）

[技术和创新点]:
1. 【技术点1】: 一句话描述（详细说明）
2. 【技术点2】: 一句话描述（详细说明）
（3-6个技术点）

[效果总结]:
【技术名】在【性能/效率/能力】方面有显著提升。（80-120字）

---
- **来源**: <primary source URL>
- **置信度**: 高 / 中
- **信号等级**: 🔴核心 / 🟡关注 / 🟢观察
- **行动**: [无/观察/升级/试玩/深读] + 具体建议
```
