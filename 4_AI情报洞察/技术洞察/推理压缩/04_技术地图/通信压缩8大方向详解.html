本质：减少每次传输的比特数 BF16→FP8→INT4→INT2。通信量 = 数据量 × bit数，量化降低的是bit数。

3
单Kernel通信计算融合

本质：消除通信等待 不减少通信量，而是让dispatch→compute→combine在一个Kernel内流水线执行，零launch开销。
传统问题：三步串行（dispatch→等→compute→等→combine），GPU大部分时间在等通信完成。
FlashMoE突破 NeurIPS 2025 · arXiv:2506.04667
1个持久GPU Kernel完成全部dispatch→compute→combine。GPU端直接发起RDMA绕过CPU。细粒度流水线重叠通信与计算。

4
压缩上下文跨GPU传递

本质：减少传输的数据维度 长上下文分布式推理中，跨GPU传的不是完整KV而是压缩后的KV表示。
问题：128K上下文×70B模型 = 每对GPU需传10GB KV（25Gbps RDMA需3.2s）→ TTFT被KV传输主导。

5
同步点丢弃

本质：直接跳过某些通信 张量并行中每个attention block后都要AllReduce同步，但某些同步点可以安全跳过。
问题：LLM-70B张量并行8卡，每层2次AllReduce（attention+FFN），80层=320次AllReduce/token。
SPD (Sync-Point Drop)学术 arXiv:2502.20727
测量每个block的同步敏感度→低敏感block跳过AllReduce→高敏感block保留。Block设计允许跳过。
# 传统：每层都AllReduce Block 0 → AllReduce → Block 1 → AllReduce → Block 2 → ... # SPD：选择性丢弃 Block 0 → AllReduce → Block 1 → [跳过] → Block 2 → AllReduce ↑ 低敏感度：跳过后误差可被后续block吸收

7
通信-计算重叠调度

本质：隐藏通信延迟 不减少通信量，而是让通信和计算同时进行——通信时间被计算时间"吸收"。
DeepSeek DualPipe业界 DeepSeek-V3生产部署
计算和通信反向流水线执行。Prefill的前向计算与上一层的通信重叠。
# DualPipe核心思路 正向：Attention计算 ←重叠→ 下一层MoE dispatch通信 反向：梯度计算 ←重叠→ 上一层通信 → 通信时间被计算时间完全吸收
生产验证：DeepSeek-V3实际部署，通信开销从>40%降至接近0%（被计算完全隐藏）。

8
全复制打破

本质：改变通信范式 从"每个GPU全复制所有Expert"（用空间换通信）到"按拓扑分区放置"（减少通信总量）。
问题：DeepSeek-V3有256 Expert，全复制=每GPU 128GB Expert参数→显存浪费巨大。
FoMoE突破 ICLR 2026
打破全复制范式。Expert分区放置 + skip-token机制。通信↓1.42~45.44x。
# 传统全复制 GPU 0: Expert[0-255] 全部复制 GPU 1: Expert[0-255] 全部复制 → 每个Token路由到任意Expert都local（但显存巨大） # FoMoE分区 GPU 0: Expert[0-63] GPU 1: Expert[64-127] → Token路由到非本地Expert才通信 → skip-token: 某些Token直接跳过（不路由到任何Expert）

8个方向的本质区别：

减少通信数据量：①量化(bit↓) + ④压缩KV传递(维度↓) + ⑥PD传输(内容↓)
减少通信次数：⑤同步点丢弃(某些不做) + ⑧全复制打破(改范式)
隐藏通信延迟：③单Kernel融合(零等待) + ⑦通信计算重叠(被吸收)
减少跨节点通信：②路由感知协作(共激活放同节点)

方向间正交性：8个方向可以任意组合。例如：①(INT4量化) + ②(共激活配对) + ③(单Kernel) = 理论极限。
