## ★★ KVQuant — 10M上下文：亚4-bit量化的极限探索

**论文**：KVQuant: Towards 10 Million Context Length LLM Inference with KV Cache Quantization
**ID**：arXiv:2401.18079
**发表**：ICML 2024

### 四大协同技术

| 技术 | 原理 | 解决的问题 |
|------|------|-----------|
| Per-Channel Key量化 | 沿channel分组量化 | Key的channel异常值（呼应KIVI） |
| Pre-RoPE量化 | 在RoPE旋转之前量化 | RoPE放大了Key的异常值 |
| 非均匀数据类型 | 按层灵敏度加权设计 datatype | 不同层/位置的分布差异 |
| Dense-and-Sparse分离 | 每向量分离异常值 | 少数极端异常值不拖累整体 |

### 关键数据

| 指标 | 结果 |
|------|------|
| 3-bit精度损失 | **<0.1 PPL**（Wikitext-2/C4）|
| LLaMA-7B单A100 | **1M上下文** |
| 8-GPU系统 | **10M上下文** |
| 自定义CUDA Kernel | **~1.7×加速** vs FP16 |

### 与KIVI的关系

KIVI发现K/V分布差异 → KVQuant进一步发现**RoPE是Key异常值的元凶** → Pre-RoPE量化。两者互补。

## ★★ QJL — 1-bit JL变换：零开销KV量化

**论文**：QJL: 1-Bit Quantized JL Transform for KV Cache Quantization with Zero Overhead
**ID**：arXiv:2406.03482

### 核心创新

```
传统量化: 每组需要存储 scale + zero-point → 额外1-2 bit开销
QJL:      Johnson-Lindenstrauss变换 + 符号量化(1-bit)
          → 无需存储量化常数 → 零开销
          → 非对称估计器: QJL处理一侧, 标准JL处理另一侧 → 无偏
```

### 关键数据

| 指标 | 结果 |
|------|------|
| KV总比特 | **3-bit** |
| KV内存减少 | **>5×** |
| 精度 | 无损 |
| 运行时开销 | 比FP16更快 |

## ★★ Quest — Query感知稀疏：动态选择关键页

**论文**：Quest: Query-Aware Sparsity for Efficient Long-Context LLM Inference
**ID**：arXiv:2406.10774

### 核心创新

跟踪KV Cache每页的Key最大/最小值 → 用当前Query估计每页重要性 → 只加载Top-K页。

```
传统(H2O): 基于历史attention score → query无关
Quest:    基于当前query与key page的范围关系 → query感知
          → 更精确地选择当前query真正需要的token
```

### 关键数据

| 指标 | 结果 |
|------|------|
| Self-attention加速 | **2.23×** |
| 推理延迟降低 | **7.03×** |
| 精度损失 | 可忽略 |

## ★★ Quamba — SSM量化：Mamba的后训练量化

**论文**：Quamba: A Post-Training Quantization Recipe for Selective State Space Models
**ID**：arXiv:2410.13229

### 核心创新

第一个面向SSM的量化方法。发现SSM的独特挑战：
- selective scan机制中的特征图高度敏感
- 输出激活有self-attention中不存在的异常值

方案：8-bit per-tensor + 输入抑制 + Hadamard变换去异常值。

### 关键数据

Mamba 2.8B → 8-bit → Orin Nano上 **1.72×延迟降低**，精度仅降0.9%。

## ★★ MELODI — 层次化记忆：短期×长期双压缩

**论文**：MELODI: Exploring Memory Compression for Long Contexts
**ID**：arXiv:2410.03156

### 方案

```
短期记忆: 跨层循环压缩上下文窗口（平滑过渡）

```

vs Memorizing Transformer(64K KV pairs) → **8×内存减少**，性能更优。

## ★★★ FlashMoE — 单Kernel分布式MoE：通信计算融合

**论文**：FlashMoE: Fast Distributed MoE in a Single Kernel
**ID**：arXiv:2506.04667
**发表**：NeurIPS 2025

### 问题：MoE All-to-All通信瓶颈

```
传统MoE执行流程（bulk-synchronous）：
  Dispatch(token→expert) → 等待 → Expert计算 → 等待 → Combine(expert→token)
  
问题：
  1. CPU调度 → GPU launch overhead
  2. Host发起通信 → 无法利用task locality
  3. 批量同步 → 膨胀/冗余的网络payload
  4. GPU利用率低（大部分时间在等通信）
```

### FlashMoE方案：单持久Kernel

```
传统: 3个独立阶段(Dispatch → Compute → Combine), 每阶段独立launch
FlashMoE: 1个persistent GPU kernel
  
  Kernel内部流水线：
    ┌─────────────────────────────────────────┐
    │  Block 0: Dispatch (token→expert, RDMA) │
    │  Block 1: Compute (expert forward)       │
    │  Block 2: Combine (expert→token, RDMA)   │
    │  → 细粒度重叠，零launch开销              │
    └─────────────────────────────────────────┘
  
  通信: GPU端发起的(R)DMA → 绕过CPU → 一侧通信
```

### 关键数据

| 指标 | vs SOTA | 说明 |
|------|---------|------|
| GPU利用率 | **9×** | 即使用FP32也优于FP16基线 |
| 延迟 | **6×** 降低 | 8×H100节点 |
| 吞吐量 | **5.7×** | 128 experts, 16K tokens |
| 通信重叠效率 | **4×** | pipeline overlap |

### 产业意义

- 通信占大规模MoE训练**>40%运行时间** → FlashMoE直击最大瓶颈
- NeurIPS 2025，工业级MoE通信优化SOTA
- 证明了**单kernel融合**是MoE通信的未来方向

## ★★ Occult — 协作通信：专家并行通信优化

**论文**：Occult: Optimizing Collaborative Communication across Experts for Accelerated Parallel MoE Training and Inference
**ID**：arXiv:2505.13345
**发表**：ICML 2025

### 核心创新

定义"协作通信"概念和"协作专家对"：
```
Intra-collaboration: 同一GPU上的expert对 → 无需通信
Inter-collaboration: 跨GPU的expert对 → 需要通信

Occult策略: 最大化intra-collaboration比例 → 减少跨GPU通信
```

两种模式：
1. **精确模式**：减少通信但不损失精度
2. **剪枝模式**：可控精度损失换取更大通信节省

### 关键数据

| 指标 | 结果 |
|------|------|
| 通信占运行时间 | **>40%**（大规模MoE） |
| 加速 | **>1.5×**（多任务/模型） |
| 精度 | 相当或优于标准fine-tuning |

## ★★ APB — 压缩上下文传递：分布式长上下文推理加速

**论文**：APB: Accelerating Distributed Long-Context Inference by Passing Compressed Context Blocks across GPUs
**ID**：arXiv:2502.12085
**发表**：ACL 2025

### 问题

长上下文Prefill的计算瓶颈 + 分布式推理的通信瓶颈 → 双重挑战。

### 方案

```
序列并行 + 近似注意力 + 压缩KV传递

  GPU 0: 处理chunk 0 → 压缩 → 传压缩KV给GPU 1
  GPU 1: 处理chunk 1 → 接收压缩KV → 本地+远程KV注意力
  
  → 同时减少计算量和通信量
```

### 关键数据

| vs 方法 | 加速 |
|---------|------|
| FlashAttention | **9.2×** |
| RingAttention | **4.2×** |
| StarAttention | **1.6×** |

精度：无显著性能退化。
