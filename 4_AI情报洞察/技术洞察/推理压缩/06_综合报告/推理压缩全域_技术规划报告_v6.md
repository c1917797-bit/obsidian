# Step 4：五看洞察

> 每看≥800字，覆盖 5 场景。遵循洞察写作指南 v1.6。

## 4.1 看行业（8 个趋势，覆盖 5 场景）

### 趋势 1：全域联合优化——DeepSeek 证明了这条路

> **反直觉**：单独优化任一对象已到 Pareto 瓶颈。突破在于"多对象联合"。

**业界案例**：

| 公司 | 动作 | 效果 | 来源 |
|------|------|------|------|
| DeepSeek | V3 MLA(KV 93%)+FP8(权重)+DeepEP(通信) | API $0.27/1M，比 GPT-4o 便宜 **10 倍** | 官网定价 |
| HyperQuant(HKUST) | arXiv:2606.23406 统一量化 | 1.7bps，3.79x | arXiv 2026-06 |
| KV Pareto | arXiv:2512.01953 联合前沿 | 68-78%↓，多省 15-20% | arXiv 2025-12 |

**因果**：PagedAttention padding 冗余，联合可共享。`[实测]` Qwen-72B 多省 12.6%。**边界**：<8B 不显著。**行动**：课题必须联合视角设计。

### 趋势 2：Agent 时代——KV 取代权重成为第一瓶颈

> **反直觉**：Agent 多轮 KV 是 O(N×轮数) 增长，权重固定。

**业界案例**：vLLM PagedAttention(50k+star) / Models Take Notes(98.5% hit rate, TTFT 降 53-398x) / SGLang RadixAttention / IntentKV(Qwen3-8B token 降 23.9%)。

`[内部]` 第 10 轮 KV=**8.3x**，仅 **23%** 被访问（Retrieval Head ICLR 2025, 51 引用）→ **77% 死重**。**边界**：工具调用场景 KV 重要性动态变化。**行动**：跨轮 KV = 最高价值+最大空白。

### 趋势 3：MoE 重新定义通信——四路突破

> **反直觉**：MoE 从显存角度看"极度浪费"——96.9% 专家死重。

**业界案例**：DeepEP(生产级) / FoMoE(ICLR 2026, 通信降 45.44x) / ASAP(吞吐+90%) / CloudMoE(OSDI 2026, 28 tokens/s)。

`[内部]` 87.5% 死重，通信占 **40-60%**。**边界**：gate 量化后路由掉 2.1%(FP8)~6.7%(INT4)。**行动**：gate FP8 保护。

### 趋势 4：VLM 视觉 Token 爆炸——2570 个 Token 是文本的 50 倍

> **反直觉**：一张 1024×1024 图片的视觉 Token 数（2570）远超文本（通常 50-500），多图场景直接 OOM。

**业界案例**：VL-Cache(2026, 90% KV↓, 7.08x decode) / VoCo-LLaMA(2025, 576x 压缩) / SparseVLM(2025, 动态稀疏) / Dynamic-LLaVA(2025, 75% prefill↓) / KVCapsule(2026, 2x TPS)。

**因果**：VIT 编码器将图片切分为 Patch（通常 14×14=196 Patch → 加位置编码 → 2570 Token），每个 Token 产生独立的 KV Cache。多图场景下视觉 KV 是文本 KV 的 50 倍。**边界**：暴力剪枝（如 VoCo-LLaMA 的 576x）在复杂 VQA 任务精度损失大；需要 query 引导的精细稀疏。**行动**：方向⑤跨场景需要 VLM 视觉 Token 稀疏。

### 趋势 5：ASR 编码器成为延迟瓶颈——600M 参数占推理 50%+

> **反直觉**：ASR 的延迟瓶颈不在解码器（自回归生成），而在编码器（一次性前向）。

**业界案例**：Whisper(OpenAI 2023) 编码器 600M 参数单次前向 200-400ms / AudioKV(2026, 首个音频 KV 压缩 40%) / Distil-Whisper(2024, 蒸馏 3x) / ReQAT(2026, FP4 QAT)。

**因果**：Whisper 编码器对完整 Mel 频谱（80 通道）做全量 attention，但其中 16 个低能量通道对识别零贡献——**20% 计算是浪费**。INT8 量化后 WER 上升 2-3%（生产不可接受），INT4 无可用方案。**边界**：频段感知量化需要音频领域知识（人耳敏感频段 vs 非敏感）。**行动**：方向⑤跨场景需要 ASR 频段感知量化。

### 趋势 6：TTS 声码器是延迟和音质的双瓶颈——24M 参数占推理 40%+

> **反直觉**：TTS 最慢的不是文本生成（LLM 部分），而是声码器（波形合成）。

**业界案例**：HiFi-GAN(NeurIPS 2020, 24M 参数, 主流声码器) / Vocos(ICASSP 2023, 参数↓80% 但 MOS 降 0.4) / CosyVoice(2024, 多语言 TTS) / BigVGAN(2023)。

**因果**：HiFi-GAN 的大卷积核（长度 3-7）导致单次合成 100-200ms，占 TTS 推理的 40%+。直接替换为轻量 Vocos 可加速但 MOS 从 4.2 降到 3.8（用户可感知差异）。LoRA 在 LLM 成熟但**从未用于声码器补偿**。**边界**：低秩分解可能破坏因果卷积（causal convolution），导致无法流式合成。**行动**：方向⑤跨场景需要 TTS 低秩+蒸馏联合。

### 趋势 7：量化安全成为隐藏风险

AlignCollapse(2026-05) 发现 INT4 后 **15-30% refusal 失效**。业界无人报告过——做了就是差异化。

### 趋势 8：推理模型 CoT 产生大量冗余 KV

R-KV(NeurIPS 2025) 发现推理模型 60-70% 中间 KV 不再需要。ThinKV(ICLR 2026 Oral) 发现 Thought 分 3 类（R/E/T），T 类可 2-bit。ShotKV(ICML 2026) 证明 CoT 链断裂导致推理崩溃。

### 反方声音

Meta："直接扩显存更简单。" / NVIDIA："FP8 已够。" → **不认同**：Agent+MoE+VLM+长上下文下显存增长跟不上需求增长。

## 4.2 看市场（8 个痛点，覆盖 5 场景）

### 痛点 1：Agent KV 8.3x——77% 死重

`[内部]` 第 10 轮 KV=8.3x，23% 被访问。每天浪费 80% 推理算力。Models Take Notes 实现 98.5% hit rate。**行动**：方向①③。

### 痛点 2：70B 需 4 卡——INT4 后 2 卡

Meta/Mistral/阿里/Google/Microsoft **5 家已落地**。DeepSeek API $0.27 vs GPT-4o $2.5 差 10 倍。`[实测]` Qwen-72B AWQ INT4 单位成本 TPS +60%。**行动**：方向④。

### 痛点 3：MoE 通信 40-60%

`[内部]` 128K+64 并发。不优化 TPOT 永远达不了 30%。FoMoE 降 45x，ASAP 吞吐+90%。**行动**：方向②。

### 痛点 4：VLM 2570 视觉 Token——多图 OOM

一张图 2570 Token，多图直接 OOM 或 TPOT 超 10 秒。VL-Cache 做了 90% KV↓但只单轮。**行动**：方向⑤。

### 痛点 5：ASR 编码器 200-400ms——首字延迟超标

实时 ASR 要求 0.5 秒出文字，但 Whisper 编码器 600M 参数单次 200-400ms。INT8 WER 上升 2-3% 不可接受。**行动**：方向⑤。

### 痛点 6：TTS 声码器 100-200ms——First Audio 超标

实时 TTS 要求 First Audio<300ms，但 HiFi-GAN 24M 参数占 40%+。替换 Vocos MOS 降 0.4 可感知。**行动**：方向⑤。

### 痛点 7：量化模型不安全

INT4 后 15-30% harmful prompt 不触发 refusal。业界无人报告。**行动**：方向①安全测试。

### 痛点 8：推理模型 CoT 冗余

R-KV 发现 60-70% CoT KV 不再需要。**行动**：方向①推理模型 KV。

## 4.3 看竞争（对手）

### DeepSeek（全链路领先）

MLA(KV 93%)+FP8+DeepEP → API $0.27/1M。但 **MLA 须重训练**，DeepEP 仅自家格式。**弱点**：不通用。

### Meta（开源生态）

GPTQ+llama.cpp(GGUF) **80k+ star**。但**不做 MoE**，不做 KV 压缩算法创新。

### NVIDIA（硬件+框架）

H100 FP8 Tensor Core 原生。TRT-LLM 内置 FP8/INT8。但**闭源**，不做算法创新。

### 竞争态势

DeepSeek 专用领先，Meta 开源领先，NVIDIA 硬件领先。**三家结构性盲区**：通用联合优化+跨场景压缩。我们的定位：**通用推理层联合压缩+5 场景全覆盖**。

## 课题 17：面向长程对话 Agent 的分层历史剪枝根技术

**课题名称**：面向长程对话 Agent 的分层历史剪枝根技术

**关键挑战**：50 轮 Agent 对话历史累积超 10K Token，每轮 Prefill 时间随历史线性增长——第 50 轮 TTFT 是第 1 轮的 5-8 倍。当前方案要么全量保留（OOM）要么简单截断（丢失早期关键指令导致任务失败率上升 20-40%），缺乏分层精细化管理。

**技术目标**：对 Qwen3/Qwen2.5 系列，长程多轮 Agent 场景：对话历史压缩 3-5 倍，多轮一致性保持，任务完成率不下降。

**关键技术**：
①**三层记忆架构（近期完整/中期摘要/远期关键词）**：近期 N 轮保留完整 KV；中期摘要压缩为语义摘要 KV；远期仅提取关键词 KV。利用模型末尾观测窗口的注意力分布识别每层的关键信息。
创新点：在 MemGPT 基础上设计三层分层历史管理，引入跨层信息保真度约束。

②**动态边界调整（任务复杂度自适应）**：简单任务近期层小（更多历史被摘要），远期层大（关键词少）；复杂任务反之（近期层大保完整推理链）。
创新点：任务复杂度自适应的记忆边界调整。

③**剪枝后 KV 与共享池协同**：被剪枝历史的摘要 KV 进入课题 1 的跨轮共享池，后续轮次需要时可从摘要恢复，而非永久丢失。
创新点：历史剪枝与 KV 共享池的工程联合。

**技术逻辑图**：
```
[对话历史] → 三层分层
  近期(N轮): 完整KV → 直接参与attention
  中期(N-2N轮): 摘要KV → 按需从共享池恢复
  远期(2N+轮): 关键词KV → 仅极端需要时恢复
        ↓
  剪枝后摘要KV → 进入课题1跨轮共享池
```

**课题规划**：Agent 分层历史剪枝课题（三层记忆+动态边界+共享池协同）：实现对话历史压缩 3-5 倍，第 50 轮 TTFT 降低 60%。

**参考论文**：
- MemGPT, 2024, arXiv:2310.08560 — OS 式内存分层（main+external+recall），本课题三层架构基础
- Letta, 2024 — 持久记忆 Agent 框架，本课题记忆持久化参考
- SnapKV, ICML 2024 — 观察窗口投票选 Token，本课题①层内选择参考
- LongMem, arXiv 2024 — 长程记忆压缩，本课题远期层参考
- Mem0, 2024 — Agent 记忆持久化，本课题工程参考

## 课题 18：面向 Agent 负载的统一推理状态-通信协同压缩根技术

**课题名称**：面向 Agent 负载的统一推理状态-通信协同压缩根技术

**关键挑战**：Agent 多轮推理涉及多种状态数据（KV Cache、Beam Search 状态、投机解码草稿、工具调用上下文），每种状态当前独立管理，跨状态冗余严重。多卡 MoE 部署下，状态数据跨卡传输（通信）与状态压缩（存储）各自优化但未协同——通信量优化的决策可能增加状态管理复杂度。

**技术目标**：对 DeepSeek-V3/Qwen3-MoE，Agent 多轮+多卡场景：统一状态管理框架，状态存储-40-60%，通信量-30-50%，Agent 多轮延迟-25%。

**关键技术**：
①**状态感知统一压缩接口**：将 KV Cache、Beam 状态、投机草稿、工具上下文统一建模为"可压缩状态对象"，根据状态类型自动选择最优压缩策略（量化/稀疏/剪枝）。
创新点：首次将 Agent 推理的多种状态统一建模为可压缩对象（现有方案每种状态独立管理）。

②**状态-通信协同调度**：状态压缩决策（哪些 KV 丢弃）与通信调度（哪些专家跨卡传输）联合优化——被丢弃的 KV 对应的专家通信也跳过。
创新点：首次实现"状态压缩-通信调度"联合决策。

③**负载感知自适应压缩级别**：高负载时降低压缩阈值（更多状态被压缩保吞吐），低负载时恢复高精度。
创新点：Agent 负载感知自适应压缩（峰值自动降级保 SLO）。

**技术逻辑图**：
```
[Agent推理状态]
  ├─KV Cache ─────┐
  ├─Beam状态 ──────┤
  ├─投机草稿 ──────┼→ 统一状态压缩接口 → 选择策略
  └─工具上下文 ────┘         ↓
                    状态-通信协同调度
                    (丢弃KV→跳过对应专家通信)
                             ↓
                    负载感知自适应
                    (高负载→更多压缩)
```

**课题规划**：Agent 状态-通信协同课题（统一接口+协同调度+负载感知）：实现状态存储-50%+通信-40%。

**参考论文**：
- FoMoE, ICLR 2026, arXiv:2606.19025 — skip-token，本课题②协同参考
- ASAP, 2026, arXiv:2606.22541 — 异步解耦+90%，本课题②重叠参考
- Gimbal, 2026 — 负载均衡，本课题③负载感知参考
- Dustin, ICML 2026 — 稀疏验证，本课题①状态管理参考
- Models Take Notes, 2026 — KV 笔记本，本课题①状态对象参考

## 课题 19：面向多轮 VLM 交互的视觉语义聚类 KVCache 压缩根技术

**课题名称**：面向多轮 VLM 交互的视觉语义聚类 KVCache 压缩根技术

**关键挑战**：VLM 多轮交互中，首轮的 2570 个视觉 Token 的 KV 在后续轮次部分仍有价值（如用户追问"刚才那张图的左上角"），但当前系统要么全量保留（OOM）要么简单丢弃（追问历史图片时需重新编码）。视觉 Token 的 KV 在空间上高度冗余（相邻 Patch 相似），但时间上的"何时需要"无法预测。

**技术目标**：对 Qwen2-VL/InternVL3，多轮 VLM 场景：视觉 KV 压缩 4-8 倍，多轮 VQA 准确率≤2%，TPOT-30%。

**关键技术**：
①**视觉语义聚类 KVCache**：将 2570 个视觉 Token 的 KV 按 2D 空间+语义相似度聚类为少数中心 KV（320-640 个）。用户追问特定区域时，按需从聚类中心重建该区域的近似 KV。
创新点：首次在 VLM 多轮场景实现"视觉 KV 空间聚类+按需重建"。

②**查询引导聚类粒度自适应**：用户关注区域用细粒度聚类（少合并），背景区域用粗粒度（多合并）。
创新点：query 感知的差异化聚类粒度。

③**跨轮视觉 KV 生命周期管理**：首轮图片的聚类 KV 标记"可恢复"状态；用户切换新图片时旧 KV 降级为"摘要级"；追问旧图片时从"摘要级"恢复。
创新点：视觉 KV 跨轮生命周期管理（摘要级↔完整级动态切换）。

**技术逻辑图**：
```
[首轮图片] → VIT 2570 Token → 2D空间+语义聚类 → 320-640聚类中心KV
                                                    ↓
[后续轮] → query分析 → 判断关注区域 → 差异化聚类粒度
            ├─关注: 细粒度    └─背景: 粗粒度
                                                    ↓
[切换图片] → 旧KV降级摘要级 → 追问时恢复
```

**课题规划**：VLM 语义聚类 KVCache 课题（2D 聚类+query 引导+跨轮生命周期）：实现多轮视觉 KV 压缩 4-8 倍。

**参考论文**：
- VL-Cache, 2026 — VLM KV 90%↓，7.08x decode，本课题单轮基线
- KVCapsule, 2026 — VLM 非对称冗余，2x TPS，本课题③冗余参考
- SparseVLM, 2025 — 视觉 Token 动态稀疏，本课题①评分参考
- VoCo-LLaMA, 2025 — 576x 极端压缩，本课题①极端参考
- Dynamic-LLaVA, 2025 — 75% prefill↓，本课题②动态参考
