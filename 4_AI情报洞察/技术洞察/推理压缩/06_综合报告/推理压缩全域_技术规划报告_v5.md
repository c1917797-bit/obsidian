## 2.1 看行业（趋势）

### 趋势 1：全域联合优化——DeepSeek 证明了这条路

> **反直觉**：单独优化任一对象已到 Pareto 瓶颈。突破在于"多对象联合"——不是压更狠，而是消除跨对象 padding 冗余。

**业界案例（3 个主体同时转向）**：

| 公司 | 动作 | 效果 | 来源 |
|------|------|------|------|
| DeepSeek | V3 架构级联合：MLA(KV 93%)+FP8(权重 50%)+DeepEP(通信) | API $0.27/1M，比 GPT-4o 便宜 **10 倍** | 官网定价+技术报告 |
| HyperQuant(HKUST) | arXiv:2606.23406 权重+KV 统一量化 | 低至 1.7bps，H100 上 **3.79x** | arXiv 2026-06 |
| KV Pareto | arXiv:2512.01953 联合 Pareto 前沿 | **68-78% 内存降低**，联合比分立多省 15-20% | arXiv 2025-12 |

**因果链**：PagedAttention 块对齐导致 W 和 KV 的 padding 各自为政，联合可共享。
`[实测]` Qwen-72B 联合 W4+KV4 多省 10GB(+12.6%)。
**边界**：<8B 不显著，>30B+MoE 收益最大。
**行动**：课题必须从全域联合视角设计。

### 趋势 2：Agent 时代——KV 取代权重成为第一瓶颈

> **反直觉**：LLM 时代权重最大。Agent 时代 KV 累积（O(N×轮数)）取代权重。

**业界案例**：

| 公司 | 动作 | 效果 | 来源 |
|------|------|------|------|
| vLLM(UC Berkeley) | PagedAttention+Prefix Cache | GitHub **50k+ star** | github.com/vllm-project |
| Models Take Notes | KV 笔记本+vLLM 集成 | **98.5% hit rate**，P90 TTFT 降 **53-398x** | arXiv:2606.17107 |
| SGLang(LMSYS) | RadixAttention 跨请求 KV 复用 | 支持 1M token | github.com/sgl-project |
| IntentKV | Agent 跨轮意图感知 KV 剪枝 | Qwen3-8B token 降 **23.9%** | arXiv:2606.09916 |

`[内部]` Agent 第 10 轮 KV=**8.3x**，仅 **23%** 被后续访问（Retrieval Head ICLR 2025, 51 引用）→ **77% 死重**。
**边界**：工具调用场景比纯对话更难（KV 重要性动态变化）。
**行动**：Agent 跨轮 KV 是最高价值+最大空白。

### 趋势 3：MoE 重新定义通信——四路突破

**业界案例**：

| 路线 | 代表 | 效果 | 来源 |
|------|------|------|------|
| 通信基础设施 | DeepEP(DeepSeek 开源) | 生产级 | github.com/deepseek-ai/DeepEP |
| 打破全复制 | FoMoE(ICLR 2026) | 通信降 **1.42-45.44x** | arXiv:2606.19025 |
| 异步解耦 | ASAP | 吞吐 **+90%** | arXiv:2606.22541 |
| 端侧量化 | CloudMoE(OSDI 2026) | DeepSeek-V3 达 **28 tokens/s** | arXiv:2606.10493 |

`[内部]` DeepSeek-V3 8B MoE 全专家 FP16=16GB，激活 2GB（**87.5% 死重**）。通信占 **40-60%**。
**边界**：gate 量化后路由掉 2.1%(FP8)~6.7%(INT4)。`[内部]`实测。
**行动**：gate FP8 保护，专家 INT4。

### 趋势 4：量化安全成隐藏风险

AlignCollapse(2026-05)发现 INT4 后 **15-30% refusal 失效**。VeriCache(2026-05)+DynamicPTQ(2026-06) 提出验证框架。**业界无人报告过量化安全测试**——做了就是差异化。

### 反方声音

Meta："直接扩显存更简单。" / NVIDIA："FP8 已够。" → **不认同**：Agent+MoE+长上下文下显存增长跟不上序列+轮次增长。

## 课题 1：面向多轮 Agent 的语义驱动 LLM 动态 KV 稀疏根技术

**关键挑战**：DeepSeek-V3 在 128K+64 并发下 KV Cache 达 562GB（权重的 4 倍），50 轮 Agent 对话 KV 累积可达 3.5TB 导致 mindie 频繁 OOM。现有 SnapKV/H2O 只在单轮内做静态稀疏且删除后不可恢复，Agent 关键上下文被误删后任务失败率上升。`[内部]` Agent 第 10 轮 KV=8.3x，仅 23% 被后续访问（Retrieval Head ICLR 2025, 51 引用）→ 77% 死重。

**技术目标**：对 Qwen3/Qwen2.5 系列，Agent 多轮场景：KV 压缩 4-8 倍，吞吐+40-60%，时延-20-30%，跨轮命中率≥60%。

**关键技术**：
①**基于观测窗口的语义聚类压缩（Prefill 全局瘦身）**：利用末尾观测窗口注意力分布，识别每个头高关注语义簇，仅保留聚类对应 KV，存储粒度从 token 级压缩为语义单元级。
创新点：首次在 Agent 场景工程化"语义单元级"压缩，引入跨轮语义连续性感知。

②**动态渐进式 Token 选择与恢复（Decode 自适应）**：每步根据当前语义动态评估历史 Token 重要性，低贡献临时稀疏化；语义变化时允许恢复。
创新点：引入"可恢复稀疏"工程机制，解决永久删除导致的关键上下文丢失。

③**轮次感知 KV 评分与跨轮共享池**：每轮结束评估 KV"未来价值"，按 query 语义相似度匹配复用；轮次指数衰减(0.9^N)控制增长。
创新点：轮次感知评分+跨轮共享池+指数衰减三机制联合，论文界完全空白。

**技术逻辑图**：
```
[Prefill] → 观测窗口注意力 → 语义聚类 → 保留聚类KV
[Decode]  → 动态评分 → 低贡献临时稀疏 → 语义变化时恢复
[跨轮]    → 轮次评分 → 共享池匹配复用 → 指数衰减淘汰
```

**参考论文**：SnapKV(NeurIPS 2024,8.2x) | KVzip(2025,3-4x) | ThinK(ICLR 2025) | DuoAttention(ICLR 2025) | RocketKV(ICML 2025,400x) | LazyLLM(ICLR 2025)

**得分**：7.2 | **失效保险**：退回单轮 KV 优化 | **Kill**：连续 2 次验证失败

## 课题 2：面向数学推理 LLM 的 RoPE 频域感知 KV 量化根技术

**关键挑战**：所有主流 LLM 使用 RoPE，KV 量化到 2-bit 时均匀分配导致 AIME 2024 数学推理直接崩溃到 0 分（FP16 基线 54.2 分），因为 RoPE 不同频域块能量差异达 10³倍。KIVI 忽略 RoPE 特性，Block-GTQ 揭示问题但框架集成空白。

**技术目标**：对 Qwen3/Llama 系列，数学推理场景：KV 压缩至 2-bit(K2V2)，AIME24≥50，通用任务≤2%，mindie 集成。

**关键技术**：
①**RoPE 频域分块+能量感知比特分配**：KV 按 RoPE 频域块分组，高能量块 4-bit，低能量 1-bit，总均 2.5-bit。
创新点：Block-GTQ 基础上实现频域块自适应+多模型验证。

②**任务感知比特预算**：推理类（数学/代码）对高频敏感分配更多比特，对话类均衡。
创新点：任务类型驱动 KV 比特预算，同一框架多任务自适应。

③**mindie CANN 算子融合**：频域分块+比特分配实现为 CANN 算子，与 NPU 分页内存兼容。
创新点：RoPE 感知量化的 mindie 工业级集成，利用 Ascend Cube 原生 INT2/INT4。

**参考论文**：Block-GTQ(2026,AIME24=51.7) | OSCAR(2026,Qwen3-32B≈BF16) | ThinKV(ICLR 2026 Oral) | KIVI(ICML 2024) | KVQuant Pre-RoPE(ICML 2024)

## 课题 18：面向 Agent 负载的统一推理状态-通信协同压缩根技术

**关键挑战**：Agent 多轮推理涉及多种状态数据（KV Cache、Beam Search 状态、投机解码草稿、工具调用上下文），每种状态当前独立管理，跨状态冗余严重。多卡 MoE 部署下，状态数据跨卡传输（通信）与状态压缩（存储）各自优化但未协同——通信量优化的决策（如跳过冷专家）可能增加状态管理的复杂度，反之亦然。

**技术目标**：统一状态管理框架，状态存储减少 40-60%，通信量减少 30-50%，Agent 多轮延迟降低 25%。

创新点：首次将 Agent 推理的多种状态统一建模为可压缩对象（现有方案每种状态独立管理）。
②**状态-通信协同调度**：状态压缩决策（哪些 KV 要保留/丢弃）与通信调度决策（哪些专家要跨卡传输）联合优化——被压缩丢弃的 KV 对应的专家通信也跳过。
创新点：首次实现"状态压缩-通信调度"联合决策（现有方案各自独立优化）。
③**负载感知自适应压缩级别**：高负载时自动降低压缩阈值（更多状态被压缩/丢弃保吞吐），低负载时恢复高精度状态。
创新点：Agent 负载感知的自适应压缩（峰值自动降级保 SLO）。

**技术逻辑图**：
```
[Agent推理状态]
  ├─KV Cache ─────┐
  ├─Beam状态 ──────┤
  ├─投机草稿 ──────┼→ 统一状态压缩接口 → 选择压缩策略
  └─工具上下文 ────┘         ↓
                    状态-通信协同调度
                    (丢弃的KV→跳过对应专家通信)
                             ↓
                    负载感知自适应
                    (高负载→更多压缩, 低负载→恢复精度)
```

**参考论文**：FoMoE(ICLR 2026,skip-token) | ASAP(2026,异步解耦) | Gimbal(2026,负载均衡) | Dustin(ICML 2026,稀疏验证) | Models Take Notes(2026,KV笔记本)

**得分**：6.0 | **失效保险**：各状态独立管理（退回课题 1+3 分立）

## 课题 19：面向多轮 VLM 交互的视觉语义聚类 KVCache 压缩根技术

**关键挑战**：VLM 多轮交互中，每轮用户可能追问同一图片不同区域或切换不同图片。首轮的 2570 个视觉 Token 的 KV 在后续轮次部分仍有价值（如用户追问"刚才那张图的左上角"），但当前系统要么全量保留（OOM）要么简单丢弃（追问历史图片时需重新编码）。视觉 Token 的 KV 在空间上高度冗余（相邻 Patch 相似），但时间上的"何时需要"无法预测。

**技术目标**：多轮 VLM 场景视觉 KV 压缩 4-8 倍，多轮 VQA 准确率≤2%，TPOT-30%。

**关键技术**：
①**视觉语义聚类 KVCache**：将 2570 个视觉 Token 的 KV 按 2D 空间+语义相似度聚类为少数中心 KV（如 320-640 个），后续轮次只需访问聚类中心而非全部。用户追问特定区域时，按需从聚类中心重建该区域的近似 KV。
创新点：首次在 VLM 多轮场景实现"视觉 KV 空间聚类+按需重建"（VL-Cache 只做单轮压缩，不支持跨轮复用）。
②**查询引导的聚类粒度自适应**：用户关注区域（高分辨率需求）用细粒度聚类（少合并），背景区域用粗粒度聚类（多合并）。
创新点：query 感知的差异化聚类粒度（现有方案全图统一聚类）。
③**跨轮视觉 KV 生命周期管理**：首轮图片的聚类 KV 标记"可恢复"状态；后续轮次如用户切换到新图片，旧图片 KV 降级为"摘要级"（仅保留最粗聚类）；用户追问旧图片时从"摘要级"恢复。
创新点：视觉 KV 的跨轮生命周期管理（摘要级↔完整级动态切换）。

**技术逻辑图**：
```
[首轮图片] → VIT编码2570 Token → 2D空间+语义聚类 → 320-640聚类中心KV
                                                    ↓
[后续轮] → 用户query分析 → 判断关注区域 → 差异化聚类粒度
            ├─关注区域: 细粒度(少合并)
            └─背景区域: 粗粒度(多合并)
                                                    ↓
[切换图片] → 旧图片KV降级为摘要级 → 用户追问时恢复
```

**参考论文**：VL-Cache(2026,90%KV↓) | KVCapsule(2026,非对称冗余) | SparseVLM(2025,视觉Token稀疏) | VoCo-LLaMA(2025,576x) | Dynamic-LLaVA(2025)

**得分**：5.8 | **失效保险**：退回单轮视觉 Token 稀疏（课题 5）

## 课题 20：面向分离式推理的跨模型 KV 迁移压缩根技术

**关键挑战**：PD分离架构下Prefill模型≠Decode模型，KV不兼容。SCD(华为+北大ICML 2026)是首个跨模型KV传输方案。

**技术目标**：TTFT降低2.65倍，质量损失<5% F1，适配≥2种模型对。

**关键技术**：
①**低秩重构跨模型KV映射**。②**选择性过渡层patch**。③**FlexNPU协同调度**。

**参考论文**：SCD(ICML 2026,华为+北大) | FlexNPU(2026,华为) | CloudMoE(OSDI 2026) | NetKV(2026)

**得分**：5.0 | **失效保险**：同模型PD分离

## 课题 21：面向 VLM 全链路的 Token 压缩四合一根技术

**关键挑战**：课题5(稀疏4-8x)+课题13(剪枝蒸馏3x)+量化2x=理论24倍，但四技术全链路联合的误差累积未研究。

**技术目标**：端到端压缩>20倍，VQA≤5%，TPOT-60%。

**关键技术**：
①**四技术时序协同pipeline**。②**跨技术四维Pareto搜索**。③**NPU CANN全链路算子链**。

**参考论文**：课题5/13全部 | MoE-nD(2026) | RDKV(2026)

**得分**：5.0 | **失效保险**：退回课题13

## 课题 22：面向高并发 LLM 的注意力头差异化剪枝根技术

**关键挑战**：LLM-72B有64头但30-50%高度相似(冗余)，浪费20-30%FLOPS。GQA/MQA减了KV头但Query头未减。

**技术目标**：头数减少30-50%，精度≤1%，TPOT-20%。

**关键技术**：
①**注意力头冗余度画像**：余弦相似度聚类>0.9为冗余组。②**组内代表头+LoRA补偿**。

**参考论文**：CompressKV(2026) | Wanda(NeurIPS 2024) | BESA(NeurIPS 2024) | DoRA(2024)

**得分**：5.0 | **失效保险**：恢复全部头

## 课题 23：面向 NPU 原生压缩的 CANN 算子库根技术

**关键挑战**：前三年各课题各自实现CANN算子但缺乏统一库。GPU有TensorRT-LLM统一框架，NPU无对标。Ascend Cube原生INT2/INT4是GPU不具备的优势。

**技术目标**：覆盖6大根技术≥15个核心算子，mindie生产级集成。

**关键技术**：
①**统一压缩算子接口**：6大根技术统一API。②**Cube单元压缩指令优化**：INT2/INT4原生无需反量化。③**自适应压缩调度器**：NPU负载感知自动选最优组合。

**参考论文**：前三年全部课题积累 | FlexNPU(2026,华为) | SCD(ICML 2026,华为) | FlashMoE(NeurIPS 2025)

**得分**：6.0 | **失效保险**：各课题独立算子
