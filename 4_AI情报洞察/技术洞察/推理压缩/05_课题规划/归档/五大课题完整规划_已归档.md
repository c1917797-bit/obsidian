## 课题A：面向Agent多轮场景的KV语义聚类与跨层一致性约束全生命周期压缩技术

### 关键挑战

Agent多轮场景下，128K上下文时KV Cache显存已达2GB/request，并发度受M_KV线性压制。现有KV压缩方法均以单层attention分布为依据，各层独立压缩导致跨层语义漂移，Agent长链路推理中错误逐层累积放大。缺乏对「多轮场景下前序轮次KV重要性高于当前轮次」这一特性的利用。恢复机制缺乏net positive验证，导致以压缩为名实则增加计算负担。

### 技术目标

对128K长上下文场景的LLM推理，KV显存占用降低5倍以上，推理吞吐提升40%-60%，精度损失≤1%。

### 关键技术

①观测窗口锚定的语义聚类压缩（Prefill阶段——生成时减量） 利用Prefill末尾观测窗口的attention分布，识别各层共同高关注的语义簇作为全局锚点。仅对锚点对应token计算完整KV，将存储粒度从token级压缩为语义单元级，从源头减少冗余数据产生。创新点：锚点跨层共享，而非各层独立聚类——这是与SnapKV的本质差异。

②跨层一致性约束与动态重要性追踪（Decode阶段——生成后压缩+查询时恢复协同） 引入层间一致性正则项，确保压缩后语义单元在各Attention层传播中表征稳定。Decode阶段实时追踪token贡献度，低贡献token压缩为INT4摘要；当贡献度回升时触发热恢复，需验证net positive——召回收益（节省的显存）必须大于召回开销（重新计算量），方触发恢复。创新点：一致性约束保障精度，按需恢复确保net positive。

③多轮感知的重要性预算分配（多轮场景——生成后压缩） 前序轮次KV分配INT4预算，当前轮次KV采用INT2或稀疏。前序轮次语义信息价值更高，应当优先保留。恢复触发时需满足两个条件：当前显存压力超过阈值，且召回后精度收益大于召回计算开销。

### 技术原理

```
【AS IS】
各层独立聚类 → 跨层语义漂移 → 长链路精度下降
各轮均匀压缩 → 前序关键信息被优先淘汰
恢复机制无验证 → 可能得不偿失

【TO BE】
跨层共同锚点 → 一致性约束保障精度
前序INT4 + 当前INT2 → 重要性感知分配
恢复验证net positive → 收益>开销才触发
```

### 技术可信性

| 技术依据 | 来源 | 关键验证 |
|---------|------|---------|
| 语义聚类锚点可保留90%信息 | SnapKV（NeurIPS 2024） | 内存效率8.2倍，生成速度3.6倍 |
| 按需恢复net positive | LazyLLM（ICML 2024） | Prefill加速2.34倍，震荡率<5% |
| 跨层正则化防止漂移 | TRIM-KV（2025） | 超越Full Cache效果 |
| 多轮前序信息价值更高 | UltraQuant（2026） | 多轮Agent TTFT降低3.47倍 |

## 课题B：面向多模态VLM的视觉Token全生命周期压缩技术

### 关键挑战

多模态VLM Agent处理一张图片时产生576个视觉token，是文本token的10-100倍。现有压缩方法无法识别视觉token之间的空间重复；无法识别「同一图片+不同问题」的跨请求复用；多轮场景下视觉KV与文本KV管理相互独立。恢复机制缺乏net positive验证。Agent多模态化是不可逆的产品趋势，不解决视觉token压缩，KV Cache将在多模态场景下率先爆炸。

### 技术目标

对多模态VLM Agent场景，TTFT降低35%以上，视觉token压缩50%以上，多轮复用率>70%，精度损失<2%。

### 关键技术

①视觉Token语义聚类+Attention协同压缩（Prefill阶段——生成时减量） 先用CLIP特征空间K-means聚类，把语义相似的patch合并，每个簇只计算一个代表token的KV；再在此基础上用attention score二次筛选，确保与任务相关的簇被保留。两步互补——聚类去除冗余，attention保障相关。恢复验证：被压缩的语义簇在召回时必须满足net positive（召回收益>召回开销）。创新点：双维度协同，而非分别独立使用——这是与LLaVA-PruMerge/SlimLLaVA的本质差异。

②跨模态动态重要性追踪（Decode阶段——生成后压缩+查询时恢复协同） 不依赖静态的Prefill attention分布，实时追踪已生成的部分文本（partial query）与各语义簇的跨模态语义关联度。高关联度簇保留完整KV，低关联度簇压缩为INT4摘要；当关联度回升时触发热恢复，需验证net positive。创新点：跨模态语义关联度替代单模态attention分布，捕捉「对当前query有没有语义贡献」而非「token重不重要」。

③视觉语义指纹缓存（跨请求——生成后缓存复用） 将图像视觉token集合编码为语义指纹（CLIP特征hash）作为缓存键，相同图片的不同问题直接复用历史视觉KV，只计算新query与图像KV的交叉attention。命中时直接复用，无需触发恢复机制。创新点：语义指纹识别「同图不同问」这一新复用模式——这是Models Take Notes的KV可编辑笔记本未覆盖的场景。

### 技术原理

```
【AS IS】
576视觉token → 逐token计算KV → 全部保留 → attention排序选top-k
相邻patch重复 → 多轮同图每次重算 → 无跨请求复用
恢复无验证 → 可能得不偿失

【TO BE】
CLIP特征K-means聚类 → attention二次筛选 → 代表token算KV
Decode：跨模态关联度动态淘汰（恢复验证net positive）
跨请求：语义指纹匹配 → 复用视觉KV
```

### 技术可信性

| 技术依据 | 来源 | 关键验证 |
|---------|------|---------|
| CLIP特征捕捉视觉语义相似性 | OpenAI CLIP | 广泛验证为视觉语义表征 |
| 聚类降低语义冗余 | ClusterKV（CUHK，2025） | 32K上下文下2.5倍吞吐 |
| 跨模态query感知可行 | IntentKV（arXiv 2026） | 8K预算下token降低23.9% |
| 按需恢复net positive | LazyLLM（ICML 2024） | 震荡率<5% |
| 跨请求KV复用效果显著 | Models Take Notes（2026） | 98.5% hit rate |

### 与课题A的关联

```
课题A（单模态LLM）
  语义聚类 + 跨层一致性 + 按需恢复 + 多轮感知
      ↓ 共享框架
课题B（多模态VLM）
  语义聚类 + 跨层一致性 + 按需恢复 + 多轮感知
  + 跨模态query感知 + 视觉语义指纹
```

## 课题C：面向多卡MoE的专家协作约束与任务感知联合通信量压缩技术

### 关键挑战

MoE架构中All-to-All通信占TPOT的40-60%，但现有方法（DeepEP/灵衢）只解决「传得更快」而非「传多少字节」。三条独立路径（协作约束路由/INT4通信量化/任务感知专家跳过）从未被联合建模。实际产品中GPU集群是异构的（A100/H100混部），不同型号间的传输策略需要差异化设计。恢复机制缺乏net positive验证。

### 技术目标

对多卡MoE推理场景，跨设备token交换次数减少30%以上，通信字节数减少50%以上，TPOT降低15%-25%，精度损失<1%。

### 关键技术

①专家协作约束与任务感知联合路由（路由决策——生成时减量） 在路由决策时同时考虑「协作约束」（减少跨设备传输次数）和「任务感知」（根据任务类型调整路由权重）。代码生成与对话任务的专家激活模式不同——根据任务类型动态调整协作分组，使当前任务高频共激活的专家优先共置。恢复验证：被跳过的专家在后续step中若关联度回升，是否触发召回——需验证net positive（召回后精度收益是否大于召回计算开销）。创新点：任务感知动态协作替代C2R的静态协作约束——这是与C2R的本质差异。

②Rank-Aware通信量化（通信传输——传输时压缩） MoE通信量化的核心问题是量化噪声导致top-k专家排名翻转。引入Rank-Aware Jaccard Loss和Gap Hinge Loss，量化损失函数显式对齐量化前后top-k专家集合的相似度，而非仅优化L2 loss。恢复验证：量化误差若导致排名翻转，是否影响最终精度——需验证net positive（量化压缩收益是否大于精度损失风险）。创新点：首次将排名稳定性引入MoE通信量化——这是与ExpertQuant的本质差异。

③任务感知专家跳过（通信执行——传输时减量） 构建「任务-专家激活」映射图谱，识别各任务类型下的永久低频专家。路由决策时直接跳过低频专家，不触发跨设备通信。被跳过的专家不参与top-k竞争，降低路由复杂度。恢复验证：被跳过的专家在后续step中若变成高频，是否触发召回——需验证net positive。创新点：跳过策略与协作约束路由联合设计——这是与TACG的本质差异（TACG仅做跳过，不做协作约束）。

### 技术原理

```
【AS IS】
路由：静态协作约束（C2R）或无约束 → 跨设备交换多
通信：FP16传输，无压缩
执行：所有专家平等参与 → 低频专家浪费通信资源
三路径独立 → 无协同收益
恢复无验证 → 可能得不偿失

【TO BE】
路由：任务感知协作约束 → 交换↓30%（恢复验证net positive）
通信：Rank-Aware INT4 → 字节↓50%（恢复验证net positive）
执行：低频专家跳过 → 参与量↓20%（恢复验证net positive）
三路径联合 → TPOT↓15-25%
```

### 技术可信性

| 技术依据 | 来源 | 关键验证 |
|---------|------|---------|
| 协作约束减少交换次数 | C2R（NAACL 2025） | 交换次数减少20-30% |
| MoE量化精度保障 | ExpertQuant（2025） | W4A4/W4A8精度损失<1% |
| 任务感知剪枝效果 | TACG（ACL 2024） | 通信成本降低31.39% |
| 打破全复制压缩通信 | FoMoE（ICLR 2026） | 通信降低1.42-45倍 |
| 路由+量化联合可行 | ASAP（OSDI 2026） | 吞吐提升90% |

## 课题D：面向长序列Prefill的Token-FFN联合与语义选择性计算加速技术

### 关键挑战

TTFT占端到端时延的60-80%，Prefill中FFN计算量是Attention的2-3倍。现有Token剪枝方法主要针对Attention阶段，忽略FFN激活的动态稀疏性——大量token的FFN输出接近零，这些计算完全浪费。Attention和FFN的重要性往往不对等，单独优化无法找到全局最优。Prefill阶段的压缩结果未与后续KV Cache管理形成联动——压缩的token若能在源头决定不生成KV，就不需要后续的KV压缩。

### 技术目标

对长序列（>32K）Prefill阶段，TTFT降低40%以上，Prefill计算量减少50%以上，精度损失≤1%。

### 关键技术

①FFN激活稀疏感知的Token选择（生成时减量——减少无效计算） 在Prefill阶段分析各token的FFN激活模式，识别激活值接近零的token（不重要计算）。对这类token跳过FFN计算，从计算源头减少无效数据产生。创新点：FFN激活稀疏感知替代纯attention重要性——这是与FTP的本质差异（FTP仅剪枝token，不区分FFN vs Attention）。

②Attention-FFN联合预算分配（生成时减量——全局最优） 将总计算预算在Attention和FFN之间动态分配：对Attention不敏感但FFN激活重要的token，保留FFN计算跳过Attention；对FFN不敏感但Attention重要的token则反之。突破单独优化Attention或FFN的局部最优。创新点：首次做Attention-FFN联合预算分配——这是与LazyLLM的本质差异（LazyLLM仅优化Attention，不涉及FFN）。

③源头KV量化联动（生成后压缩——从源头协同） Prefill阶段被判定为不重要的token，在生成时直接跳过KV计算。将Token-FFN联合判断的结果直接传递给KV管理模块，从源头减少KV生成量，而非生成后再压缩。创新点：FFN判断与KV管理联动——这是课题A的前置依赖。

### 技术原理

```
【AS IS】
所有token逐个计算Attention+FFN → FFN冗余未解决
Token剪枝：仅按attention重要性跳过token
KV管理：先完整计算KV，再做事后压缩 → 源头浪费

【TO BE】
FFN激活分析 → 稀疏token跳过FFN计算
联合预算：attention重要+FFN不重要→跳过attention
         attention不重要+FFN重要→保留FFN
源头联动：FFN不重要→KV也不生成
综合：Prefill计算量↓50%，TTFT↓40%
```

### 技术可信性

| 技术依据 | 来源 | 关键验证 |
|---------|------|---------|
| FFN激活存在动态稀疏 | FTP（ICLR 2025） | FFN token剪枝验证 |
| 按需恢复net positive | LazyLLM（ICML 2024） | Prefill加速2.34倍 |
| Hybrid-head架构参考 | Hymba（ICLR 2025） | Hybrid架构有效性 |
| 激活压缩降低开销 | Activation Beacon（ICLR 2025） | 长上下文压缩7.0分 |

### 与课题A的关联

```
课题D（Prefill计算优化）
      ↓ 源头联动
课题A（KV生命周期管理）
      ↓ 共享判断结果
FFN不重要 → KV也不生成
→ 从源头减少KV产生量，而非事后压缩
```

## 课题E：面向新范式的多尺度隐状态选择与混合架构协同推理优化技术

### 关键挑战

SSM（Mamba）架构线性复杂度的attention对长上下文有天然优势——KV Cache问题在SSM上不存在。但SSM的隐状态是压缩的序列表征，其「重要性」不能直接用Transformer的attention score衡量。Samba/Jamba等混合架构同时具有SSM和Transformer的优势，但压缩策略的设计空间也相应翻倍。如果SSM成为2027-2028年的主流架构，现在不提前研究，到时候要从零开始。

### 技术目标

SSM隐状态选择准确率>90%，长序列（>128K）场景下TPOT降低35%以上，精度损失<1%。

### 关键技术

①SSM隐状态重要性评估（生成时减量——定义新度量） Mamba的隐状态是压缩表征：h_t = A·h_{t-1} + B·x_t，其重要性由历史时间步对当前隐状态的贡献度决定。通过梯度敏感度分析（哪些历史状态对当前loss影响最大），设计SSM版本的「KV重要性分数」。恢复验证：卸载后若需要召回，需验证net positive。创新点：首次为SSM架构定义可计算的隐状态重要性度量——这是与所有Transformer KV压缩方法的本质差异。

②选择性隐状态保留与卸载（生成后压缩+查询时恢复协同） 在推理过程中，对SSM隐状态做选择性保留或卸载：高贡献历史状态保留在GPU显存，低贡献状态卸载到CPU或压缩为低秩表征。卸载后的隐状态在召回时需验证net positive——召回收益（节省的显存）必须大于召回开销（重新计算量）。创新点：SSM专用压缩策略——这是学术空白。

③混合架构协同压缩（分层感知策略） Samba/Jamba同时包含SSM层和Transformer层。SSM层采用隐状态选择策略，Transformer层采用KV量化/剪枝策略。探索层类型与压缩策略的最优匹配：哪些层适合量化，哪些层适合剪枝，哪些层适合跳过。恢复验证：各层按需恢复均需验证net positive。创新点：首次为混合架构设计差异化的压缩策略——这是学术空白。

### 技术原理

```
【AS IS】
Transformer：KV Cache显存爆炸 → 需要KV压缩
SSM：线性复杂度 → 无显式KV Cache问题
→ 但SSM隐状态也有冗余，现有压缩策略直接套用不适用
→ 混合架构（SSM+Transformer）压缩策略未知

【TO BE】
SSM隐状态：梯度敏感度 → 重要性分数 → 选择性保留/卸载（召回验证net positive）
Transformer层：KV量化（INT4/INT2）+ 语义剪枝
混合架构：SSM层用隐状态选择，Transformer层用KV压缩
→ 差异化策略替代统一策略
```
